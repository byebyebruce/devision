## 现状

| 文件 | 题数 | 构成 |
|---|---|---|
| `train_100k.jsonl` | 100,000 | GQA 是非 40,000、GQA 二选一 20,000、VQAv2 是非 40,000 |
| `cocoqa_train.jsonl` | 57,197 | 有没有 15,000（noul，另含相对位置的 noul 题）、绝对位置 15,000、大小 15,000、相对位置 12,197 |

## 发现

### 1. 题型覆盖窄

- **所有 choice 题都是二选一**：训练集里 56,195 道 choice 题，选项数全部是 2。Jev 的 choice 支持 2–255 个选项，实际使用中 "这是什么房间：厨房 / 卫生间 / 卧室" 这类三选一、多选一很常见，模型从来没训练过。
- **只有是非题和二选一**：没有计数（"几个人"）、颜色、"什么运动 / 什么动物 / 什么房间" 这类开放类别题。VQAv2 里这类题（answer type 为 number 和 other）约占六成，目前全部被丢弃。

### 2. 只看题目就能猜（文本捷径）

用 "训练集里同一句题目的多数答案" 去答评测题，完全不看图：

| 评测集 | 题目在训练集里出现过 | 只看题目的准确率 |
|---|---|---|
| POPE | 297 / 300 | **0.636** |
| val_cocoqa | 912 / 1,000 | **0.714** |
| val_gqa | 104 / 1,000 | 0.606 |
| val_vqav2 | 299 / 1,000 | 0.538 |

主要来源是 COCO 出题：

- **"有没有某物" 按类别严重偏斜**：person 78% 答 "有"；chair、car、dining table、cup、handbag、bottle、backpack 这些 81–88% 答 "没有"。原因是负例挑常见的共现物体，而正例从图中物体里随机抽、大多数图里都有人。这和 POPE 的出题方式相近，所以**POPE 上的提升有一部分可能来自这个捷径**。
- 大小题只看类别能答对 0.844，上下题 0.757（见实验记录），"dining table 在下面" 96%、"person 比 tennis racket 大" 100%。
- 共有 108 句高频题目的答案偏斜 ≥ 75%，涉及 17,296 道训练题，占全部训练题的 11%。

### 3. 标签质量（各抽 8 道对图核对）

| 来源 | 有问题或无法核实 | 说明 |
|---|---|---|
| VQAv2 是非题 | 0 / 8 | 标签细致（"人背着滑雪板" 判为 "没有穿滑雪板"），主观题的软标签合理（"水面平静吗" 0.4） |
| COCO 出题 "没有某物" | 约 1 / 8 | 一题背景里有疑似桌子的物体；COCO 标注不全时 "没有" 可能是错的 |
| GQA 是非题 | **3–4 / 8** | 一题明显标错（红黑格子衬衫问 "是红色吗" 答 "否"）；另有两三题问的物体在 256 像素下看不见或找不到（"纸巾右边的自行车"、"香肠"、"书"） |

GQA 来自 Visual Genome 场景图，问题经常涉及很小或被遮挡的物体，在 256×256 输入下大量题目无法从图上判断。

### 4. 在已测条件下学不会的题占了不少

- 在已测的条件下（只训投影层的对齐、阶段 2 的 LoRA 或全量放开 ModernBERT、最多 1 万张合成图），模型没学会 "文字说的那个物体在哪边"（见 `../experiments/2026-09-30-rlcd-plateau.md`）。GQA 二选一里约 64% 是左右 / 上下题，COCO 出题里还有绝对和相对位置题，合计约 3 万道训练题。在绑定问题解决之前，它们提供的有效信号很少，主要被模型当作类别先验来学。这不等于这个架构或新配方永远学不会空间关系。

### 5. 评测集偏小、和训练同源

- POPE 只有 300 题、50 种不同的问法，标准误约 2.6%；laya-vision 用的是 3,000 题。
- val_cocoqa 和训练集同一套出题规则，同样带着上面的捷径。

## 改进方案

按 "预期收益 / 成本" 排序。所有改动都**生成新文件**（例如 `cocoqa_train_v2.jsonl`），不覆盖现有数据；用新的实验 YAML 对比。

| # | 方案 | 解决 | 做法 | 成本 |
|---|---|---|---|---|
| 1 | **"有没有某物" 按类别配平** | 文本捷径 | 每个类别的 "有 / 没有" 各占一半：负例仍按共现挑（保留 POPE 式难度），但同时按类别配额抽正例，让 "chair" 被问到时有一半是 "有"。大小、上下题同理，优先保留 "违反类别常识" 的样本（杯子比汽车大、桌子在上方） | 低：改 `cocoqa.py` 的抽样，生成新文件 |
| 2 | **从 VQAv2 非是非题生成多选题** | 只有二选一、题型窄 | 对 "what color / what sport / what room / what animal / how many" 等题，以标注者答案分布为 gold（软标签），从同类问题的答案词表里挑 2–4 个干扰项（排除任何标注者给过的答案），组成 3–5 选一。VQAv2 train 有数万道这类题可用，图片已在本地 | 中：新转换器 + 测试 |
| 3 | **减少 GQA、筛掉看不清的题** | GQA 噪声 | 降低 GQA 在混合数据中的比例（例如 6 万 → 2 万），优先保留不涉及空间关系的是非题和属性选择题；如果拿到 GQA 场景图里的物体框，可以剔除目标物体面积过小的题 | 低（降比例）/ 中（按框筛） |
| 4 | **暂时下调左右类题** | 学不会的题占比 | 在绑定问题解决前，把左右类题（GQA 和 COCO 出题）降到很小的比例，上下、大小题按方案 1 去掉先验样本 | 低 |
| 5 | **扩大并去偏评测集** | 评测不可靠 | POPE 用 lmms-lab/POPE 全部 3 个分片（random / popular / adversarial 各 3,000）；评测报告里加一列 "只看题目的准确率"，提升必须超过这条线才算看图；新增 VQAv2 val 多选题评测集，对应方案 2 | 低 |

### 建议的执行顺序

1. 先做方案 5（评测）和方案 1（配平），成本最低，而且能把 "看图" 和 "猜先验" 分开，后面的比较才可信。
2. 再做方案 2（多选题），这是覆盖面上最大的缺口，也最可能缩小和 laya-vision 在 VQAv2 上的差距。
3. 方案 3、4 在混合新数据时一起调整比例。

数据生成脚本都在仓库外的 `scripts/data/`。新训练集准备好后，用一份新的 `configs/*.yaml` 从当前最好的对齐 checkpoint 开始跑阶段 2，和现有配方对比。

## v2 修订（2026-10-02，按外部评审）

外部评审核对了 209,285 道训练题，提出的问题全部复核属实（`runs/analysis/data_quality/verify_review.txt`），修复后同一套检查的结果在 `verify_review_after.txt`。数据现在由 `scripts/data/v2_build.py` 一条命令重建：先生成评测集，再生成训练集，按图片哈希切出 dev，**所有过滤之后**再做最终配平，最后验收并写 `data/v2/MANIFEST.json`（每个文件的题数、图片数、答案分布、选项数、sha256、只看题目的基线）。任何一项检查失败，构建即中止。

### 新增的对照

- **只看题目的基线**：每个 dev / eval 文件在 MANIFEST 里都有，报告准确率时必须并列给出。
- **配错图对照**：`devision-eval --shuffle-images`，或在实验 YAML 的 `evaluate` 里写 `controls: true`，每个评测集再用别的样本的图片测一遍。比较真实图与错配图的准确率，并结合只看题目的基线判断视觉贡献；存在文字线索时，不要求错配图一定降到均匀随机水平（2026-10-02 验收修正）。

### 仍待处理

- 多选题只看题目仍比随机高约 9 个点（主要是训练和评测共用的常见问法）；
- 多选训练题里颜色和计数占 78%；评测里肉类 19 题、蔬菜 33 题、食物 71 题、水果 78 题、天气 81 题，结论不稳；
- 位置、相对位置和 GQA 左右题占训练池 23.8%，混合比例要按能力分层、靠对照实验决定。


## v2 再次修订与实验计划（2026-10-02 17:40，回应 `critic/critic.md`）

### 本轮新增的修复

- **候选必须逐个对得上**：问题用 "或" 和逗号列出的每一个候选都必须恰好是该类别词表里的一个词，否则不出题（如 "dry, snowy, windy, or rainy?" 只有两个候选在词表里；"a tennis ball or frisbee?" 会把 tennis 当成选项）。"what is this animal eating?" 这类问动作对象的题不再用动物作选项。
- **只看题目的基线**在 MANIFEST 里按题型分开记录。验收发现其训练数据范围和并列处理与原评审不同，准确口径见本节末的验收补充；原先称其为“评审算法”不准确。

## 相对位置的上下题补充（2026-10-03，v4）

v3 在相对位置上下题上从 0.860 掉到 0.572（`../training-log.md`）。原因在混合：`v2_mix.py` 给相对位置整类只配 2,500 道，从上下 1,402 / 左右 7,414 的池里随机抽，再经左右限额和重新配平，训练混合里上下只剩 172 道。

- **COCO 池到顶了**：放开每对类别的上限（40 → 1,000）后，平衡的上下题仍是约 1,500 道。COCO 的大多数类别对几乎总是同一个方向（人在餐桌上方），按"每对类别上下各半"配平时被整组丢掉，上限不是瓶颈。
- **从 GQA 场景图扩池**：`scripts/data/v2_vg_relation.py`，规则与 COCO 相同（名字在图中唯一、框 ≥ 1%、竖直间隔 ≥ 5%、每对名字上下各半），另外排除背景、身体部位、衣物、复数名字和出现少于 200 张图的名字；在 COCO 图片上，名字若是 COCO 类别，还要求 COCO 标注里该类恰好一个实例（场景图只标了部分物体，"the bowl" 可能是好几个碗之一）。只用本地有的图（VG 中属于 COCO train2014 的用 COCO 文件，其余用已下载的 GQA 图），评测和 dev 图片按 COCO / VG 两套 id 剔除。得到 1,784 道（1,576 张图、680 对名字，上下各 892）。测试 `scripts/data/test_v2_vg_relation.py`。
- **噪声**：抽查 16 道（`runs/analysis/vg_relation_check*.jpg`），方向标签都与框一致；但约 1/4 的题目名字有问题——同名物体不止一个却只标了一个，或场景图把物体标错（把柜门标成 "surfboard"）。这是 Visual Genome 标注本身的噪声，规则消不掉；因为每对名字上下各半，噪声不带方向偏向。
- **v4 训练数据**：`scripts/data/v4_relation_mix.py` → `data/v2/train_relation_tb.jsonl`：上下题 3,186 道（COCO 1,402 + 场景图 1,784，上下各半）+ 从 `train_mix` 随机回放 3 倍（9,558 道）防遗忘。配置 `configs/v4-relation-tb.yaml`，从 v3 接着训 2 个 epoch。
- 以后重建训练混合时，上下类相对位置题要单独保底，不能和左右类一起算进"空间题"限额。

## 左右题的镜像反例（2026-10-03，为第 6 轮准备）

左右题到 v3 仍在随机水平，之前试过的办法（只训投影层、LoRA r16/r64、放开全部参数、4 倍合成数据、带方位的完形填空）都没用（`../experiments/2026-09-30-rlcd-plateau.md`）。新做法：把每道左右题在左右镜像的图上再问一遍、答案对调——同一张图、同样的词、相反的答案，只看名字或选项顺序必错，只有看出物体在哪才能都对。

`scripts/data/v6_flip.py`（测试 `test_v6_flip.py`）→ `data/v6/flip_lr.jsonl`：COCO 位置池和相对位置池里全部左右题的镜像版，25,530 道（位置 18,116、相对位置 7,414），18,100 张镜像图在 `data/v6/images/flip/`；镜像图的 `image_id` 加 `:flip`，按图计数时与原图分开。抽查 2 对（`runs/analysis/flip_check.jpg`），答案都随镜像正确对调。图中文字也被镜像，但这些题不涉及文字。训练时要与原题一起放进混合，才构成成对反例。
