# 训练数据质量评估与改进方案（2026-10-02）

只读分析，没有改动任何数据文件。脚本和原始输出在 `runs/analysis/data_quality/`（`stats.py`、`priors.py`、`spotcheck.py` 及对应的 `.txt` / `.jpg`）。

## 现状

| 文件 | 题数 | 构成 |
|---|---|---|
| `train_100k.jsonl` | 100,000 | GQA 是非 40,000、GQA 二选一 20,000、VQAv2 是非 40,000 |
| `cocoqa_train.jsonl` | 57,197 | 有没有 15,000（noul，另含相对位置的 noul 题）、绝对位置 15,000、大小 15,000、相对位置 12,197 |

## 发现

### 1. 题型覆盖窄

- **所有 choice 题都是二选一**：训练集里 56,195 道 choice 题，选项数全部是 2。Jev 的 choice 支持 2–255 个选项，实际使用中 "这是什么房间：厨房 / 卫生间 / 卧室" 这类三选一、多选一很常见，模型从来没训练过。
- **只有是非题和二选一**：没有计数（"几个人"）、颜色、"什么运动 / 什么动物 / 什么房间" 这类开放类别题。VQAv2 里这类题（answer type 为 number 和 other）约占六成，目前全部被丢弃。

### 2. 只看题目就能猜（文本捷径）

用 "训练集里同一句题目的多数答案" 去答评测题，完全不看图：

| 评测集 | 题目在训练集里出现过 | 只看题目的准确率 |
|---|---|---|
| POPE | 297 / 300 | **0.636** |
| val_cocoqa | 912 / 1,000 | **0.714** |
| val_gqa | 104 / 1,000 | 0.606 |
| val_vqav2 | 299 / 1,000 | 0.538 |

主要来源是 COCO 出题：

- **"有没有某物" 按类别严重偏斜**：person 78% 答 "有"；chair、car、dining table、cup、handbag、bottle、backpack 这些 81–88% 答 "没有"。原因是负例挑常见的共现物体，而正例从图中物体里随机抽、大多数图里都有人。这和 POPE 的出题方式相近，所以**POPE 上的提升有一部分可能来自这个捷径**。
- 大小题只看类别能答对 0.844，上下题 0.757（见实验记录），"dining table 在下面" 96%、"person 比 tennis racket 大" 100%。
- 共有 108 句高频题目的答案偏斜 ≥ 75%，涉及 17,296 道训练题，占全部训练题的 11%。

### 3. 标签质量（各抽 8 道对图核对）

| 来源 | 有问题或无法核实 | 说明 |
|---|---|---|
| VQAv2 是非题 | 0 / 8 | 标签细致（"人背着滑雪板" 判为 "没有穿滑雪板"），主观题的软标签合理（"水面平静吗" 0.4） |
| COCO 出题 "没有某物" | 约 1 / 8 | 一题背景里有疑似桌子的物体；COCO 标注不全时 "没有" 可能是错的 |
| GQA 是非题 | **3–4 / 8** | 一题明显标错（红黑格子衬衫问 "是红色吗" 答 "否"）；另有两三题问的物体在 256 像素下看不见或找不到（"纸巾右边的自行车"、"香肠"、"书"） |

GQA 来自 Visual Genome 场景图，问题经常涉及很小或被遮挡的物体，在 256×256 输入下大量题目无法从图上判断。

### 4. 当前模型学不会的题占了不少

- 实验已经确认模型学不会 "文字说的那个物体在哪边"（见 `../experiments/2026-09-30-rlcd-plateau.md`）。GQA 二选一里约 64% 是左右 / 上下题，COCO 出题里还有绝对和相对位置题，合计约 3 万道训练题。在绑定问题解决之前，它们提供的有效信号很少，主要被模型当作类别先验来学。

### 5. 评测集偏小、和训练同源

- POPE 只有 300 题、50 种不同的问法，标准误约 2.6%；laya-vision 用的是 3,000 题。
- val_cocoqa 和训练集同一套出题规则，同样带着上面的捷径。

## 改进方案

按 "预期收益 / 成本" 排序。所有改动都**生成新文件**（例如 `cocoqa_train_v2.jsonl`），不覆盖现有数据；用新的实验 YAML 对比。

| # | 方案 | 解决 | 做法 | 成本 |
|---|---|---|---|---|
| 1 | **"有没有某物" 按类别配平** | 文本捷径 | 每个类别的 "有 / 没有" 各占一半：负例仍按共现挑（保留 POPE 式难度），但同时按类别配额抽正例，让 "chair" 被问到时有一半是 "有"。大小、上下题同理，优先保留 "违反类别常识" 的样本（杯子比汽车大、桌子在上方） | 低：改 `cocoqa.py` 的抽样，生成新文件 |
| 2 | **从 VQAv2 非是非题生成多选题** | 只有二选一、题型窄 | 对 "what color / what sport / what room / what animal / how many" 等题，以标注者答案分布为 gold（软标签），从同类问题的答案词表里挑 2–4 个干扰项（排除任何标注者给过的答案），组成 3–5 选一。VQAv2 train 有数万道这类题可用，图片已在本地 | 中：新转换器 + 测试 |
| 3 | **减少 GQA、筛掉看不清的题** | GQA 噪声 | 降低 GQA 在混合数据中的比例（例如 6 万 → 2 万），优先保留不涉及空间关系的是非题和属性选择题；如果拿到 GQA 场景图里的物体框，可以剔除目标物体面积过小的题 | 低（降比例）/ 中（按框筛） |
| 4 | **暂时下调左右类题** | 学不会的题占比 | 在绑定问题解决前，把左右类题（GQA 和 COCO 出题）降到很小的比例，上下、大小题按方案 1 去掉先验样本 | 低 |
| 5 | **扩大并去偏评测集** | 评测不可靠 | POPE 用 lmms-lab/POPE 全部 3 个分片（random / popular / adversarial 各 3,000）；评测报告里加一列 "只看题目的准确率"，提升必须超过这条线才算看图；新增 VQAv2 val 多选题评测集，对应方案 2 | 低 |

### 建议的执行顺序

1. 先做方案 5（评测）和方案 1（配平），成本最低，而且能把 "看图" 和 "猜先验" 分开，后面的比较才可信。
2. 再做方案 2（多选题），这是覆盖面上最大的缺口，也最可能缩小和 laya-vision 在 VQAv2 上的差距。
3. 方案 3、4 在混合新数据时一起调整比例。

数据生成脚本都在仓库外的 `scripts/data/`。新训练集准备好后，用一份新的 `configs/*.yaml` 从当前最好的对齐 checkpoint 开始跑阶段 2，和现有配方对比。
