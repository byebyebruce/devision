# 从 v12 重新训练：修正数据偏置并学习绑定

日期：2026-10-11。作者：Codex。状态：负责人已确定初始化起点；下列配方、预算和实现仍为待执行建议。

## 1. 负责人决定与目标

负责人明确：“不想保留 13，要从 12 开始训练，因为 13 的破坏性太大。”据此撤销 [上一份方案](2026-10-11-r13-recovery-plan.md) 中从 R13 恢复及其 A/B、预算和放行条件。

**唯一初始化 checkpoint：`runs/v12-ext/stage2`。** 新实验不加载 R13 权重、S2 参数、优化器或续训状态，也不将 R13 作为教师。R13 既有数据问题分析和预测仅作历史证据；此决定不包含删除历史产物或停止现有进程。

目标改为：**守住 v12 的存在性、计数、科学和通用能力，再获得绑定提升。** 所有主要差值均以 v12 为基线，不以 R13 的退化水平作为合格线，也不要求短训练立即重现 R13 的全部绑定成绩。

本次只更新方案文档，未执行训练、评测、温度拟合，未修改数据、代码、配置或 checkpoint。

## 2. 第一轮只改训练配方，保留 v12 结构

- 沿用 v12 的冻结 SigLIP2、256 输入、64 个视觉 token、投影层、决策头及 LoRA 规格；阶段 1 对齐不重做。
- **第一轮不增加 S2 或 S1。** 这是减少变量的设计选择，不是已经证明 S2 有害。此前短筛选 S2 对 S0 的优势区间包含 0，不能把整套 R13 配方的绑定收益归于 S2 单项。
- 修正存在性正负配额、计数候选项构造、旧任务分层回放；沿用 RLCD 目标，不同时更换训练损失或增加教师推理。
- 若修正数据后仍不足，再提“同数据、同预算、v12 初始化，新增零初始化 S2”的单独对照；不继承训练过的 R13 模块。本轮不自动开展该对照。

这些修正针对已有直接证据：真实对象存在性题正例仅 14.97%、计数候选提供下中位数捷径、旧能力困难切片缺乏保护。具体统计保留在上一份文档第 2–3 节；它们支持改数据，但尚不能量化各项对退化的因果贡献。

## 3. 数据配方：约 80,000 次题目曝光，旧任务至少占一半

按展开后的题数计量，不按 JSONL 行数或来源文件数平均。下表是启动前要固定的目标配额；完整成对单元造成的取整应写入最终 manifest，准确步数按实际打包结果计算。

| 任务块 | 比例 | 目标题目曝光 | 要求 |
|---|---:|---:|---|
| 新绑定监督 | 30% | 24,000 | 真实照片 GQA/VisMin 约 16,000，合成约 8,000；保留完整反事实对/场景族、显眼程度及比较切片 |
| 原有真实照片存在性 | 20% | 16,000 | 从 v12 训练池抽 COCO-exist、Objects365；各来源正负约 1:1，固定类别配额，不设一万道否题保底 |
| 计数 | 20% | 16,000 | 原计数回放约一半，PixMo/TallyQA complex 约一半；0–2、3–5、6–10 分桶，每桶约 1/3，并记录桶内数量分布 |
| 科学/示意图 | 10% | 8,000 | ScienceQA、AI2D、TQA；覆盖相同文字不同图答案不同的模板族，不能只重复一个磁铁小集合 |
| 通用旧能力 | 20% | 16,000 | A-OKVQA、VQA choice/yesno、大小、V7W/VSR 等，给小来源保底并保留原软标签 |

存在性、科学、通用三块合计 50% 为旧任务；计数中还包含旧任务回放。每题只计入一个主配额，不能重复计算“旧任务占比”。这套比例是待验证起点，不是已证明的最优配比。

必要的数据约束：

1. **正负平衡针对具体任务。** 先保证真实对象存在性各来源约 50% 正例，再检查物体类别的偏斜。属性组合不存在、空间关系、一般 VQA 分开报告；保留合成和编辑对，不为全局 50/50 随意删除困难负例或改标签。
2. **纠正计数捷径。** 正确数在 0–10 的纯数字计数使用同一 `0..10` 完整候选集，排列独立打乱；不以 gold 为中心选邻近数。答案超范围、非整数或软标签映射不完整的题单列，不能裁掉正确答案。原来 2–5 候选的开发评测仍保留。
3. **唯一题数与曝光分开。** 已核对 v12 池中 ScienceQA 4,725、AI2D 1,575、TQA 1,575，合计 7,875 条。8,000 是约曝光量，可能涉及少量重复/取整；优先完整覆盖，明确最大重复次数，不能写成新增 8,000 道不同的题。其他来源同样报告唯一图片、问题和场景族。
4. **保护已有强项。** 新绑定来源只占 30%，不再让所有新来源不加选择地占约 81%。通用块来源配额在构建前固定，避免 A-OKVQA 或大量存在题挤掉 VQA/大小等来源。
5. **沿用图片隔离。** 校验 caption 对齐及历轮训练、监控、校准和测试身份，包含 COCO/VG 映射、合成照片背景身份及已有近重复规则。继承旧数据报告不代替对新混合清单的核对。

## 4. 一条训练主线，固定总日程，提前检查是否损害旧能力

建议实验名 `r13b-v12`（只是待实现名称），从 v12 建立新优化器、新学习率日程和独立输出目录。

| 参数 | 建议 |
|---|---|
| 总曝光 / epochs | 约 80,000 题，一遍；按完整单元实际打包确定步数 |
| micro_batch | 8，约 10,000 步 |
| lr_new / lr_head | `2e-5` / `1e-5` |
| lr_lora | `5e-5` |
| S2 / grounding | 关闭；不使用 `lr_cond` |
| warmup | 300 步，随后按完整约 10,000 步日程 cosine 到 0 |
| RLCD / LoRA | 保持现有目标、`sigma_start=0.4`、`sigma_end=0.1`、r=16、alpha=32 |
| 精度 / seed | 本机 MPS FP32 / 0 |
| 保存 | 每 500 步；保留已有数值异常保护 |
| 小面板监控 | step 0、2,000、4,000、6,000、8,000、末步 |

这些学习率低于 R13 正式训练，是保护旧能力的起始选择，不保证无需调整。**前 2,000 步是检查退化，不是要求新绑定能力已经训练完成。** 历史 2,000–3,000 步筛选没有合格候选；本方案不能重复“短筛选未过就判架构无效”的推断。

如果前段没有触发止损，按预写日程继续；不在 2,000 步先把学习率降至零再临时接训。触发止损的分支结束，不自动降低学习率换配置重跑，也不从 R13 借用权重。启动前先完成数据与面板准备，不能把这份建议当作已经存在的可执行 YAML。

## 6. 预写判断：以 v12 为保护线

启动前冻结面板、seed、准确总步数和下面的条件。所有差值均为候选减 v12；按原图/合成族配对 bootstrap 2,000 次、95% 区间，保留逐题预测。小切片证据不足应如实报告，不以总体 dev_mix 持平代替。

### 6.1 周期止损

- 从 step 2,000 开始，存在性召回下降 ≥3 个百分点且区间上界 <0，或平衡准确率下降 ≥2 个百分点且上界 <0：停止该分支。
- 原格式计数或科学面板准确率下降 ≥3 个百分点且上界 <0：停止该分支。原本就弱的宽候选计数不能掩盖原格式退化。
- 存在性、计数或科学的未校准 NLL 比同口径 step 0 增加 ≥0.10 且差值下界 >0，连续两个监测点出现：停止并排查；单次波动不直接判故障。非有限或设备返回异常仍按现有运行保护处理。
- 真实照片绑定若下降 ≥3 个百分点且区间上界 <0，同样停止。尚未提高本身不是前段止损理由。

这些为拟定的新实验止损阈值，执行者可在开训前提出资源/样本量方面的异议，由负责人确定；运行后不能为了继续投入临时放宽。

### 6.2 末步是否值得进入全量回归

- 真实照片绑定准确率较 v12 提高且差值下界 >0；合成联合正确率较 v12 提高且下界 >0，同时报告每个显眼程度层。
- 存在性召回、平衡准确率及原格式计数/科学准确率，差值下界均 >−2 个百分点；存在性假正例率的增加上界 <+2 个百分点。
- 校准后概率质量没有“计数或科学 NLL 增加 >0.02 且差值下界 >0”；其他任务的 NLL/ECE 也照实报告。
- 宽候选计数须报告相对 v12 和最佳常数基线的差值、真图/错配图收益；不能只凭预测数字不再集中就宣布会计数。
- 任何主要项明确退化则不进入；区间过宽则记证据不足，交负责人决定，不自动无限加步或加种子。通过者只跑一次全套历史回归，不在中途全面重复跑 benchmark。

### 6.3 是否采用

目标是旧能力接近或优于 v12，绑定能力得到可靠提升。**正式采用继续按原有旧能力保护和概率警戒规则报告**，而非“比 R13 好就通过”。保留 R13 作为历史比较列即可，不以其绑定成绩抵消新的旧任务退化。最终若需要放宽取舍，须由负责人明确决定。

### 8.2 实施前要定的事

1. **v12-ext 的扩展来源不在任何任务块里（待定，影响最大）**：
   - v12 池里有 10 个来源约 19.2 万题（占池 54%）不属于第 3 节的五块：CLEVR 35,000、SNLI-VE 30,000、FigureQA 30,000、IconQA 27,260、Vision-Flan 24,152、VisOnlyQA 11,486、CLEVR-Math 10,000、Super-CLEVR 10,000、MapQA 7,500、SpatialSense 7,059。另外 Objects365 约 6,200 道左右题也不在其中。
   - 这些是 v12 相对 v11 学会的能力（training-log v12 一节：Vision-Flan 62.7 → 92.3、IconQA 41.3 → 71.7 等）。
   - 第 3 节"旧任务至少占一半"没有覆盖它们，会有遗忘风险，而现有的保护线（`test_*`、`bench_lv_*`）也测不到。
   - 两种做法：在"通用旧能力"块里给它们保底（会挤占其他来源），或至少把 `data/ext/dev_ext.jsonl` 按来源加进训练中监控和末步判定。
2. **按题型而不是按来源分配额**：Objects365 这个来源同时有存在性题（50,288）、计数题（约 23,500）和左右题（约 6,200）。"每题只计入一个主配额"应按题型判定，否则 Objects365 的计数题会被算进存在性块。
3. **窄候选计数无论怎么构造都有捷径（离线模拟，不涉及模型）**：
   - 用 v12 池里 0–10 的真实计数 gold 分布（TallyQA / Objects365 / PixMo-Count，66,199 题）模拟：若干扰项从 0..10 随机抽、2–5 个选项，"选最小的数"能对 61.1%，"下中位数"能对 38.3%，随机期望 32.0%。原因是 gold 偏小。
   - 现在的 ±3 邻近构造（PixMo 两类、TallyQA complex 实测）是"下中位数"能对 51.9% / 44.0%。也就是说，换一种窄候选的抽法只是把捷径换成另一种。
   - 宽候选 `0..10` 没有只看选项的捷径，只剩先验：最常见的答案"2"占 24.7%，三桶各 1/3 后会更低。
   - 建议：0–10 的训练计数题全部用宽候选，原 2–5 候选只留在评测里（第 3 节第 2 条保留了原格式评测，但没写训练里窄候选还占多少）。如果要保留一部分窄候选训练，先定比例，并在清单里报告"最小数 / 下中位数 / 最常见数"三条规则的准确率。
4. **宽候选的温度分桶**：
   - `0..10` 是 11 个选项，落在 `choice:11+` 桶（`laya.common.temp_bucket`）。v12 没有这个桶（只有 `choice:2`、`choice:3-5`、`noul:2`），会退回 choice 的总温度。
   - 拟合集里 11 个选项的题少于 50 道（`MIN_BUCKET_ITEMS`）时同样不建桶。
   - CountBench 是 10 个选项，落在 `choice:6-10`。如果想让训练与 CountBench 同桶，可以改用 `1..10`，但这样就丢了 0；保留 0..10 的话，校准集至少要有 50 道 11 选项题。待定。
   - 答案大于 10 的题（如 IconQA 1,718 道）按第 3 节第 2 条保留原格式、单列。
5. **周期止损需要逐题输出，现有代码给不了（待定，需要一个小的代码改动或改规则）**：
   - 训练中的 `--eval`（`rlcd.py` 的 `_set_metrics`）每个集合只给准确率（全部 / noul / choice）、按来源拆分、NLL、ECE，温度为 1；没有逐题明细。
