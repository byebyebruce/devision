# exp19 方案：解冻 SigLIP 最上面 4 层的 2,000 步小对照（待评审）

日期：2026-10-14。负责人："可以，开始吧"。按负责人此前的做法，代码和测试写完后先交评审，评审没有问题再训练。不算一轮，不产出可采用的模型。

## 要回答的一个问题

从第 1 轮起，视觉编码器 SigLIP2 一直冻结。示意图科学题、左右镜像、VSR 这类"要在图里找到并比较"的能力，十几轮补数据都没补上（`docs/experiments/2026-09-30-rlcd-plateau.md`、`docs/research/laya-vision-gap.md`）。exp17、exp18 处理的是遗忘问题，不是能力上限。

这里问的是：**同一份数据、同一批序、同样 2,000 步，只放开视觉塔最上面 4 层，这些目标面板会不会在早期就变好、而其他能力没有明显损失？**

文献对解冻视觉塔的结论不一（`docs/research/binding-2026-10-08.md`：LLaVA-OneVision 后期解冻、视觉学习率取语言模型的 1/5，Prismatic 报告有害）。所以先做短程。

## 设计：两组只差一个变量

| 组 | 说明 | 来源 |
|---|---|---|
| B（视觉冻结） | r14b 数据（含 v6 左右镜像对 2,000、VSR 1,000），种子 1，到第 2,000 步 | **复用** `runs/exp16-r14b-s1` |
| D（解冻最上面 4 层） | 同 B，SigLIP2 第 8–11 层（共 12 层）和最后的 layer norm 以学习率 5e-6 训练 | 新训，`configs/exp19-vision.yaml` |

- 选 r14b 数据，而不是 r14，是因为它有左右镜像对和 VSR 的训练信号。前 2,000 步按复用的批序统计：镜像 391 题、VSR 199 题、科学 1,573 题。
- 其余与 exp16-r14b-s1 完全相同：学习率 2e-5 / 1e-5 / 5e-5，warmup 300，余弦日程按 10,235 步计，micro batch 8，MPS FP32，种子 1。
- **超参数（开训前冻结，不扫）**：解冻 4 层，学习率 5e-6，低于本项目投影层（2e-5）和 LoRA（5e-5）的学习率。跨论文只借鉴"视觉组用较小学习率"的思路：LLaVA-OneVision 是全模型训练，视觉 2e-6、语言 1e-5、全局 batch 512；本实验 batch 8、语言侧主要是 LoRA，两边不能按比例比较保守程度，这一点没有验证。（评审 EXP19-N01 修订。）
- 结构、视觉 token 数和输入分辨率都不变，推理计算量不增加，**CPU 推理延迟预计基本不变**（未测）。

## 判定（开训前写下，结果出来后不改）

只在第 2,000 步读一次，温度 1 的逐题记录，D − B，逐题配对。重采样单位是图片，镜像图和原图算同一张。

- **P1 目标面板**：`science`、`flip`、`vsr` 三个面板准确率差的等权平均，同一张图在各面板中一起进出。下界 > 0，记为"早期改善"。
- **P2 不明显伤害**：`exist`、`bind_gqa`、`ext`、`count_narrow`、`count_wide` 中，没有任何一个面板准确率差 ≤ −3 个百分点且上界 < 0（与此前止损规则的口径相同）。

| 结果 | 条件 | 下一步 |
|---|---|---|
| **有效** | P1 下界 > 0，且 P2 成立 | 建议做更长的训练（步数和采用规则那时另写），由负责人批准 |
| **无效** | P1 点估计 ≤ 0 | 不再按这个设置解冻视觉塔 |
| **不确定** | 其他情况（包括 P1 下界 > 0 但 P2 不成立） | 交负责人决定 |

只报告、不改判定的项：
- 8 个面板 NLL 差的等权平均；
- 每个面板的准确率和 NLL，D − B、D − v12 各一份；
- flip 按 596 张原图分组；
- 三个 PixMo 面板。

**已知限制**：
- `science` 面板不能单独切出"必须看图"的题；
- VSR 面板小（280 题），而且全部在温度拟合集里；
- 只有一个种子，2,000 步不代表训完的结果；
- 测试集不碰。

## 实施（代码已写好，尚未训练）

- `src/devision/train/rlcd.py`：
  - `TrainConfig.vision_unfreeze_top`（默认 0，即冻结）和 `lr_vision`（默认 5e-6）；
  - `_vision_params` 选出最上面 N 层和 `post_layernorm`，层数不在范围内就拒绝；
  - 视觉参数单独一个优化器组；
  - `_forward` 只在视觉参数需要梯度、且当前允许求梯度时，才对视觉塔求梯度，评测和教师前向不受影响；
  - 这两个设置加进续训一致性检查；
  - 学习率日志改为按组名记录。原来只有 S2 模块、没解冻文本层时，S2 的学习率被记成 `lr/encoder`，现在记成 `lr/cond`，只影响日志。
- 训练出的视觉权重随 checkpoint 一起保存（视觉塔本来就在 `model.safetensors` 里）。
- `tests/train/test_vision_unfreeze.py`（tiny 模型，CPU）：
  - 默认冻结时，保存的视觉权重不变；
  - 解冻时，只有最上面的层和最后的 layer norm 变化，embedding 和 head 不变；
  - 批序和每次噪声抽样时的随机数状态与冻结时相同，第 0 步通过 `start_check`，第 1 步的 nll 相同，之后不同；
  - 层数越界会被拒绝；
  - 中断续训后的损失和视觉权重与一次训完相同。
- `configs/exp19-vision.yaml`：与 `configs/exp16-r14b-s1.yaml` 只差 `vision_unfreeze_top`、`lr_vision`、`start_check`、`start_tolerance`（`--dry-run` 检查通过）。
- `scripts/exp19/chain.sh`：复用 exp18 的链。exp18 的链只加了一个日志名变量，行为不变。
- `scripts/exp19/report.py`：先用 `same_start` 核对起点，失败时返回 2，再算 P1 / P2 和出口。试跑：把 exp16 的 r14 组当作 D、r14b 组当作 B 跑通，不作结论。
- 验证：`uv run pytest` 186 项通过（新增 5 项），`scripts/exp18` 3 项通过，pyright 0 错误。

## 预算

- B 复用，0 分钟。
- D 的耗时是估计，未实测。视觉塔多 4 层的反向传播，估计每步比 B 多 10–20%：B 日志里 20 个 `step_s` 窗口的平均是 1.195 秒；原写的 1.39 秒是第 100 步的单个窗口，含起步开销。2,000 步加两次监测约 75–85 分钟。
- 内存（估计）：解冻的 28,353,024 个参数，除激活值外还要存梯度和 AdamW 的两份状态，FP32 合计约 325 MiB；另有激活值和临时内存，这不是峰值估计。实际的 step 耗时、总墙钟时间和 `torch_mps_gb` 从本次运行日志里读取。（评审 EXP19-N02 修订。）
