## 1. 区域覆盖审计（`scripts/exp66/audit.py` → `data/exp66/audit.json` e50ab2e6…，逐读明细 audit.details.jsonl）

**口径**：

- 墨迹：文字色像素（EXP60 的规则：最大通道 < 110、通道差 < 40），在字段的参照框内取。
  - 训练和 tune：参照框是字段行带，或文字框外扩 3 px；
  - dev24：参照框是 EXP60 oracle 框。
- 框：已登记的 EXP62 选择器框。训练集用 data/exp64/train.jsonl；tune_V 和 rl_tune 用 EXP62 的读数（核对过登记）；dev24 用 EXP62 的 details。
- 共 7,224 个读数，每个读数都找到了墨迹。
- 分开记的四组量：
  - 画布：墨迹高度、底边距、外侧边距，栏中心 / 宽（从外侧量），行距 / 墨迹高，标题到首行的间距（以行距计），罐底到标题的间距；
  - 偏移：框中心 − 墨迹中心（y 以墨迹高计）；
  - 相对几何：墨迹在框内的中心和高度，按框单位计。region 的 geom 正是用这个坐标把每个 token 交给读出头；
  - token：被选中的格子数，以及它们覆盖墨迹的比例。
- 另统计生成器 train split 全部 6,000 个场景，只用绘制元数据（PIL 文字框）。

## 2. 版式变体（`scripts/exp66/build.py` → `data/exp66/`）

- **温度**：每个样本的整栏（罐、粒子、标题、两行字段）向外平移 shift px，两个样本平移相同。
  - shift 在 [−s_in, s_max] 内均匀取。
  - s_max 是让所有文字离画布边缘 ≥ 1 px、罐外框 ≥ 2 px 的最大外移；s_in（≤ 8）是让文字离画面中线 ≥ 2 px 的最大内移。两者都在两个视图上同时满足。
  - 之后沿用 EXP61 的空白行裁剪：顶 t ∈ 0..min(30, 首个墨迹行)，底留 m ∈ 0..6 px。
- **磁力**：沿用 EXP61 的顶裁剪，并在底部加 b ∈ 0..8 行空白（标签的底边距）。
- **不变的部分**：行距、字号、措辞、数值都用生成器自己的。
  - 同一族的两个视图（场景及其改值孪生）共用全部版式参数，由 random.Random(sha256("exp66-v1:" + family)) 决定，族内只有数值在变；
  - 两个视图的画布尺寸相同（已核）。
- **标签**：沿用 EXP45 / 51 的语义，并随实际绘制平移。
  - 温度：该样本的半幅行带（宽 w / 2 − 4，高一个行距），以平移后的栏为中心，在画面中线处截断。shift = 0 时与 exp45 的行带完全相同（已核）；
  - 磁力：宽标签带；
  - 然后整体平移 −t，并裁到画布内。没有统一换成紧框。
- **逐题全量核对**（绘制元数据 + 像素）：
  - 值的文字框在框内，也在画布内（不切字）；
  - 另一对象的文字、同一样本的另一行和标题都不碰框；
  - 框内所有文字色像素都落在目标文字框内（磁力另允许它自己的尺寸线）；
  - 裁剪只去掉空白行。
- **集合**：
  - **train_C**：生成器 train split 的 100 个温度族 + 100 个磁力族，按稳定 hash 排序选取，排除 exp49 的全部 440 个族和 EXP61 train_V（即 EXP62 父图）的 200 个族。共 400 张图、1,200 题；
  - **train_C_parent**：这些族的生成器原图（就是 data/real_layout 里的文件），用 EXP45 框，按 key 与变体题一一配对。共 400 张、1,200 题；
  - **tune_C**：tune split 的全部 300 个族（即 rl_tune / tune_V 的族），用新版式。共 600 张、1,800 题，现在冻结，从不训练。
- **隔离**：train_C 与 tune_C 的族交集 0、case 交集 0（case 包括孪生的 case）；与 exp49、EXP61 的族交集 0。confirm split 不动。
- **身份**：questions e9bee6ba…，图片摘要 c570f037…，coverage 0a0c528e…，MANIFEST c8f09627…。重建结果逐字节相同。
- **新版式覆盖**（`coverage.json`，按墨迹计）：

**仍未覆盖的缺口**（明确记下，不为赶进度重试）：

- 外侧边距 0–1 px：要做到就得让字贴边或被切，违反不切字的要求。新版式最小到 2 px。
- 磁力标签的水平位置：dev24 最低 0.193，生成器最低 0.222，本轮没有改。
- 真实图的字体渲染、JPEG 压缩、罐的形状和间距（罐底到标题的间距 0.88，略低于训练的 p05 0.95）都没有建模。
- 第 1 节里 token 选择与相对几何的区分，要等前向才能做。

## 3. 之后的运行（未获许可，先审方案和预算）

- **冻结**：EXP64 头 0e275bdf、EXP57 视觉 962503fb、网格 n12 / 0.25、区域规则、决策模型。
- **唯一训练的部件**：选择器。从 EXP53 端点 8f10f1fd 出发，配方与 EXP62 逐项相同：L1 + GIoU、AdamW 1e-3、100 步预热后 cosine、seed 0、2,000 步、取末步、CPU。
- **与 EXP62 的唯一差别**：对子池在 EXP62 的 1,200 对之外加上 train_C / train_C_parent 的 1,200 对。
  - 每批仍是 24 对 + 16 行回放（fit_O + fit_L），批计划由同一个生成器产生、固定 seed；
  - 因为池子扩大，每对的曝光从 40 次降到 20 次。这一点算作配方的一部分，结论只归于整个配方。
- **对照**：同一个 EXP64 头配 EXP62 选择器 c92b7b7e。rl_tune、tune_V、dev24 的读数沿用 EXP64 已登记的结果；tune_C 在本次运行中现读。
