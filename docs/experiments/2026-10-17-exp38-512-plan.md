# exp38 方案：原图 512 输入迁移短筛（评审第 1 轮：EXP38-R1-01–03 已补，按 EXP38-RUN-01 附条件放行）

日期：2026-10-17。依据：评论家 EXP37-RESULT-01 / 02、EXP38-PREP-01 / READOUT-01、V04-NIGHT-02。

exp37 说明，在共同版式下把数字放大到 256 上约 16 px、训练和测试一致时，补全和绑定可以被救回；但两个模型在原图上都只有 0.09 / 0.11。这里不重绘任何图，直接在原生图片上检验：用更高的采样密度（512 输入）再适应一次，exp37-L 的能力能不能转到原图的数字和对象对应上。

本对照同时改变了像素采样和视觉序列长度，不声称把两者的因果分开。

## 两臂

| | C（对照） | H（实验） |
|---|---|---|
| 配置 | `configs/exp38-c.yaml` | `configs/exp38-h.yaml` |
| 输入 / 视觉 token | 256 / 64 | 512 / 256 |
| 起点 | `runs/exp37-l/stage1`（sha256 `f9fc93c2…`） | 同一份权重，`scripts/exp38/convert.py` 只把 config 改成 image_size 512 + interpolate_pos_encoding |

- **共同部分**：
  - 都从 exp37-L 的末点独立开始；
  - 数据：exp36 的原图混合（`912a9cd2…`，4,000 族两视图的原 real_layout 图 + 8,000 张 COCO），同一文件、同一顺序，seed 0；
  - exp36-B 的双侧全数值遮罩，各 1,000 步，batch 16；投影层 2e-5、LoRA r16 / alpha 32 / 1e-4、warmup 100、max_caption 44，视觉塔冻结。
  - 两份 YAML 只差 name 和 init（已 diff）。
  - 不用重排的 L 图，不靠 OCR、gold 框或问题文字裁剪，不重绘评测图；confirm、75 题属性、80 题 ChartQA 都不进入。
- **结构**（保留全部已有参数）：
  - patch16、visual_shuffle 2、投影层的维度和全部参数张量都不变，不折叠、不重置，不下载别的骨干。
  - 512 下 SigLIP 输出 32 × 32 patch，现有 `Projector` 按网格 2 × 2 合并成 256 个视觉 token。
  - 位置编码用 transformers 自带的 `SiglipVisionEmbeddings.interpolate_pos_encoding`（在原 16 × 16 表上双三次插值），只在非原生尺寸时启用；视觉塔原 256 的位置表和配置都保留。
- **代码改动**（`src/devision/model.py`、`train/align.py`、`train/rlcd.py`）：
  - `ModelConfig` 新增 `interpolate_pos_encoding`（默认 False，旧 checkpoint 行为不变）。
  - `VisionDecisionModel.vision_patches()` 成为唯一运行视觉塔的地方：decide / evaluate（`image_features`）、对齐（`_mlm_logits`）、决策训练（`_forward`）原来直接调视觉塔的三处都改走它。
  - image_size 与视觉塔原生尺寸不同、却没打开插值时，直接报错。
  - 预处理统一用 `cfg.image_size`（`image_tensor` / `_Images` 原本就读它）。
  - 冻结的边界不变：对齐时视觉塔在 no_grad 里，投影层在外面；决策训练按 `vision_unfreeze_top` 决定是否让梯度进入视觉塔。
  - 视觉 token 插在 [CLS] 之后，文字的 512 预算不受影响，长问题和多选项不会因为多了 token 被截断（编码器上限 8,192）。
- **身份**：两个起点的权重 sha 完全相同，但行为不同，所以 START / 报告同时记 model sha、config sha、image_size、视觉 token 数和插值设置（`CONVERTED.json` 另记转换前后每个权重文件都逐字节相同）。

## CPU 夹具（`tests/train/test_resolution.py`，tiny 模型）

1. 转换后所有参数与源逐张量相同，只有 config 不同；512 的视觉 token 是 256 的 4 倍；decide 能正常返回概率。
2. 尺寸不是原生、又没开插值时拒绝构建。
3. 512 下对齐：投影层有变化，视觉塔与起点逐位相同；再做决策训练（`vision_unfreeze_top 1`）：视觉塔顶层有变化，说明梯度没有被截断。存盘再加载，image_size 和插值设置都保留。

全部测试 216 + 3 项通过，pyright 0 错误。256 的旧行为由原有测试覆盖。

## 512 实际能看清多少（`runs/exp38-preview/`）

- 用场景字号和 letterbox 比例估算的数字墨迹高度（按字形框估算，不是逐张测量），见 `digit_heights.json`：

  | | 256 中位（范围） | 512 中位（范围） | 512 上 ≥ 8 px | 512 上 ≥ 12 px | 512 上 ≥ 16 px |
  |---|---|---|---|---|---|
  | tune 1,800 个数字 | 5.2（3.3–7.7） | 10.4（6.6–15.4） | 90% | 7.6% | 0% |
  | fit 600 个数字 | 5.2（3.6–7.6） | 10.4（7.2–15.1） | 89% | 10.7% | 0% |

- 512 只放大两倍：没有一个数字达到 exp37-L 训练时的 16 px，约十分之一仍低于 8 px。
- 预览：`inputs.png`，tune 文件中前 8 张温度图和前 8 张磁力图，按顺序选取、不看任何预测，每张给出 256 | 512 两种实际输入。

## 读出（运行前写下，不改；`scripts/exp38/report.py`，复用 exp36 的统计）

  - ScienceQA 温度 / 磁力的真图和固定错图；

- **预算决定**（评论家 EXP38-R1-02）：采用 A 的优先顺序，上限改为 min(启动 + 210 分钟, 10-18 00:30)。194 分钟的估计在其内，但这只是估计，不是实测保证。
- **截止和缺项**（`scripts/exp38/steps.sh`，chain 用它运行每一步）：
  - 每一步（含 512 转换）都在截止前 60 秒结束：到点 TERM，15 秒后 KILL。最后 60 秒留给终报告。
  - 每一步的结果写进 `runs/exp38-status.txt`（completed / failed / interrupted / missing），不凭 details 文件存在就算完成。
  - 只报告的项一旦被打断或来不及开始，其余的都记为 missing，不再启动。
  - 终报告只用 completed 的项：保护没评完时写"保护未完整评估，代价只在已完成面板中观察"，不写成全套无代价。
  - 主读出缺失时结局为 incomplete，不给任何通过标签。
  - 终报告失败或主步骤失败时，chain 以非零退出；不在截止之外补跑。
- **身份**（EXP38-R1-01）：
  - readout 在第一次前向前写 START.json，记 config sha、image_size、视觉塔原生尺寸和 patch、visual_shuffle、视觉 token 数、插值设置。
  - 报告核对：同一臂的 tune 和 fit 是同一个模型、同一种输入；C 必须是 256 / 64 / 不插值，H 必须是 512 / 256 / 插值。不符合就拒绝出报告。
  - 复用已有的 512 转换目录时，先核对它的源 sha 和配置。
- **非有限 loss**（EXP38-R1-03）：对齐时只要 loss 非有限（包括纯 MLM），就在任何更新之前报错停止，不保存 checkpoint。
- **CPU 夹具**：
  - `scripts/exp38/test_exp38.py`（4 项）：部分保护、主读出缺失、H / C 身份对调被拒；截止落在附加评测里时，主结果保留、缺项准确标注、不响应 TERM 的子进程在限时内被结束、终报告照常写出；报告失败时返回非零。
  - `tests/train/test_resolution.py` 新增注入 NaN 的用例：在更新前失败，不留 checkpoint 和 align_report。

命令：`nohup bash scripts/exp38/chain.sh > runs/exp38.out 2>&1 &`，评论家放行后才运行。
