# EXP72 方案：训练时让模型使用固定的 K 中间量——同起点、同预算、以比较为主的 raw / K 两臂（EXP72-PREP-01；CPU 方案与数据审计，未写 runner，未运行）

日期：2026-10-19。依据 EXP70-RESULT-01：

- 零样本插入 K 块全面变差（冲突宏平均 −0.144）；EXP68-X 自己训练过的速度胜组合只答对 8 / 20。
- EXP68 的训练里，温度比较只占 1,200 / 9,600 = 12.5 % 的 loss，每类 200 / 9,600 = 2.08 %；4,800 道温度读数题不算组合比较的监督。监督暴露不足是合理解释之一，但没有被证明是原因。
- 本实验的方向是「训练时让模型学会使用固定的 K 中间量」，不是继续零样本插入，也不是只给同一种直接分类配方加预算。不续训 EXP68 端点去追分数，不扫 K 格式、权重或步数。candidate_eligible 恒为 false。

## 两臂（唯一的差别是温度 state 里有没有 K 块）

- **相同的部分**：
  - 都从 EXP68-X 的冻结端点（2e5b272e… / 87f82281…）独立出发：原样加载它的决策头和已合并的旧 LoRA，再加一个新的 LoRA r16（B 初始化为零，所以训练从 EXP68-X 的函数开始），训练这个新 LoRA 和原有的决策头；不随机重置决策头（评审 EXP72-NOTE-01）；
  - 配方与 EXP63 / 65-C / 68 相同（lr_lora 5e-5、lr_head 1e-5、warmup 100、seed 1、batch 8、text_only CE、权重全 1、末步）；
  - 同一份行、题、组、顺序和批计划（审计逐项核对，见下）；
  - 磁力行在两臂里逐字节相同。
- **raw 臂**：温度 state = 提示 + 四个数的表（与 EXP68 相同）。
- **K 臂**：在同一 state 后加 EXP70 已固定的 K 块（scripts/exp70/build.k_block）。K 只从 state 里的四个数精确计算，原来的四个数照样保留，不写谁更大，不读金标。K 仍是外部精确算出的；即使 K 臂通过，也不能说模型学会了乘法或平方。
- **归因**：K − raw 才是中间表示的对照。两臂相对 EXP68 历史端点的差别来自新的共同配方（以比较为主、两遍），只能归于整个配方。

## 预写判据（运行前冻结）

- **拟合**：训练切片六类各 ≥ 0.90，才解释该臂的泛化；否则只报告「没有拟合」，不定位泛化，也不加预算。
- **核心**（K 臂相对 raw 臂）：新诊断两个冲突类在 K 臂下各 ≥ 0.80，且 K − raw 冲突宏平均的下界 > 0（95 % 百分位区间，组合族 2,000 次配对重抽，两视图一起，seed 0，与 EXP68 / 70 相同）。
- **继续端点的必要条件**（K 臂；评审 EXP72-R1-01）：训练切片六类各 ≥ 0.90；G 的 1,800 道数值读数 all ≥ 0.98；exist / science 相对 EXP63 不低于 −0.02；新诊断两个冲突类各 ≥ 0.80；K − raw 冲突宏平均下界 > 0。raw 臂也完整报告自己的拟合、G 和保护结果，不隐藏对照的失败。
- **单独报告、不能用均值顶替失败类**：「两者相等」类、两视图都对、旧 fit。
- **分支**：
  0. 必要证据（起点保真；两臂的训练切片、新诊断、G；两臂的 exist / science）缺失 → incomplete；身份或逐题合法性不符 → invalid；都不给路线，已算出的指标照常报告；
  1. K 臂未拟合 → 不定位泛化，不追加预算；
  2. K 臂的 G 读数 < 0.98 或保护不过 → 停止，不管比较题结果如何（「比较达标但读数或保护失败」也停）；
  3. K 没有增益（下界 ≤ 0）→ 停止这个固定表示配方；
  4. K 有配对增益且两个冲突类都 ≥ 0.80 → 才准备与实时读取组合（另行许可）；
  5. K 有增益但有冲突类 < 0.80 → 部分帮助，记录哪一类不够，不追加预算。
  - **P 路径未验证，完整的旧读数门槛也未验证**：只通过 G 不等于原来的完整 reading gate 已通过；实时接入仍需另行评审。

## 预算（按 EXP65 / 68 实测：训练 0.908 步 / 秒；EXP68 训练阶段 1,200 次更新共 28.1 分钟，其中约 6 分钟是加载和在 fit 上的首末验证；decide 约 6.7 个请求 / 秒；exist / science 每臂约 5 分钟）

| 阶段（每臂） | 估计 |
|---|---|
| 训练 475 次更新（训练中的验证集改用 240 题的训练切片，而不是 1,600 题的旧 fit） | 约 8.7 分钟 + 约 2 分钟开销 |
| freeze | < 0.5 分钟 |
| decide：240 + 480 + 400 + 600 = 1,720 个请求 | 约 4.3 分钟 |
| exist / science | 约 5 分钟 |
| **每臂** | **约 20 分钟** |

- 两臂合计约 40 分钟，加起点保真、start 和报告约 2–3 分钟，**总计约 43 分钟**，在 45 分钟的目标之内。
- 余量很小，而且 K 输入更长之后的实际吞吐还没测过，不能保证一定全部完成。runner 按优先级排序：起点保真 → 两臂训练 → 必要读出（训练切片、新诊断、G）→ exist / science → 最后才是只报告的旧 fit（缺失就照实标记）。不会为了预算删掉 G 或改成子集；运行中缺了必要集合就给 incomplete，不会宣称通过。上限 45 分钟、留 120 秒报告不变；只运行一次，两臂串行，与其他模型任务错开。

## 实现（EXP72-R1-01 之后；未运行）

- **配置**：`configs/exp72-raw.yaml`、`configs/exp72-k.yaml`。参数与 configs/exp68-x.yaml 逐项相同；init 是 runs/exp68-x/stage2；data 和 val 分别是各臂的训练文件和训练切片。两份 YAML 除 name / data / val 外完全相同（check_yamls 核对）。
- **runner**（`scripts/exp72/exp72.py`、`run.sh`，硬上限 2,700 秒，留 120 秒报告）：
  - start（不加载模型）：绑定 EXP68 的运行和 X 端点、data/exp68、data/exp70、data/exp72（MANIFEST 和计划审计）、各臂的读出文件、tokenizer、EXP57 的 screens、代码；check_pairs 核对 raw / K 读出文件是同一批题和金标。
  - fid：EXP68-X 上的 48 题起点保真（与 EXP68 已登记记录比较），不通过就不训练。
  - train_raw → freeze_raw → train_k → freeze_k：沿用 devision-pipeline；freeze 核对 475 次更新，并对 EXP68-X 的实际端点做导出核对。
  - decide：两臂依次读必要集合（训练切片、新诊断、G）。
  - 两臂的 exist / science（devision-eval，记录在各臂的冻结身份下）。
  - decide_fit：最后才读只报告的旧 fit。
  - report（不加载模型）：每臂的拟合、诊断、G 读数（EXP63 的 reading_summary「all」，严格核对 1,800 道读数题、每题一次）、保护；K − raw（95 % 百分位区间，组合族 2,000 次配对重抽，seed 0）；route() 按上面的分支给结论。
- **CPU 夹具**（`scripts/exp72/test_exp72_runner.py` 8 项，加数据夹具共 11 项，全过；pyright 0 错误）：
  - 两份 YAML 改动任一参数就被拒绝；raw / K 读出文件成对相同；
  - g_reading：用 EXP65-C 已登记的 G 记录复算，得到 n = 1,800，all 与 EXP65 报告的值相同（0.99889）；比较题不进分母；少一题、多一题都被拒绝；
  - route 的边界：比较全过但 G = 0.979 → 停止；G = 0.98 → 读数项通过；保护失败 → 停止；K 臂未拟合、无增益、部分、incomplete / invalid 都有对应结论；raw 臂的 G 只报告、不阻断；
  - 报告级（假记录）：两臂记录相同 → 证据完整、增益为 0、走「无增益」分支；K 臂缺 G → incomplete；K 臂的 G 登记后被改 → invalid；K 臂保护低 0.05 → 停止；
  - run.sh stub：顺序 start → fid → 两臂训练 / freeze → decide → 两臂 exist / science → decide_fit → report；fid 失败时不训练、直接 finalize；默认 2,700 秒、留 120 秒。

## 第 2 轮修正（评审 EXP72-R2-01 / R2-02 / DESIGN-02；未运行）

- **R2-01 保护基线的身份**：

  - 现在 START 用 bound_exp63 登记 EXP63 的基线：先调用 exp65.bound_e63（EXP63 的运行文件和登记、冻结端点 3e8443e9 / 70c302c4、冻结的 exist / science 记录），再要求它等于 EXP68 START 里记录的 EXP63——EXP68 START 自己的 sha256 是固定的。

  - 夹具：在 EXP63 的逐文件链接副本里，把 exist 的摘要和明细一起换成另一份内部一致的结果（翻转一题，重算摘要的准确率）：

- **R2-02 冻结端点损坏**：每个臂的冻结核验改用 frozen_state：
  - FROZEN.json 或检查点文件不存在 → missing（证据 incomplete）；
  - 存在但截断、结构错误或 sha256 不符 → invalid（记录原因）；

- **DESIGN-02**（运行前已被接受）：K 臂必须拟合；raw 臂未拟合时，只报告它的结果，不阻断。此时只能说「同预算下中间表示的监督适配收益」，不能说排除了优化或拟合差异后的纯泛化收益，也不能据此说 raw 路线普遍做不到。K 臂自己未拟合仍然停止，其他门槛不放宽。
