# exp39 方案：低内存的 512 原图迁移（H 臂重跑；实现与 CPU 夹具已写，待评审，未运行模型）

日期：2026-10-17。依据：评论家 EXP38-MEM-03、EXP39-PREP-01。

exp38 的 H 臂（512 输入、batch 16）在这台 24 GB 机器上用了约 19.6 GB 的 MPS 驱动内存。与其他应用并存时持续换页，第 350 / 400 步的窗口是每步 27 秒，最终在第 400 步左右按评论家裁决做了有界中断，exp38 记为 incomplete（资源 / 预算原因，不是数值或科学门槛的失败）。C 臂（256）随后单独补救运行（`scripts/exp38/rescue_c.sh`）。

这一份方案只为把 512 的原图迁移在可控内存下重新检验一次：设置与 exp38-H 相同，只改物理执行方式。

## 设置（与 exp38-H 只差执行分块）

- **相同**：起点 exp37-L（sha256 `f9fc93c2…`），用 `scripts/exp38/convert.py` 以 512 读取（只改 config）；数据 exp36 原图 16k（`912a9cd2…`），顺序和 seed 0 相同；全数字遮罩；1,000 个有效更新，有效 batch 16；学习率、LoRA、warmup、44 token、冻结方式都不变。
- **只改**：`micro_batch: 8`。每个有效批的 16 行照常抽取、遮罩、改写数字，然后分两个 8 行的部分前向和反向：
  - 每部分的损失 = 该部分被遮 token 的交叉熵**总和** ÷ 整批 16 行的被遮 token 数，所以两部分的梯度相加，正好等于整批的均值梯度；
  - 每个有效批只做一次 zero_grad、一次 clip、一次 optimizer、一次 scheduler；日志、warmup、eval_every 和 1,000 步都按有效更新计；
  - 每部分在任何更新之前检查有限性，非有限就报错退出，部分梯度不会被用于更新，也不保存 checkpoint；
  - 不保留两部分的计算图。
- **验证**：`align._evaluate` 仍按原来 16 行一批生成说明文字选择、随机遮罩和批内轮转的换图，只把前向切成 8 行，所以题序、换图 id 和分母都不变。
- **数值读出**（`scripts/exp36/readout.py`）：同样先按 16 行生成，再切 8 行前向（这一项要等 C 补救的读出跑完后才改，以免影响正在运行的、已审的读出代码），题单和固定换图映射不变。
- 不和决策监督组合（代码里直接拒绝）。

## 实现与 CPU 验证（df1fb71）

- `src/devision/train/align.py`：`AlignConfig.micro_batch`（默认 0，旧路径完全不变）、`_micro_step`、`_logits_in_parts`。
- `tests/train/test_align_micro.py`（tiny 模型，CPU）：
  1. 整批 16 对 8 × 2（tiny 上是 4 对 2 × 2，同样的随机抽取、遮罩和数字改写；各部分被遮 token 数不等）：每步损失、步数、每次 val 的指标都在 1e-5 内相同，最终权重 allclose（1e-5）；
  2. 第二部分注入 NaN：在更新前报错，不留 model.safetensors；
  3. micro_batch 不能整除 batch、或与决策监督组合时，拒绝。
- 全部测试 223 passed，pyright 0 错误。
- "有效 batch 相同"本身不证明更快；等价只说明差别仅在执行分块和浮点误差。

## 资源检查点与失败退出（运行前写定）

- 物理 batch 8 时，激活内存约为原来的一半。原 H 在第 0–250 步稳定在约 17.6–18.6 GB 的 MPS 驱动内存，换页开始前每步约 6.5 秒；8 × 2 的每步时间预计与之相近或略慢（同样的计算量分两次做）。
- **首窗口检查**：第 50 步时读 SwanLab 的 `perf/step_s` 和 `sys/torch_mps_gb`。如果 step_s > 9 秒，或 MPS 驱动内存 > 16 GB 且系统可用内存 < 2 GB，就按 guard 有界结束，记为资源中断，不自动重试，交评论家裁决。
- 之后每个窗口都检查；连续两个窗口 > 12 秒 / 步时同样结束。
- 运行前确认没有其他模型进程。是否关闭其他应用由负责人决定，我不会自行关闭。

## 读出与门槛

与 exp38 相同（`scripts/exp38/report.py`）：在原 600 tune 上比较 H − C，按族配对，用 exp38 的四个投入条件。C 就用 C 补救的结果，前提是它的身份核对通过：256 / 64 / 不插值，同一份 exp37-L、同一数据和步数。H 的身份必须是 512 / 256 / 插值，并且 `micro_batch` 写进报告。
