# exp55 方案：只给事实表加千位分隔符的冻结文字接口对照（CPU 准备完成，未运行，等评论家的模型许可）

日期：2026-10-18。依据：评论家 EXP55-PREP-01–03（EXP54-RESULT 验收之后）。

## 问题

EXP54 中 G 没有过线，失败集中在速度字段：选项是 "1,360 m/s"，表里写的是 "1360"。本轮只改这一处写法，用来区分"数值本身难"和"输入与候选格式不一致造成的、可修复的损失"。EXP54 的结果不改、不重跑。

## 只改一个变量

- **不可变来源**：EXP54 已登记的四份输入（START `1098e403…`，registry 中 inputs 和 4 份 details 的 sha 都要核对）。
- **格式函数**（`scripts/exp55/exp55.py` 的 `fmt`）：
  - 只接收数值字符串：整数部分从右往左每三位插一个逗号，小数部分逐字保留，`unreadable` 不变（1360 → 1,360；14、0.75 不变）；
  - 不符合严格数字格式（`^[0-9]+(\.[0-9]+)?$`）的值直接拒绝；
  - 去掉新增的逗号必须逐字还原，不经 float，不取整，不补单位，不修正预测；
  - 不接收候选、gold、题目、字段、qid 或场景。
- **P / G / D**：每个值独立格式化，再用 EXP54 的 `serialise` 重建 state（先核 EXP54 的 state 等于 `serialise(state_text, 旧表)`）。
- **E**：与 EXP54 逐字节相同（start 核 sha）。
- **其余全部沿用 EXP54**：EXP50-T（加载前核实际 sha）、EXP53 的读数、600 张原图和题目 / 选项 / gold / state 原文、行顺序、单位策略、每图一个请求、image = None、raw 温度 1。
- 共 2,400 次请求、9,600 题次，没有视觉前向，也没有训练。
- **输入变化**（无模型构造）：

| 条件 | 改变的请求 | 改变的数值 |
|---|---|---|
| P | 224 / 600 | 386 |
| G | 229 / 600 | 389（等于金标带逗号的 389 道速度题） |
| D | 224 / 600 | 386 |
| E | 0 | 0 |

- **截断检查**（EXP50-T 的本地 tokenizer 和序列预算，不加载权重）：四个条件的新旧输入都没有 state token 被丢弃，选项全部可区分；新 state 最多 93 个 token（旧的最多 92）。start 阶段会重做这项检查，若出现截断就拒绝运行。

## 判据（EXP54 的门槛完全不变）

- **门槛**：G / P 门槛和两项因果门槛照用 EXP54 的。
  - P 读对子集仍是 EXP53 冻结的 1,470 题（从 EXP54 的 P 输入计算），门槛仍为 0.90；
  - 供体覆盖 / 跟随仍从实际 D 值计算，比较前去掉分隔符，unreadable 留在原分母中。
- **主要格式对比**（预写）：G 速度 600 题"新 − 旧"的准确率配对差及 case 簇区间；下界 > 0 时支持这次格式改变带来收益。
  - 另报：金标带逗号的 389 题 / 不带逗号的 211 题；请求实际改变 / 未改变的切片；P 速度、G / P 全量变化；错 → 对、对 → 错；NLL。
  - 这些分层只用于解释。
- **复现对照**：E 的全部请求，以及其他条件中输入逐字未变的请求，同题预测必须相同、概率最大差 ≤ 1e-5。不满足时标"对照未复现"，不做单变量格式归因，不自动重试。
- **分支**：
  - G / P 和两项因果门槛全部通过，才进入自动读取与普通推理的整合准备；
  - 格式效应阳性但门槛没全过，只说明修复了一部分损失；
  - 其余按 EXP54 的分支。
- **比较题**：600 道只分层报告，包括温度题 A / B / neither 的预测分布。
- 缺主条件或身份错误记 incomplete / invalid。

## 实施与预算

- **阶段**（`scripts/exp55/run.sh`）：
  1. **start**（无模型）：核 EXP54 绑定、实际权重、题单；构造并登记新输入；截断检查；START 在任何前向之前写好，记录 HEAD、9 个文件的 sha、EXP54 的源 sha、变化计数和截断统计。
  2. **decide**：复用 EXP54 已审查的 stage_decide（加载前核权重，P → G → E → D，逐条件登记），在 exp53 的 watch 下运行。
  3. **report**：新明细和配对的 EXP54 明细都核身份；失败或到限时 finalize，报告失败时链非零退出。
- **预算**：EXP54 实测 decide 约 7 分钟（6.16 个请求 / 秒），总计 7 分 11 秒，所以本轮估计约 8–12 分钟。硬上限 20 分钟，最后 90 秒留给报告；watch 截止比外层早 35 秒，宽限 10 秒。
- fresh only，只跑一次，不自动改模板、不重试、不接训练。

## CPU 验证（`scripts/exp55/test_exp55.py`，8 项通过；pyright 0 错误）

- 格式函数：千位、小数、unreadable、拒绝已带逗号 / 非数字 / 空 / 负号 / 多个点 / 科学计数法，并能还原。
- 只有表值改变：E 与 EXP54 相同；P / G / D 去掉逗号后逐字等于旧值，行名不变，state 去掉逗号后等于旧 state，孪生不变。
- gold 和选项改变时，格式化后的输入不变。
- 报告口径：去掉分隔符后供体计数复现 828 / 131 / 24 / 702（不去分隔符会少算在候选内的数量）。
- 配对：题集不同时拒绝；未改变的请求有概率变化时判未复现；转移计数。
- 未复现时不做格式归因（final_branch）；EXP54 文件缺失或改动时拒绝。
- 短链：真实 watch，假 decide 带忽略 TERM 的子进程；在截止时停止并 finalize，没有残留。
