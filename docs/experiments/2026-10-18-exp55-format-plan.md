## 只改一个变量

- **不可变来源**：EXP54 已登记的四份输入（START `1098e403…`，registry 中 inputs 和 4 份 details 的 sha 都要核对）。
- **格式函数**（`scripts/exp55/exp55.py` 的 `fmt`）：
  - 只接收数值字符串：整数部分从右往左每三位插一个逗号，小数部分逐字保留，`unreadable` 不变（1360 → 1,360；14、0.75 不变）；
  - 不符合严格数字格式（`^[0-9]+(\.[0-9]+)?$`）的值直接拒绝；
  - 去掉新增的逗号必须逐字还原，不经 float，不取整，不补单位，不修正预测；
  - 不接收候选、gold、题目、字段、qid 或场景。
- **P / G / D**：每个值独立格式化，再用 EXP54 的 `serialise` 重建 state（先核 EXP54 的 state 等于 `serialise(state_text, 旧表)`）。
- **E**：与 EXP54 逐字节相同（start 核 sha）。
- **其余全部沿用 EXP54**：EXP50-T（加载前核实际 sha）、EXP53 的读数、600 张原图和题目 / 选项 / gold / state 原文、行顺序、单位策略、每图一个请求、image = None、raw 温度 1。
- 共 2,400 次请求、9,600 题次，没有视觉前向，也没有训练。

| G | 229 / 600 | 389（等于金标带逗号的 389 道速度题） |

- **截断检查**（EXP50-T 的本地 tokenizer 和序列预算，不加载权重）：四个条件的新旧输入都没有 state token 被丢弃，选项全部可区分；新 state 最多 93 个 token（旧的最多 92）。start 阶段会重做这项检查，若出现截断就拒绝运行。

## 实施与预算

- **阶段**（`scripts/exp55/run.sh`）：
  1. **start**（无模型）：核 EXP54 绑定、实际权重、题单；构造并登记新输入；截断检查；START 在任何前向之前写好，记录 HEAD、9 个文件的 sha、EXP54 的源 sha、变化计数和截断统计。

  3. **report**：新明细和配对的 EXP54 明细都核身份；失败或到限时 finalize，报告失败时链非零退出。
