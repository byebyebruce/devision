# 第 15 轮 r15-vision：r14b 数据 + 解冻 SigLIP 最上面 4 层，训满一轮（方案，待评审）

日期：2026-10-14。负责人在 exp19 之后选第 1 条（"1"）。轮次名是暂定的，可由负责人改。按负责人此前的做法，方案和代码先交评审，评审没有问题再训练。采用规则在训练前写下，结果出来后不改。

## 为什么

- exp19（2,000 步）判为不确定：目标面板准确率 +0.55 [−0.71, +1.89]，没有明确伤害到其他面板；只报告的 8 个面板 NLL 等权平均 −0.016 [−0.027, −0.004]。
- 短程看不出准确率的变化，可能是训练还不够长。这一轮同时带着三样东西：r14 的计数提升、r14b 的左右镜像对和 VSR、解冻的视觉塔。这是现有组合里最可能产出 v0.3 候选的一个。
- 这一轮要回答的是"整套配方训满后能不能过采用规则"，**不单独**回答"解冻本身贡献了多少"：没有同样训满、视觉冻结的 r14b 对照（r14b-mirror 在种子 0 第 2,000 步就止损了）。

## 配方

- 数据：`data/r14b/train.jsonl`（81,875 题，sha256 `ef8a25ed…`），与 r14b-mirror、exp16-r14b-s1、exp19 相同。
- 从 v12 起步，SigLIP2 第 8–11 层和 `post_layernorm` 以 5e-6 训练；其余学习率 2e-5 / 1e-5 / 5e-5，warmup 300，余弦日程 10,235 步，micro batch 8，MPS FP32，**种子 1**。
- `configs/r15-vision.yaml` 的 `stages` 与 `configs/exp19-vision.yaml` 逐字相同（已 diff），只多了 `evaluate`。`evaluate` 与 r14b-mirror 相同：27 个集合，含四个 `bench_lv_*` 和对照组，另加 `lv_report`。
- **从 exp19 第 2,000 步接着训**：`scripts/r15/chain.sh` 第一次运行时，把 `runs/exp19-vision/stage2/` 的 `resume.pt`（第 2,000 步的训练状态：权重、优化器、日程、批序、随机数状态）和 `monitor/step0`、`monitor/step2000` 复制到 `runs/r15-vision/stage2/`，并在 `seeded_from.json` 记下来源和 `resume.pt` 的 sha256。
  - 续训时会核对 `_RESUME_KEYS`（含种子、学习率、解冻层数、蒸馏项）和题数，任何一项不同就拒绝运行。
  - 已有测试证明，中断后续训与一次训完的结果相同（`test_resume.py`、`test_vision_unfreeze.py`）。
  - 好处是省掉约 85 分钟的重复训练。代价是本轮前 2,000 步的 SwanLab 曲线留在 exp19 的 run 里，本轮的 run 从第 2,000 步开始。
- CPU 推理：结构、视觉 token 数和分辨率都不变，预计基本不变（未测）。

## 训练中的止损

沿用 r14b 冻结的止损规则（`scripts/r14b/rules.json`，11 条），每 2,000 步对第 0 步（即 v12）判定一次，触发就结束本轮，不重试、不放宽。

已知限制：exp16 显示，这些规则在第 2,000 步的判定会随训练轨迹变化。第 2,000 步已有记录（exp19），用同一规则只读复算过，**不触发**：存在性召回 −1.9 [−3.5, −0.6]，扩展宏平均 −1.1，其余更小或为正。

## 采用规则（训练前写下）

与 r14 / exp17 相同，比较对象 v12，按题配对、按图片重采样（`scripts/r14/accept.py --cand runs/r15-vision/eval`）：

1. **主要条件**：`test_count_fresh` 或 `bench_countbench` 准确率提高，且差值下界 > 0。
2. **旧能力保护**：所有 `test_*`、`bench_pope`、四个 `bench_lv_*` 的差值下界 > −2 个百分点；"已证明退化"（上界 < 0）单独报告。
3. **概率质量警戒**：任一集合校准后 NLL 升高 > 0.02 且下界 > 0。

1、2 满足且 3 未触发，即作为 v0.3 候选交负责人决定；否则保留 v12。

只报告、不作为条件的比较：
- r15 − r14、r15 − exp17 α = 0.5（`accept.py --base ... --out compare/vs_<名>.json`，不会覆盖正式结果）；
- 与 laya-vision 的详细比较（`lv_report.py`）；
- 开发面板末步判定（`judge.py --rules scripts/r14b/rules.json final`）。

**关于测试集的适应性使用**：这些测试集已经多轮用来判断训练方向，本轮结果要如实披露这一点，不称为全新的独立验证。

## 实施

- `scripts/r15/chain.sh`：在 r14b 的链基础上加了三件事：首次运行时从 exp19 播种；流水线（训练 + 全量评测）成功后跑正式采用判定和两个只报告比较；以采用判定的退出码结束。止损或连续 3 次失败时，不做全量评测，退出 1。
- `scripts/r14/accept.py` 加 `--out`：不传时行为不变，r14 的测试 13 项通过。
- 训练代码没有新改动，用的是 exp19 已验收的版本。
