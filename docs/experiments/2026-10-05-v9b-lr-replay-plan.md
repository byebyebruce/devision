## 一、为什么还值得验证一次

**1. 纯专项训练的收益很大，而且是看图得来的。**
- R 在留出镜像集上：位置题同时对 0.233 → 0.684，+45.2 [+40.8, +49.5]；看图收益 +21.7 [+16.0, +27.7]；相对位置选择 +29.6 [+25.6, +33.8]（`runs/r9/R/eval/compare/`）。
- 这是第 6 轮以来，左右题第一次在留出图上明显学会。

**2. S-mix 为什么没保住，还没定位。** 已知的只有这些：
- 按"已看到的左右题次"对齐，混合训练在同样曝光量下学得少：约 2,400 题次时，R 的 dev 准确率 0.704，S-mix B 0.624。S-mix 的题次是按混合比例估算的，没有复原每个 batch 的真实累计。
- S-mix 与 R 同时有几处不同：
  - 左右题构成：S-mix 里相对位置选择题占 1/3，R 只占 2%；
  - 有没有回放；
  - 总步数，以及随总步数的学习率余弦退火、RLCD 的 σ 退火；
  - 样本本身。
- 现有结果不能把失败归到其中任何一个，本方案也不做机制归因。

**3. 所以先回答一个具体的问题。** X1 回答：R 这份原题，额外加上回放之后，收益还在不在、旧能力掉多少。只有这个配方过了门槛，才值得投入约 1 小时 45 分的正式评测。

**4. 还不知道 R 本身让旧能力掉了多少。** R 从没在 `dev_mix` 上评过。0d 只做评测，约 10 分钟，结果决定 X1 加多少回放，或者直接停止。

## 二、第 0d 步：R 在 `dev_mix` 上评一次（只评测，已开始）

**口径（看结果前写死）**：
- **旧能力切片**：`data/v5/dev_mix.jsonl` 去掉 `source ∈ {coco-position, coco-relation}` 且 `axis = lr` 的 400 题，剩 4,778 题。上下题（这两个来源中 `axis = tb` 的 246 题）保留在切片里。
- **配对方式**：R 与 v8 用相同题号配对（v8 用 `runs/v8-vsr-v7w/eval/dev_mix.details.jsonl`），按原图重采样，给差值 Δ（R − v8）的 95% 区间。
- **另外报告**：全部 5,178 题的总体、400 道左右题、按来源的分项。
- 这个切片只去掉了直接训练的专项任务，其他来源里仍可能有空间问题，不宣称它与左右能力完全无关。
- **来源显著退化**：切片内某个来源的 Δ 区间上界 < 0，且点估计 ≤ −3 个点。ScienceQA（173 题）、TQA（167 题）等小来源检验力有限，只能抓到大的退化；没有显著退化，不等于证明没掉。
- **近重复**：R 有 5 张训练照片与 A-OKVQA dev 的图相同（`runs/r9/dhash_audit.json`）。0d 另附去掉这些题后的 aokvqa 敏感性结果，不称严格独立。

**分支（按顺序判断，先满足的为准）**：
1. **丙（停止）**：切片 Δ 的点估计 < −3 → 本轮不继续左右这条线，第 9 轮改走其他数据，另写方案。这只是预算上的停止条件，不证明加回放也保不住旧能力。
2. **乙**：切片 Δ 的点估计在 [−3, −1)，或有来源显著退化 → X1 用回放 2,500 题。
3. **甲**：其余情况 → X1 用回放 1,250 题。

## 三、X1：R 的原题 + 回放（筛选，只做一次）

- **左右题**：R 的原题。`data/v9/r_pairs.jsonl`（SHA256 `6c6b596c…26fee`）由 `real_lr.py` 的规则与 seed 9 还原：2,500 题，其中位置 2,442、相对位置选择 24、相对位置是非 34。
  - 用 `v9_mix.py --pairs-file` 构建。按现行隔离规则，那 5 张近重复照片上的 12 题整对去掉（不补），剩 2,488 题，与 R 的差别就是这 12 题，题号列在 MIX.json 的 `dropped_ids` 里。
  - 不为此重训 R。
- **回放**：甲 1,250 题、乙 2,500 题，按已通过方案第四节的配额表缩放（含 VSR / ScienceQA / Visual7W），dHash 近重复已剔除。
  - 甲：`data/v9/x1_r1250/`，3,738 题；乙：`data/v9/x1_r2500/`，4,988 题。两份都已构建，与留出图交集为 0。
- **训练**：从 v8 出发，2 个 epoch（同 R），学习率 new / head 5e-5、LoRA 1e-4，warmup 50，micro batch 8；甲 936 步，乙 1,248 步。
  - 余弦学习率和 RLCD 的 σ 都按本次的总步数退火，配置写在 YAML 和 `run.json` 里，可以追溯。
- **评测**：`val` 用 `dev_lr_pairs`，与 R、S-mix 一致，方便同口径比较；训练结束后再评 `dev_mix`。只用末步的 checkpoint。
- **YAML**：`configs/r9-x1.yaml`（name `r9-x1`）。

**X1 的门槛（看结果前写死）**，都与 v8 比，在同一 `dev_lr_pairs` 和同一个 4,778 题切片上：

| 条件 | 要求 |
|---|---|
| 位置保住收益（主要目标） | 同时对率 Δ ≥ +22.05 个点（R 的 +44.1 的一半），且区间下界 > 0 |
| 旧能力 | 切片 Δ 的点估计 ≥ −1 个点 |
| 来源警戒 | 切片内没有来源显著退化（定义同 0d） |
| 相对位置选择、是非 | 只报告，不作条件（dev 上只有 92 / 66 对） |

- **三条都满足** → 进入正式轮次 v9b（第四节）。
- **任一条不满足** → 停止左右这条线，不重试、不追加组合，记为"R 原题加回放未保住"，第 9 轮改走其他数据。
- **X2**（2:1 构成）本方案不做：X1 过了，就用 R 的构成；X1 没过，就停止。X2 留作以后研究构成时的选项。
