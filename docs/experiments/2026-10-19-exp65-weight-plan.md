# EXP65 方案：同预算普通追加 CE（C）对照规则分类加权 CE（W）（EXP65-PREP-01；CPU 准备，未运行）

日期：2026-10-19。依据 EXP63 终点裁决（EXP63-RESULT-01 / 02）：

- EXP63 的 fit 温度 0.940 < 0.95，原结局「fit not learned」不改。
- fit 的 12 个、G 的 18 个温度比较错误，四道读数都答对。
- 「质量 / 速度反向、质量较大者胜」这一类在训练里只有 52 / 1,200 条比较题，fit 2 / 8、G 7 / 16。
- 本实验要区分：普通的额外曝光是否就够，还是冲突规则的相对监督强度另有收益。candidate_eligible 恒为 false。

## 两臂（唯一的差别是逐题 CE 权重）

- **相同的部分**：
  - 都从 EXP63 的冻结端点（3e8443e9 / 70c302c4）独立出发，各新建 LoRA r16 和决策头；视觉、读取等冻结部分不变；
  - EXP63 的配方：lr_lora 5e-5、lr_head 1e-5、warmup 100、seed 1、micro / eval batch 8、text_only CE；
  - 同一份 data/facts/train.jsonl 和真实批计划：1,200 次更新，每题一次，两视图单元不拆；固定末步；
  - 不是 resume EXP63，不改任何已有产物。
- **C**：权重全为 1，就是原来的代码路径（不给权重文件）。
- **W**：`question_weight_file = data/exp65/weights.jsonl`。
  - 温度比较题按六类加权 w = 200 / n_class（n 只在 train 上统计），其他题都是 1；
  - 温度比较总权重 1,200，全体 9,600，与 C 相同；
  - loss = Σ wᵢ·CEᵢ / 批内题数（不用 Σw 作分母）；
  - RLCD 噪声照常抽取，所以两臂的随机数路径相同；权重只影响训练，验证、decide、拟温都不变。
- **实现**：rlcd 增加 `TrainConfig.question_weight_file`，默认为空，原路径不变。
  - 文件必须给每道训练题恰好一个有限正权重，不能有多余的 key，只能和 objective ce 一起用；
  - 已写入续跑键；
  - 推理、序列构造、Reading、EXP64 的绑定文件都没改；实现放在隔离 worktree `devision-exp65`（分支 exp65-prep）。

## 新的规则诊断（`data/exp65/diag.jsonl`，SHA 243ab53d…，现在冻结）

- **规模**：六类各 40 个规范 case（seed 65），每个 case 问两次（A / B 交换），共 480 个请求，每个请求一题。「两者相等」的两次用同一张表，选项各按自己 id 的固定 hash 排序，两次的顺序可能相同（不重建数据）。
- **数值**：取自训练集自己的取值（43 个质量值、174 个速度值）。排除了 data/real_layout 全部 split、data/cmp、data/facts 里已有的 4,036 个规范 case。不按 EXP63 的错题选例。
- **文本**：EXP63 G 条件的接口，即共用的温度 state 文字 + 金标数值表（serialise / fmt，行序与 G 相同）、生成器的题目和选项。选项按 sha256(id) 换序；标签按生成器规则；不加计算结果或提示。
- **金标分布**：A 200、B 200、相等 80。
- **用途**：按 EXP63 错误设计的开发诊断，不参与训练，不用来挑 checkpoint，也不是确认集。统计时同一 case 的两次放在同一个簇里。

## 读出与判据（逐臂；不改写 EXP63 的结局）

- **原门槛逐臂照用 EXP63**：fit / G / P / 1,800 道读数 / 两项保护。G / P 的收益对 EXP57 起点的登记记录计算（EXP63 里登记的 start_fit / G / P，经 read_set 核对），不换成更容易的基线。
- **另报**：
  - 相对 EXP63 端点的增减（比较题按 case 簇配对）；
  - exist / science 相对 EXP63（容差 −0.02，避免阶段间累积下降）；
  - 诊断六类准确率；W − C。
- **实用条件**（每臂）：
  - 原 EXP63 各门槛全过；
  - 诊断六类准确率都 ≥ 0.80；
  - 两项保护相对 EXP63 不低于 −0.02。
- **加权归因**：诊断冲突两类等权宏平均的 W − C，按 case 簇区间下界 > 0。
- **决策**（预写）：
  - 两臂都满足：有归因才选 W，否则选 C（不归功于加权）；
  - 只有 C 满足：选 C；
  - 只有 W 满足：有归因才选 W，否则不走；
  - 都不满足：停止这一轮预算，不加 epoch，不扫权重。
- **起点诊断是路线判定的前提**（评审 EXP65-R1-01）：EXP63 端点的诊断必须唯一完整、已登记、身份对得上，报告里记为 completed。
  - 缺失：判定给 incomplete；没登记、登记后被改、身份不符：给 invalid；两种都不做路线判定。
  - 各臂的指标、配对差和 W − C 照常报告。
- **读出范围**：EXP63 端点只读诊断（它的 fit / G / P 已登记）；两臂读 fit / G / P / 诊断；不新增 H。
