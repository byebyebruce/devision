# exp130：v0.4 → exp129 权重插值，修 POPE / 是非题而保住新用途（预写，2026-10-28 22:05，exp129 训练收尾、未评）

**背景**：r22、exp125–exp128 换种子 / 换混合后，POPE 对 v0.4 一直在 −0.3 到 −1.0（r22 −0.34、exp125 −0.78、exp126 −0.98、exp128 −0.76 显著），exp127 还出现 test_vqa_yesno −2.8；数据侧已加对抗共现负例的 coco-exist 回放（exp124、exp129），新用途收益则是 +25 到 +47 的量级。微调把旧能力拉偏而新能力远超门槛时，WiSE-FT 式的权重插值通常能用少量新收益换回旧能力。exp17（v12-ext ↔ r14）和 v04-interp（v0.3 ↔ r20）做过插值，前者未过面板规则、后者被 r21-soft 取代，都不是 v0.4 → v0.5 这对模型，不算原样重复。

**做法**（`scripts/v05/chain_exp130.sh`，在 exp129 链退出后自动跑）：
- θ(α) = θ_v0.4 + α·(θ_exp129 − θ_v0.4)，α ∈ {0.9, 0.75, 0.6}（`scripts/exp17/interp.py`；两边 420 个张量同名同形），温度在 exp129 的同一 val（`data/v05/exp81/calib.jsonl`）上重拟合。
- 选 α 只看开发集（`scripts/v05/exp130_select.py`）：新用途 gui_dev_state、gui_shop_dev_state、gui_dev、ego_dev 各自保留 exp129 相对 v0.4 收益的 ≥ 85%，且 dev_coco_exist + dev_vqa_yesno 准确率合计比 exp129 高 ≥ 0.5pp；取满足的最小 α。都不满足就停，不看测试集。
- 选中的 α 用 exp129 的 32 个集合 + controls 全量评测一次（`configs/exp130-interp.yaml` 由脚本生成，`history` 写入 exp129 训练中监测的 7 个集合），再跑 lv_report，结果在 `runs/exp130-interp/a<α>/`。测试结果出来后不换 α。

**对照**：v0.4（r21-soft，正式门槛）、exp129（α = 1，同一训练）。

**判据**（`devision-compare` 按图 95%）：
1. 对 v0.4：exp129 的判据 1、2 同样成立（三个新用途显著提升，其余旧集合与外部 bench 无显著退步，含 POPE、test_vqa_yesno、test_size）。
2. 对 exp129：POPE 与 test_vqa_yesno 点估计 ≥ 0；新用途 test_gui_state / test_gui_shop_state / test_ego 的下降不显著或不超过 exp129 对 v0.4 收益的 15%。
3. 校准：32 集 ECE 中位数不高于 exp129。
- 1–3 都过 → r23 = exp129 配方训练 + 同 α 插值（插值写成 r23 的后处理步骤，α 固定不再选）。
- 1 不过、2 过 → 插值方向对但不够，记录 α 曲线，下一步考虑更小 α 或换种子。
- exp129 本身已过全部判据时，exp130 仍跑完，用于判断 r23 是否加插值。

**预算**：开发集 5 个模型 × 6 集约 30 分钟，全量评测约 90 分钟；exp129 约 23:45 评完后启动，约次日 02:00 完成。
