# exp54 方案：冻结的自动读数 → 普通决策，零训练的文字接口诊断（CPU 准备完成，未运行，等评论家的模型许可）

## 问题

EXP51 / 53 已证明自动读出的数值可用，EXP52 共同训练的新头没有学会读数。本轮只回答一个问题：把**已经读出**的数值交给现有的普通选项评分，它能不能可靠地用上？不训练任何东西，不引入新表示。

## 固定对象

- **决策**：EXP50-T 的普通决策权重（`1a8e5439…` / `99c6246e…`，start 阶段做冻结核对），通过 `Decider.decide(state=文字, questions=原题, image=None)` 调用。温度只在内存里设为 1（与 devision-eval `--no-temperature` 相同），不改磁盘上的 config。
- **读数**：复用 EXP53 登记的 `runs/exp53/details_auto.jsonl`（`2b8544f4…`，path = auto，START `c640dd9a…`），即冻结的选择器（`8f10f1fd…`）加 EXP51 的头（`0b548142…`）的自动读数。这是组件组合诊断，不是实时全链，也不是部署速度证明；不改变普通全评不加跨集合缓存的约定。
- **题目**：原图 rl_tune 的 600 行（`84117b36…`）。1,800 道读数题是主判据，600 道比较题只分层报告。原题、选项和顺序都不变，不新增题目，也不做人工计算答案。

## 事实表与四个条件（`scripts/exp54/exp54.py`）

- **每张图一份表**：接在原 state_text 后面，同图的各题共享。
  - 行由该图读数题的**问题文本**经 6 个固定模板映射得到：两个样本的质量和速度、两组磁铁的距离。行顺序固定，不认识的文本直接拒绝。
  - 数值不带单位（"14"、"1360"、"0.75"），单位留在原 state、问题和选项里。
  - 格式：`Values read from the picture (numbers only; units as in the question):` 后面每行一条，例如 `Sample A: mass of each particle = 14`。
- **四个条件只改表里的值**：
  - **P**：EXP53 的自动读数，严格解码；不合法的写 `unreadable`，不挑选、不修补、不回退到 oracle 或候选项。构造函数 `p_table` 只接收读数题的文本和自动预测，不接收 gold、框、family / case 或选项。
  - **D**：同一族另一视图（固定孪生图）的整份 P 表；本题的问题、候选和 gold 不变。主要的供体统计只看值改变的题。
  - **E**：同样的行，所有值都是 `unreadable`。
  - **G**：同样的模板填入金标数字（独立的 `g_table`，独立的 oracle 阳性对照）。只给数值，不给正确选项，也不说"答案是"。
- **核对**：在真实数据上无模型构造，P 读对 1,470 / 1,800 题（与 EXP53 的自动读数一致），表中有 127 个值是 `unreadable`。
- **范围**：只覆盖这 6 种读取模板，没有解决任意问题的分解。磁力大小、方向等非数值信息没有进入表，比较题按 kind / axis 分层报告，阴性不能全部归因于"数值没用上"。

## 预写判据（`report`）

- **统计**：exp42 的口径（case 连通簇，seed 0，2,000 次重抽）：
  - 全部读数题的字段宏平均（all）、值改变题（changed）、异值单题（different）、异值两对象（both）、值改变孪生（twin）、A / B 同答（same_answer）、NLL；
  - 按 P 读对 / 读错分层的决策准确率；
  - 供体跟随：D 的答案是否是带有孪生值的选项，以及孪生值是否在当前候选里；字符串比较只用于这一项报告，不进入主分；
  - 比较题按 kind / axis 报告。
- **概率核对**：概率必须来自实际 decide，有限且归一，按选项文字对齐；逐题核全集、无重复、选项顺序和 gold。
- **门槛**：
  1. **G 文字使用有效**：all ≥ 0.90，两对象 ≥ 0.80，孪生 ≥ 0.80。不满足时只说明当前下游 / 序列化接口没有成立，不否定 EXP53。
  2. **P 使用过线**：all ≥ 0.70，各字段 ≥ 0.50，两对象 ≥ 0.50，孪生 ≥ 0.50，P 读对的题中决策准确率 ≥ 0.90。
  3. **因果对照**：P − E 两对象 ≥ 0.10 且下界 > 0；值改变题上 P − D 单题宏平均 ≥ 0.20 且下界 > 0。
  4. 缺主条件、身份错误或概率错误记 incomplete / invalid，不用 G 补 P。
- **分支**：
  - G 和 P 都通过且依赖内容：下一步做普通推理内的自动读取整合，再做比较、迁移和保护筛查；
  - G 通过、P 没通过：按"读对却选错"和"读错"分层，决定是做接口适配还是读取泛化；
  - G 没通过：先查文字消费；
  - 不按本轮结果换 checkpoint、模板、补单位或重跑。比较题的结果不作为本次读数接口的事后否决项。

## 实施、身份与预算

- **阶段**（`scripts/exp54/run.sh`）：
  1. **start**（无模型）：
     - EXP50-T 冻结核对；
     - EXP53 START 和 registry 中的自动明细（sha 加上 identity 的 path / START）；
     - 题单和 rl_tune 是 EXP53 绑定的那两份；
     - 写出四个条件的实际输入 inputs_<C>.jsonl（含 state 全文和表）并登记，START.json 记录 HEAD、文件 sha、模型、raw 温度、image = None、分组上限。
  2. **decide**（MPS）：在 exp53 的 watch 下按 P → G → E → D 的顺序运行，每张图每个条件一个请求。每个条件完成后立即写出明细并登记，失败时保留已完成的条件。
  3. **report**（无模型）：失败或到限时用 --finalize。报告失败时链返回非零。
- **请求数**：600 张图 × 4 个条件 = 2,400 次 decide 请求，每次 3 或 5 题（≤ 8），共 9,600 题次，都不带图片。
- **时间（估计，不跑真实模型冒烟）**：
  - 依据：EXP48-X 在 rl_tune 上每请求 P50 224 ms，其中含一张图的编码；不带图时，按每请求约 0.2–0.25 秒算（表多了约 40 个 token）。
  - 2,400 × 0.2–0.25 秒 ≈ 8–10 分钟，加上加载约 0.5 分钟、start 约 0.5 分钟、报告约 1 分钟，**合计约 10–12 分钟**。
  - 硬上限 30 分钟，最后 90 秒留给报告；watch 的截止比外层早 35 秒，宽限 10 秒。
  - P 最先完成，所以最早得到完整的原图主读出。
- **资源**：只有文字，没有视觉特征；模型约 2 GB；输入和明细各几 MB。

## CPU 验证（`scripts/exp54/test_exp54.py`，8 项通过；pyright 0 错误）

- P 不读 gold：改动全部 gold 数字、gold 选项和选项顺序后，P / D / E 的表和 state 不变，只有 G 改变；不合法的读数仍为 unreadable。
- D 是孪生图的 P 表；孪生在另一族的图上时拒绝；不认识的问题模板拒绝，行顺序固定。
- 普通 decide（tiny 模型，image = None，raw 温度）：每题概率有限、归一，对应原选项。
- 明细拒绝：漏题、重题、伪造概率（和不为 1）、另一条件的 identity、选项顺序改变（以上都重新登记，以检验内容核对）；登记后被改动。
- 门槛和分支：G / P 都过且依赖内容时继续；G 未过；P 缺失时 incomplete；P 读对子集低于 0.90 时为"G 过、P 未过"。
- 没有明细时 finalize：四个条件都是 missing，分支为 incomplete。
- 短链（真实 watch，假 decide 带一个忽略 TERM 的子进程，EXP54_LIMIT 60 秒）：watch 在截止时停止，链返回 124，执行了 finalize，子进程没有残留。
