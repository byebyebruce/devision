# 第 14b 轮 r14b-mirror：r14 配方 + 左右镜像对和 VSR 的回放底数

日期：2026-10-13。负责人看完 r14-count 的结果后决定："先试试吧"（选项 1，未另请评审）。采用规则在训练前写下，结果出来后不改。轮次名是暂定的，可由负责人改。

## 为什么

r14-count 达到了主要条件（CountBench +14.5 [+10.0, +18.9]），但没过旧能力保护：
- `test_relation_flip` −1.4 [−2.8, −0.1]，已证明退化；
- `test_position_flip`、`test_vsr` 未证明守住；
- What'sUp 的 NLL 升高 +0.051。

它的回放里几乎没有左右类题：
- VSR 只有 53 题（v12 训练集里有 5,400 题）；
- v6 的左右镜像对一题都没有。

候选原因是左右能力被稀释。本轮只改这一处，看能否在保住计数提升的同时守住左右 / 关系类。

## 配方

代码在 `scripts/r14b/build.py`（原在分支 r13b-v12 的提交 98f6ae0，已合入 develop），输出 `data/r14b/train.jsonl`，共 81,875 题，约 10,234 步。

| 块 | 题数 | 相对 r14 |
|---|---:|---|
| r14 的其余 6 个块 | 57,873 | 逐题相同 |
| 回放：v12 扩展 | 21,002 | 每个来源 2,400 → 2,100，是 r14 那批题的子集（−3,000） |
| **新增：左右镜像对** | 2,000 | 从 `data/v6/train_flip_mix.jsonl` 取 1,000 对，每对是原图 + 镜像图：关系 600 对、位置 400 对 |
| **新增：VSR** | 1,000 | v12 训练池里不在通用回放中的 VSR 题 |

- 回放占 70.7%；全部是非题中答"是"占 50.04%。
- 构建时核对过：镜像对和 VSR 两块的图片（去掉 `:flip` 后缀按 id 比对，再按文件名比对）都不在本轮任何评测集、监测面板或 val 中。

训练参数与 r14-count 完全相同。监测面板比 r14 多两个：
- `flip` = `data/v6/dev_lr_pairs.jsonl`（1,544 题，其中 462 题也在温度拟合集里，用途为 monitoring）；
- `vsr` = `data/v5/dev_vsr.jsonl`（280 题）。

止损规则和阈值与其他面板相同（`scripts/r14b/rules.json`），由 `scripts/r14b/chain.sh` 执行。

## 采用规则（训练前写下）

1–3 与 r14-count 相同，比较对象是 v12，按题配对、按图重采样（`scripts/r14/accept.py --cand runs/r14b-mirror/eval`）：

1. **主要条件**：`test_count_fresh` 或 `bench_countbench` 的准确率提高，且差值下界 > 0。
2. **旧能力保护**：所有 `test_*`、`bench_pope` 和四个 `bench_lv_*`，差值下界都要 > −2 个百分点。
3. **概率质量警戒**：任一集合校准后 NLL 升高 > 0.02 且差值下界 > 0。
4. **开发面板**（辅助）：同 r14，另加 `flip`、`vsr` 两个面板，下界 > −2（`judge.py --rules scripts/r14b/rules.json final`）。

1、2 满足且 3 未触发，即作为 v0.3 候选，交负责人决定；否则保留 v12。

另外报告 r14b − r14（`accept.py --cand runs/r14b-mirror/eval --base runs/r14-count/eval`），只用来判断这次修改有没有起作用，不作为采用条件。关注的集合：`test_relation_flip`、`test_position_flip`、`test_vsr`、`bench_whatsup`、`bench_countbench`。

### 能说的和不能说的

- **能说的**：两轮唯一的差别是 3,000 题回放。
  - r14b 多了左右镜像对 2,000 题和 VSR 1,000 题，扩展集少了 3,000 题，其余逐题相同、顺序随机。
  - 这个差别下，r14b 在第 2,000 步按规则止损，r14 没有。
- **不能说的**：
  - 不能说"加镜像对伤害计数"。面板只有 300 题，r14b 的 −3.3 相当于少答对 10 题，和 r14 同步的 −0.7 区间大幅重叠；r14 自己在第 6,000 步也到过 −1.7。
  - 换了 3,000 题后，整个打乱顺序和每步看到的批次都变了，两轮的差别里混有训练顺序带来的随机波动。没有同配方换种子的重复，分不开这两者。
- **镜像对和 VSR 两个新面板**：到第 2,000 步都没有回升（−0.3、−1.4，区间含 0）。止损发生在训练前 20%，还不能判断这处改动对左右类最终有没有用。

### 留给负责人和评审的问题

1. 原格式计数面板只有 300 题，按图配对的区间宽度约 ±3 个百分点。用"差值 ≤ −3 且上界 < 0"做止损，单次监测的误报率可能不低。是继续沿用、扩大面板，还是改成要求连续两次触发（像 NLL 规则那样）？任何改动只对之后的轮次生效，不回头救 r14b。
2. 下一步可选的方向：
   - **A**：按 r14 原配方换种子重复一次，测训练顺序带来的波动有多大；
   - **B**：在 r14 的基础上只追加镜像对和 VSR，不削减扩展集；
   - **C**：直接采用 r14，作为取舍；
   - **D**：保持 v12。
