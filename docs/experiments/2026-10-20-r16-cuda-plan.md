## 训练路线（负责人 2026-10-20 修订：从 v0.3 接着训，不从零重走）

从 v0.3（`runs/v03/model`，即 HF snapshot af353dc…）开始，只加 v0.3 没学过的数据，用 v0.3 最后一段的混合做回放。

**新数据（对 v0.3 是新的）**：r13 的训练来源，v0.3 链路里一道题都没用过（r14 / r14b / `ext/train_mix` 都不含；只有 PixMo 双类的图片在 r14 里以单类题出现过，`scripts/exp14/build.py:61-72`）：
- VisMin、CounterCurate、GQA-bind 训练集（成对题不拆开）、CoGenT A、VAW；
- TallyQA-complex、PixMo 双类计数题。

r13 在 v12 上用这些数据：bind_gqa +7.6、relation_flip +19.8、relation +16.9、position_flip +7.7、What'sUp +30.5、CoGenT B +5.9；退步 POPE −6.5、CountBench −6.7（`2026-10-11-r13-report.md`）。已查明的原因要在 r16 的构建里修掉：
- 存在题按类别 yes = no 配平（r13 的 `absent()` 只放进 "no"，真实照片存在题只有 15% 是 yes）；
- 计数题改成 0..10 选项（r13b 的写法，`scripts/r13b/build.py:15-19`），不用围绕正确答案 ±3 的窗口；构建后核对"选下中位数"这类不看图规则接近随机；
- ScienceQA 回放保留必须看图的题和 AI2D / TQA 的全部份额。

不能训练：What'sUp、SugarCrepe、CountBench、CoGenT B（r13 的迁移评测，r15 的 heldout）。

**回放**：60–70% 来自 `data/r14b/train.jsonl`（v0.3 最后一段的混合；r14 用的是 70.7%），保留镜像对和 VSR 的下限，保留原格式计数题。r14b 依赖 `ext/train_mix`、exp14、r14，都属于数据 B。

**设置**：新优化器，预热 100–300，每 1,000–2,000 步监测。绑定类能力需要较大的步数（exp15-bind 4k 题 / 2,000 步对 bind_gqa 无效），所以按长程用 exp21 的设置：2e-5 / 1e-5 / 5e-5（new / head / LoRA），解冻 SigLIP 顶部 4 层，`lr_vision` 5e-6。结束后重拟合温度，盯 NLL（exp21 在 v0.3 上续训时各面板 NLL 升了 0.03–0.13）。

**数据 B 的构建顺序**（数据 A 完成后）：v11 计数集（`v11_count_eval.py`、`v9_mix.py`）→ `ext/build_ext.sh` → `r13/identity.py`、`r13/gqa_bind.py`、`r13/sources/build_sources.sh` → `exp14/build.py`、`r13b/build.py`、`r14/build.py`、`r14b/build.py` → 新的 r16 混合（新来源 + r14b 回放）。

不采纳：v0.4-k 的读数组合（成本高，position −2.0 / size −1.6 / vqa_choice −1.5，新图读数 1/240，dev16 未达标）；exp20 的 256 token（flip −8.3）；exp29 选项顺序平均（无收益）。post-r15-order A/B 的结果没有记录，不作依据。

## 设备与精度

**EXP77 结果（2026-10-20，`configs/exp77-amp-{bf16,off}.yaml`）**：从 v0.3 出发、data-v2 混合前 8,000 题、1,000 步、exp21 的续训设置（解冻 SigLIP 顶部 4 层），只改 `amp`。

| | bf16（`amp: cuda`） | fp32（`amp: off`） |
|---|---|---|
| val（`v2/dev_mix_half`）准确率，第 0 / 1000 步 | 0.809 / 0.807 | 0.809 / 0.808 |
| val NLL 套用拟合温度后（未套用：第 0 步 0.451 → 第 1000 步） | 0.415（0.575） | 0.414（0.533） |
| 每步耗时（micro_batch 8） | 0.303 s | 0.346 s |
| 显存峰值（nvidia-smi，每 5 s 采样） | 5.9 GB | 6.4 GB |

结论：两者结果在噪声内一致，后续用 bf16（CUDA 上的默认值），快 12%。12 GB 显存足够（解冻视觉顶层时约 6 GB）。另外：在 v0.3 见过的数据上续训，准确率不变而未校准的 NLL 上升（变得过度自信），与历史经验一致，r16 的收益只能来自新数据。


- `rlcd.py` 的 `amp` 默认 `"cuda"`：在 CUDA 上前向用 bf16 autocast。v0.3 链路里 v11 之前的段在 MPS 上实际是 fp32，之后显式 `amp: off`。按 EXP77 用 bf16。
- 显存：12 GB；micro_batch 8 在冻结视觉时预计足够，解冻 SigLIP 顶层后在 r17 开训前实测，必要时改 micro_batch 并单独记录。
- 延迟：发布前用 `--device cpu` 单独测（CLAUDE.md 约束）。
