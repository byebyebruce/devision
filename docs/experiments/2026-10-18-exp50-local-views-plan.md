# exp50 方案：固定局部视图与细粒度通路（T / C 两臂；CPU 准备完成，未运行，等评论家的模型许可）

日期：2026-10-18。依据：评论家 EXP50-PREP-01..05（EXP49 终点之后）。

## 问题

保持普通 `decide` 接口和全图通路不变，把原始图片里的局部细节交给现有的 QuestionConditioning 作为 K/V，能否在原图上建立数值读取和对象绑定？

EXP49 的依据：
- SigLIP 末层在 L 图（数字 16 px）未见图上能读出数字（整串 0.834），原图只有 0.241；
- projector 之后只剩 0.221（L）/ 0.033（原图）。

## 两臂（唯一臂间变量：局部视图的像素来源）

- **T**：从原始图片按固定矩形裁局部视图，每个视图再各自 letterbox 到 256。裁剪发生在全图降采样之前。
- **C**：先把原图降到与全图 256 letterbox 相同的细节，再在同一原图坐标里裁完全相同的矩形，同样 letterbox 到 256。
  - 降细节规则（`devision.image.degraded`）：用全图 letterbox 的内容矩形尺寸 `nw, nh = round(w·s), round(h·s)`，其中 `s = 256 / max(w, h)`。先 bilinear 缩到 (nw, nh)，再 bilinear 放回 (w, h)。
  - 所以 C 看到的空间范围和上下文与 T 相同，但没有比全图 256 更多的原始细节。
  - 边界取整与 T 相同：矩形都取整到整数像素，两臂共用 `view_rects`。
- **相同的部分**：
  - 两臂的全图分支完全相同（原图标准 256 letterbox），测试逐位核对；
  - 视图个数、顺序、矩形、几何编码、letterbox 边相同；
  - 新增参数及其初始化逐张量相同，测试核对两臂进入优化器前的全部张量。
- **不用的控制**：不用"重复全图、假装在不同位置"作控制。
- **能下的结论**：T − C 检验的是"这套共享结构下保留原始细节"的作用。C 和 T 同时提高，只能支持共同的新通路或配方，不能算作局部高分辨率的独立效果。

## 实现（同一路径用于训练、评测和普通 decide）

- **配置**：`ModelConfig` 新增 `local_views` / `local_overlap` / `local_source`，随 checkpoint 保存。
  - 默认 0，即旧行为：旧 checkpoint 读入后答案逐位相同（测试）。
  - 不靠实验脚本裁图冒充产品接口。
- **像素**：`image_tensor` 在局部模式下返回一张图的打包张量 `[3 + 3·16 + 1, 256, 256]`（`devision.image.local_pixels`）。
  - 依次是：全图 letterbox、16 个视图的 letterbox、一个几何平面（首行依次是原图宽、高和每个视图的 (x0, y0, x1, y1)）。
  - 这样批处理和 `_Images` 都不用改。
- **模型**：`VisionDecisionModel.visual_inputs` 是 decide、训练前向和 aux 共用的唯一入口。
  - 全图和 16 个视图都过同一个 SigLIP，每次至多 64 个视图，内存有界；测试核对分块与不分块的结果相同。
  - 64 个视觉 token 只来自全图，经原有 2×2 projector，所以 ModernBERT 的视觉序列仍是 64。
  - K/V = 全图 256 个 patch 加 16 × 256 个局部 patch，共 4,352 个；局部 patch 不经过 projector。
  - 每个 K/V patch 带它在整张原图里的几何 (cx/w, cy/h, pw/w, ph/h)（`patch_geometry`，全图 patch 也同样计算）。经新的 `QuestionConditioning.geom = Linear(4, 1024)`（初始化为零）加到 K/V 上。
  - 没有 padding mask：所有视图总是存在；letterbox 灰边上的 patch 与全图分支一样保留，它的几何落在视图之外。
  - 测试：图中白点所在的 patch，其几何中心与原图像素坐标的差在一个 patch 以内。
- **输入里没有 oracle**：
  - 视图矩形只由 (w, h, n, overlap) 决定，测试核对内容不同、尺寸相同的两张图矩形相同；
  - 不用题目、对象框、字段、答案、数据集名、样本 ID 或文字检测；
  - 框只在 `scripts/exp50/geometry.py` 里做审计。
- **训练**（`TrainConfig.local_views` 等）：
  - 在设种子之前启用局部视图，所以 LoRA 初始化、批序和噪声不变；
  - 每个 micro batch 的不同图片只编码一次，再按题索引；测试核对与逐题编码的结果相同；
  - 与 region / grounding / 蒸馏 / 数字辅助损失、视觉塔解冻同时使用时拒绝；
  - 已有其他局部设置的 checkpoint 拒绝。
- **测试**：`tests/train/test_local_views.py`，12 项；`scripts/exp50/test_exp50.py`，3 项。`uv run pytest -q` 264 项通过（含新增 12 项），exp48 / 49 / 50 脚本测试 17 项通过，pyright 0 错误。

## CPU 几何核查（`scripts/exp50/geometry.py` → `data/exp50/geometry.json`；预览 `runs/exp50-preview/sheet.png`）

- **范围**：实验涉及的 880 张原图和 880 张 L 图，即 exp49 题单里的全部图片（fit 和 tune）。
- **原图数字框**：只读重放生成器的绘制，取数字子串的文字框。
  - 全部 2,376 个被问到的框都落在 EXP45 已核的行框之内（脚本内检查）。
- **L 图数字框**：exp37 / exp40 的槽框去掉内边距，作为近似字形框。
- **墨迹高度**：字号的 0–9 字形框高度乘以缩放。
- **网格规则**（`view_rects`）：
  - 在 n 的因数分解 cols × rows 中，选单格最接近正方形的一种；
  - 视图尺寸 = 单格 × (1 + overlap)，不超过原图；
  - 首个视图贴左 / 上边，末个视图贴右 / 下边，中间均匀分布；
  - 并集覆盖整张图，四边都覆盖（测试）。
- **选择准则**（看结果之前写在脚本里）：
  - 在 n ≤ 16、≥ 99.5% 的原图数字被某个视图完整保留的候选中，选原图数字在其最佳视图里墨迹 ≥ 16 px 比例最高的；
  - 并列时选视图少的。

原图（2,728 个数字，含两视图的全部字段）：

| 候选 | 完整保留 | 切字 / 缺失 | 质量·速度 墨迹中位（≥12 / ≥16） | 距离 墨迹中位（≥12 / ≥16） |
|---|---|---|---|---|
| 全图 256 | — | — | 5.4 px（0 / 0） | 4.3 px（0 / 0） |
| n8, 0.25 | 0.9949 | 14 / 0 | 11.5 px（— / 0） | 20.1 px（— / 0.78） |
| n12, 0.25 | 0.9945 | 15 / 0 | 17.0 px（1.00 / 0.72） | 23.0 px（0.98 / 0.98） |
| n12, 0.50 | 0.9996 | 1 / 0 | 14.2 px（0.92 / 0.06） | 19.3 px（1.00 / 0.80） |
| n16, 0.25 | 0.9923 | 21 / 0 | 17.3 px（— / 0.72） | 27.1 px（— / 0.97） |
| **n16, 0.50（选定）** | **1.0000** | **0 / 0** | **14.4 px（0.92 / 0.07）** | **22.7 px（1.00 / 1.00）** |

- **选定**：16 个视图、重叠 0.5。
  - 温度图（约 560 × 405）为 4 × 4，视图约 210 × 152，放大约 1.22 倍。
  - 磁铁图（约 650 × 140）为 8 × 2，视图约 122 × 105。
- **如实说明**：
  - 质量 / 速度数字从全图的 5.4 px 增到 14.4 px（约 2.7 倍），≥ 12 px 的占 92%，但 ≥ 16 px 只占 7%。
  - 距离数字 100% ≥ 16 px。
  - n12 / 0.25 的墨迹更大（17 px，72% ≥ 16），但有 15 个数字在所有视图里都被切，不满足预写的 ≥ 99.5% 完整保留，所以没选。
  - 14 px 是否够 SigLIP 读出没有直接证据：EXP49 的阳性是 16 px。这一次选定网格，不用模型成绩改网格。
- **L 图**：数字本来就大，全图 256 下已是 16 px（≥ 16 的占 94–96%）。在局部视图里只有 53% 被某个视图完整包含（宽数字超出视图），L 的读数主要仍靠全图分支。
- **C / T 对照**（测试和预览）：
  - 两臂同一矩形；
  - 全图分支与 `to_pixel_values` 逐位相同；
  - T 的视图 = 原图裁剪的 letterbox，C 的视图 = `degraded` 后裁剪的 letterbox，都逐位核对；
  - 细节图上 T 视图的像素标准差 > 3 倍 C 视图的；
  - 预览里 T 清晰，C 模糊到全图 256 的细节。

## 训练（固定，两臂相同）

- **起点**：EXP48-X 的冻结终点（`a8b92cb9…` / `c017a469…`），chain 启动前核对，不使用 EXP49 的 oracle 小头。
- **数据**：EXP42 O+L 训练集，严格四题组，CE + interaction_weight 1.0（EXP48 配方，不再搜权重）。
  - 576 次有效更新 / 臂，micro_batch 8，每批两个完整四题组（一个原图、一个 L），不拆单元。
  - 批计划（`scripts/exp50/plan_check.py` → `data/exp50/PLAN.json`）与 EXP48 逐项相同，每批 4 张不同的图。
- **优化设置**：lr_new 2e-5、lr_head 1e-5、lr_lora 5e-5、lr_cond 1e-4、warmup 100、seed 1、amp off、eval_every 0、save_every 500。
  - `configs/exp50-{t,c}.yaml` 只差 name 和 local_source（测试核对）。
- **参数组**（实际张量数和参数量写进 train_report 的 `local.groups`）：
  - projector（4,202,496）；
  - head（Laya 决策头可训练部分）；
  - LoRA（r 16）；
  - cond（原 QuestionConditioning 7,085,056 + 新几何层 5,120）。
  - **SigLIP 全部冻结**（train_report 的 `local.vision_trainable` 必须为 0），X 训过的顶 4 层保持 X 的值。
- **两臂相对 X 的共有变化**（全部披露）：
  1. 局部视图通路和几何层；
  2. SigLIP 顶 4 层由可训练改为冻结；
  3. 在 X 已训过的同一 576 次更新上再训一遍（相当于第二个 epoch）。所以 A − X 混有"多训一遍"，C 臂正是它的对照；
  4. val 改用 `data/exp50/val_quarter.jsonl`。它是 val_sub 按文件顺序每 4 行取 1 行，244 / 973，因为每题现在要编码 17 张图。只用于监测和保存的温度，主读出用 temperature 1，不受影响。
- **终点固定**：第 576 步，不按 tune 选步；fresh 启动，不 resume，不重试。

## 读出与预写条件（`scripts/exp50/report.py`，与 EXP48 同口径）

- **集合**：主集合是原图 rl_tune；fit_O / fit_L、rl_tune_L 是机制和拟合参考；exist / science 只作风险观察，不宣称七面板安全。
- **统计**：沿用 EXP48，即字段等权、异值两对象、值改变孪生、严格四题（rl_tune 176 组，274 组因"没有交换"排除），case 簇配对区间（2,000 次重采样，seed 0）。
- **基线**：冻结 X 的同题 raw 记录。
  - 读取前核对 X 的冻结身份和每个集合的记录；题集不同则拒绝。
  - 无模型复算已复现 X 的 EXP48 读出：rl_tune 两对象 0.041，四题 0/176。
- **两臂身份检查**：START / run.json / train_report / checkpoint config 必须全部对上（起点、数据、四题组 sidecar、局部规则、本臂的像素来源、视觉塔冻结）。任何一项不对就拒绝（测试 8 种错臂）。
- **每臂 progress（四条同时满足，判的是"值得做候选训练"，不是发布通过）**：
  1. 原图异值单题宏平均 ≥ 0.60；
  2. 原图异值两对象 ≥ 0.20，且 A − X 下界 > 0；
  3. 值改变孪生两视图全对 ≥ 0.20，且 A − X 下界 > 0；
  4. 严格四题全对 ≥ 0.10，且 A − X 下界 > 0。
- **归因（局部原始细节）**：T − C 原图两对象 ≥ +0.10，且下界 > 0。
  - C 通过而 T 不通过时，按 C 的真实结果裁决，不算局部细节成功。
  - 两臂都不通过时，不接同配方加步或加权。
- **不当作成功**：logit、注意力和 loss 的变化都不算离散成功。
- **逐题记录**：逐题预测和冻结终点身份都保存，可重算。

## 预算（两臂 + 主读出 + 报告 ≤ 90 分钟；以首窗实测重算）

依据 EXP48-X 的实测：
- 每次更新 1.43 秒，训练加 2 次验证共 16.9 分钟；
- 6 个集合的评测 7.4 分钟，2,601 次请求；
- EXP49 抽取 1,760 张图不到 39 秒（含加载），SigLIP 每张约 12 ms；
- 本机裁 16 个视图每张 6–7 ms（已测）。

| 项目 | 每臂估计 |
|---|---|
| 训练 576 × (1.43 + 4 张图 × 16 视图 × 12 ms ≈ 2.2 秒) | 21 分钟 |
| 验证 2 次 × 244 题 × (75 + 200 ms) | 2.2 分钟 |
| 加载、保存、冻结 | 2 分钟 |
| 评测：原 7.4 分钟 + 2,601 次请求 × 0.2 秒 | 16 分钟 |
| **合计** | **约 41 分钟** |

- **总计**：两臂约 82 分钟，加报告约 1 分钟；绝对截止为启动 + 90 分钟，最后 120 秒留给报告。
- **SigLIP 去掉反传（未计入）**：X 训顶 4 层，这里全冻结，每次更新还应省一些时间，所以上表偏保守。
- **watch**（`scripts/exp50/watch.py`）：
  - 首窗或相邻两个窗口 > 2.6 秒 / 更新时停止（超过 2.6 秒两臂就装不进 90 分钟）；
  - 内存规则同前（MPS > 16 GB 且可用内存 < 2 GB）；
  - 停滞上限 15 / 15 / 10 分钟。
- **超预算处理**：不自动缩集合、改阈值、加步或重试。
  - 顺序 T → C：时间不够时 C 缺失，归因记为 incomplete。
- **内存**：EXP48-X 的 MPS 峰值 ≤ 8.64 GB（当时还要对 SigLIP 顶 4 层反传）。
  - 新增：每步 68 张图的无梯度 SigLIP 激活（分块 64，峰值约 0.3 GB）、K/V 4,352 × 1024 × 8 题（约 0.14 GB）、条件模块反传保存的输入和注意力（约 0.2 GB）。
  - 验证每块 32 题：K/V 约 0.6 GB。
  - 预计峰值 ≤ 10 GB。
- **磁盘**：每臂 checkpoint 2.0 GB 加记录，合计约 4.2 GB（可用 275 GB）。
- **不用特征缓存**：评审允许绑定身份的磁盘缓存，但普通 decide 不能走缓存。为让训练、评测和 decide 共用同一路径，全部实时计算。
- **CPU 延迟**：每次请求要多跑 16 次 SigLIP。按 SigLIP-base 在 4 线程 CPU 上每张约 60–80 ms 估计，约增加 1–1.3 秒；v0.3 是 P50 175 ms。
  - 现在不加载真实模型，所以没有实测；若成为候选必须实测并写明，作为取舍依据。
