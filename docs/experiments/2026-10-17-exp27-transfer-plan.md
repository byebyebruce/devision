# exp27 方案：exp26 的读数能力能不能带到真实 ScienceQA 题上——只评测（代码与测试已写，待评审，未运行模型）

日期：2026-10-17。负责人："好，你上面说的事情可以着手开始做了"（exp26 之后、Codex 交接 EXP26-RESULT-02 的下一步）。只评测，不训练、不校准、不发布。

## 要回答的问题

exp26（`docs/experiments/2026-10-16-exp26-bind-align-plan.md` 结果一节）：在合成两面板图上，读数和比较都过线（dev16 读数 0.922、比较 0.950）。但训练图和测试图是同一种画法；ScienceQA 的温度题是两个瓶子下面各写着"Sample A / B"和质量、速度，磁力题是两对磁铁加距离标注，版式不同。

这里问：**exp26 第 5,000 步的模型，与 v0.3 在同一批真实 ScienceQA 温度 / 磁力题上相比，准确率和看图收益有没有提高？旧能力掉了多少？**

## 被比较的两个模型

- **v0.3**：`runs/r15-vision/stage2`（与 v0.3 发布包权重哈希相同，见 `runs/manual-vision/20261016-web-photos/v03-identity.md`）。
- **exp26 第 5,000 步**：exp26 的链在第 5,000 步记录写完后停训，没有走到最后的保存，只留下 `runs/exp26-read-compare/stage2/resume.pt`（第 5,000 步的可训练权重，已核对 `len(losses) = 5000`、331 个张量）。`scripts/exp27/export.py` 按 `rlcd.train()` 开训前的方式搭好模型，包括视觉塔顶部 4 层、同样的 LoRA 和 unfreeze_top，再把可训练权重按名字一一拷入（名字集合必须完全相同，否则拒绝），然后合并 LoRA、保存到 `runs/exp27-transfer/exp26-step5000`。
  - 温度沿用起点 `runs/exp26-align/stage1` 的温度，没有重新拟合。准确率与温度无关；NLL 不作判定。

## 判定（运行前写下，结果出来后不改；`scripts/exp27/report.py`）

- **迁移**（沿用 exp21 的 `readout.transfer`，第 0 步换成 v0.3）：
  - 温度、磁力两类准确率变化按 **68 : 114** 加权（ScienceQA validation 里这两种问法的题数）；
  - 看图收益变化 = (真图 − 错图)@exp26 − (真图 − 错图)@v0.3，同样加权；
  - 同一题的四条记录一起，按原图在类内重采样。

| 结果 | 条件 | 可以说 | 下一步候选（另写方案，不自动启动） |
|---|---|---|---|
| 观察到迁移 | 准确率变化与看图收益变化的下界都 > 0 | 合成面板上学到的读数 / 绑定在这批真实温度 / 磁力题上也起作用 | r16 正式方案：把读字 + 面板对齐并进正式配方，加回放保护旧能力 |
| 准确率升、看图收益未证 | 准确率下界 > 0，看图收益下界 ≤ 0 | 准确率高了，但不能说是因为更会看图 | 交负责人 |
| 未见迁移 | 准确率下界 ≤ 0 | 合成画法与真实版式之间还有差距 | 做更接近真实版式的合成数据（瓶子 / 磁铁式布局） |

- 只报告：温度、磁力分项；浓度、吸斥的配对变化；24 道转录题；7 个保护面板（exp26 − v0.3，按原图重采样，ext 用 13 来源等权宏平均，flip 镜像并到原图），任一 ≤ −3 且上界 < 0 记为"有代价"。exp26 只训了合成题，旧能力预计会掉；这一项用来设计 r16 的回放，不是本实验的门槛。
- 不能说的：exp26 不是候选模型，不能替换 v0.3；41 道温度题样本小，不显著不等于没有效果；单种子。
