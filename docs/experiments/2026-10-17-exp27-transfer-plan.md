# exp27 方案：exp26 的读数能力能不能带到真实 ScienceQA 题上——只评测（代码与测试已写，待评审，未运行模型）

日期：2026-10-17。负责人："好，你上面说的事情可以着手开始做了"（exp26 之后、Codex 交接 EXP26-RESULT-02 的下一步）。只评测，不训练、不校准、不发布。

## 要回答的问题

exp26（`docs/experiments/2026-10-16-exp26-bind-align-plan.md` 结果一节）：在合成两面板图上，读数和比较都过线（dev16 读数 0.922、比较 0.950）。但训练图和测试图是同一种画法；ScienceQA 的温度题是两个瓶子下面各写着"Sample A / B"和质量、速度，磁力题是两对磁铁加距离标注，版式不同。

这里问：**exp26 第 5,000 步的模型，与 v0.3 在同一批真实 ScienceQA 温度 / 磁力题上相比，准确率和看图收益有没有提高？旧能力掉了多少？**

## 被比较的两个模型

- **exp26 第 5,000 步**：exp26 的链在第 5,000 步记录写完后停训，没有走到最后的保存，只留下 `runs/exp26-read-compare/stage2/resume.pt`（第 5,000 步的可训练权重，已核对 `len(losses) = 5000`、331 个张量）。`scripts/exp27/export.py` 按 `rlcd.train()` 开训前的方式搭好模型，包括视觉塔顶部 4 层、同样的 LoRA 和 unfreeze_top，再把可训练权重按名字一一拷入（名字集合必须完全相同，否则拒绝），然后合并 LoRA、保存到 `runs/exp27-transfer/exp26-step5000`。
  - 温度沿用起点 `runs/exp26-align/stage1` 的温度，没有重新拟合。准确率与温度无关；NLL 不作判定。

## 判定（运行前写下，结果出来后不改；`scripts/exp27/report.py`）

- **迁移**（沿用 exp21 的 `readout.transfer`，第 0 步换成 v0.3）：
  - 温度、磁力两类准确率变化按 **68 : 114** 加权（ScienceQA validation 里这两种问法的题数）；
  - 看图收益变化 = (真图 − 错图)@exp26 − (真图 − 错图)@v0.3，同样加权；
  - 同一题的四条记录一起，按原图在类内重采样。

| 结果 | 条件 | 可以说 | 下一步候选（另写方案，不自动启动） |
|---|---|---|---|
| 观察到迁移 | 准确率变化与看图收益变化的下界都 > 0 | 合成面板上学到的读数 / 绑定在这批真实温度 / 磁力题上也起作用 | r16 正式方案：把读字 + 面板对齐并进正式配方，加回放保护旧能力 |
| 准确率升、看图收益未证 | 准确率下界 > 0，看图收益下界 ≤ 0 | 准确率高了，但不能说是因为更会看图 | 交负责人 |
| 未见迁移 | 准确率下界 ≤ 0 | 合成画法与真实版式之间还有差距 | 做更接近真实版式的合成数据（瓶子 / 磁铁式布局） |

- 只报告：温度、磁力分项；浓度、吸斥的配对变化；24 道转录题；7 个保护面板（exp26 − v0.3，按原图重采样，ext 用 13 来源等权宏平均，flip 镜像并到原图），任一 ≤ −3 且上界 < 0 记为"有代价"。exp26 只训了合成题，旧能力预计会掉；这一项用来设计 r16 的回放，不是本实验的门槛。
- 不能说的：exp26 不是候选模型，不能替换 v0.3；41 道温度题样本小，不显著不等于没有效果；单种子。

### 事后观察（只读明细，不改判定；按评审 EXP27-RESULT-01–03 修订，2026-10-17）

- **这批开发题上有下降的证据**，不只是"没证明迁移"：加权准确率 −11.1 [−20.1, −2.1]，区间全为负；6 个保护面板的区间上界都 < 0。
- **"选一样"是观察到的行为，原因还没定位。** exp26 在真实题上：温度 32 / 41 选 neither（正确答案里只有 3 题是它），浓度 45 / 45；但磁力只有 7 / 120 选"same in both pairs"（正确 34），所以没有普遍偏向"相等"。neither 在第 1 / 2 / 3 位时都会被选（温度 16 / 10 / 6，浓度 17 / 18 / 10），不能只用位置偏向解释；同题换序还没做。
- **合成题上的分层证据**（exp26 第 5,000 步，比较题）：

  | 条件 | 选相等 | 正确答案为相等 | 比较正确 |
  |---|---|---|---|
  | dev16 原图 | 68 / 400 | 63 / 400 | 380 / 400 |
  | 擦除数字 | 186 / 200 | 31 / 200 | 37 / 200 |
  | 同批擦除图 + 数值文字 | 31 / 200 | 31 / 200 | 198 / 200 |

  拿不到两个数时，模型倾向答"相等"；给出数值后就不偏。这个倾向在决策训练阶段形成：exp26 阶段 B 擦除图选相等 0 步 0 / 200、1,000 步 174 / 200、5,000 步 186 / 200；exp25 阶段 B 也从 0 / 200 到 200 / 200，所以它不是 exp26 新增的面板对齐带来的。训练文件里相等答案只占 17.1%（1,592 / 9,334），不是"相等占多数"的标签先验。
- 所以，此前写的"合成训练里的 equal 选项带来答案偏向"超出了证据。更符合现有证据的说法是：**缺少可用数值时偏向相等**；真实图上的读数 / 绑定失配可能触发同样的行为，但措辞、题目模板和视觉域差异都还没排除。
- **温度和磁力的失效环节不同**（24 道转录题按同题拆开，每格正确数 / 12）：

  | 模型 / 题类 | 原图 | 空白图 | 空白图 + 转录数值 |
  |---|---|---|---|
  | v0.3 温度 | 6 | 6 | 5 |
  | exp26 温度 | **3** | 1 | **10** |
  | v0.3 磁力 | 4 | 4 | 3 |
  | exp26 磁力 | 4 | 3 | **3** |

  exp26 的温度题，给出数值后 12 题里对了 10 题，空白时全部答 neither，补了数值就一题都不答 neither。所以温度题优先怀疑从真实图提取信息 / 绑定这一步（不能只凭这一点断定只缺 OCR）。这 12 题里没有质量、速度一大一小互相冲突的组合，10 / 12 不代表会做一般的物理计算。磁力题直接给出距离 / 大小文字也只对 3 / 12（例如 test-1376 明确写 Pair 1 相距 3 in、Pair 2 相距 5 in，模型却选 Pair 2 更强），说明规则、关系方向或题目 / 选项理解也没打通。
- 真图 / 错图的预测有变化（温度 13 / 41、磁力 32 / 120 改变），模型对图有反应，但反应没有和正确内容对上；不能说"完全不看图"。

### 解读（只限于这次的设置）

- 能说的：只用合成面板题训练出的 exp26，在这批真实温度 / 磁力开发题上没有比 v0.3 更好，温度题明显更差；它带来了对"neither / 一样"类选项的强偏向，并且旧能力明显下降。合成面板上的读数和绑定（exp26）没有直接带到真实瓶子 / 磁铁图上。
- 不能说的：不能说读字 / 面板对齐对真实题无用——这次评的是只训合成题的整套模型，没有回放真实数据；也不能把"选一样"直接归因于合成训练的 equal 选项，或把下降都归因于"读不出"。旧能力下降是在 exp24-A、exp26-A 还是 exp26-B 发生的，这次分不开。样本小（温度 41 题）、单种子；dev_sqa 参与过此前决策。
- 决定（评审 EXP27-RESULT-01 / 04）：exp26 的配方不采用、不原样延长；下一步是 exp28 短诊断（`docs/experiments/2026-10-17-exp28-diagnose-plan.md`），定位失效环节后按预写的分支只做一项修复。
