# exp133：原生分辨率切块 tiles 0 / 2 对照（预写，2026-10-29 02:10，exp132 训练中，不算轮次）

**背景**：v0.5 目标里的网页操作、文档 / 小字、图表都要读小字。Mind2Web 1024×800 截图 letterbox 到 256 后字高约 3 px；exp129 的 gui_state 监测集里 Mind2Web 子集只有 35.4%（AITW 75.9%）。切块（spec「实验性、可选：原生分辨率切块」，506dd79 合入）给短边 ≥ 512 的图另加 2×2 个原生 256 块（320 视觉 token），小图逐位走 v0.4 的路径。exp78（位置编码插值到 384）、exp79 / exp83（同像素更多 token）没有新增像素，不算重复；见 `docs/research/v05-training-directions.md` 方向 2。

**字高可读性检查**（零成本，先于训练）：`scripts/v05/tile_readability.py` → `runs/v05-monitor/tile_readability.json`，结果见下节；若各用途字高在 256 下 < 6 px 的比例不占多数，本实验降级为只跑 tiles 2 一臂的小规模探针。

## 字高可读性检查结果（02:15，`runs/v05-monitor/tile_readability.json`）

字高是模型实际收到的像素；「切块」列只算会被切块的图（不切块的图按 256 计）。p10 / 中位 / p90：

| 用途（依据） | 256 下 | 切块视图 | 256 下 < 6 px → 最好视图 | 被切块的图 |
|---|---|---|---|---|
| FUNSD 表单（实测词框） | 2.6 / 3.6 / 4.6 | 5.1 / 7.2 / 9.2 | 98.3% → 25.4% | 100% |
| Mind2Web 网页（近似：文字元素框，行高上限 24 px） | 3.2 / 4.8 / 4.8 | 6.4 / 9.6 / 9.6 | 100% → 5.2% | 100% |
| ChartQA test（估计：尺寸实测，字高假设 11.5 px） | 3.5 / 3.7 / 3.7 | 6.9 / 7.4 / 7.4 | 93.6% → 7.0% | 90.8% |
| RICO-ScreenQA（近似：答案元素框） | 5.5 / 7.3 / 8.8 | 10.9 / 14.7 / 17.6 | 15.4% → 0% | 100% |
| AITW 手机截图（实测 OCR 框） | 2.6 / 3.7 / 6.0 | 5.2 / 7.5 / 10.4 | 91% → 68–70% | 28% |

评测集被切块的比例：test_gui 63.4%、test_gui_state 61.6%（即 Mind2Web 部分）、test_gui_shop_state 22.8%、test_ego 0%、test_chartqa 90.8%、POPE 7.8%、MMBench 5.2%、ScienceQA(lv) 5.4%。

**结论**：网页、表单、图表在 256 下几乎全部 < 6 px，切块后大多到 7–10 px → 检查通过，按两臂对照跑。手机截图保存后短边 270–485 px，72% 不会被切块，所以本实验对 AITW / 购物基本是不切块的对照，**不能**回答手机 UI 是否受益；若切块有效，下一步再试 `tile_min_side` 384 或按长边判断。图表字在切块后约 7 px，仍处在可读边缘，ChartQA 增益可能有限。

**做法**：
- 数据 `data/v05/exp133/train.jsonl`（`scripts/data/v05/exp133_mix.py`，53,762 题，sha256 `0d7c46aa…`）：exp129 训练文件按来源取子集，偏向大图小字（mind2web 6,000 全部、screenqa 2,048 全部、chartqa 12,000、aitw-general 6,000、aitw-shopping 4,000、epic-visor 6,000、ai2d / tqa 各 2,000、scienceqa 1,500、iconqa 500）+ FUNSD 表单绑定 414 全部 + 小图旧来源回放（vqav2 3,000、coco-exist 2,000、gqa 2,000、n2-spatial 2,000、coco-size 1,000、v7w / coco-count-val 各 500、tallyqa 300）。评测图片已在 exp129 / FUNSD 构造时剔除。
- 两臂 `configs/exp133-tiles{0,2}.yaml` 只差 `tiles`：都从 v0.4（`runs/r21-soft/train`）起，seed 133、micro batch 4（切块序列 ~470 token，exp129 的 8 估计放不下；为了可比两臂同用 4），其余超参同 exp129，1 epoch 约 13.4k 步。tiles 2 臂先跑；若 CUDA OOM，两臂都改 micro batch 2 重来（chain 自动处理并记录）。
- 评测 18 集（heldout，不跑 controls）：用途侧 test_chartqa（ChartQA 官方 test，exp131）、test_gui_state / test_gui（Mind2Web 818 + AITW 722，按 source 拆分）、test_gui_shop_state、test_ego、test_funsd（FUNSD 表单 dev 111 题，两臂与 v0.4 都没训练、没监测过）；守护侧 POPE、test_vqa_yesno、test_size、test_v7w、MMBench、MME、CV-Bench、What'sUp、CountBench、EgoThink、RealWorld、ScienceQA(lv)。
- **CPU 延迟**：两臂各在 40 道 Mind2Web 截图题上 `devision-eval --device cpu --no-group`（`runs/exp133-*/latency_cpu.json`，单题 P50 / P95）。

**对照**：主比较 tiles 2 对 tiles 0（同数据同种子，差就是切块）；参考 v0.4，以及 exp129 / exp132（全量配方、不切块）。

**判据**（`devision-compare` 按图 95%，tiles 2 对 tiles 0）：
1. 读小字：test_chartqa、test_gui_state 的 Mind2Web 子集、test_gui 的 Mind2Web 子集、test_funsd 四项中至少两项显著提升，且没有一项显著退步。
2. 守护：12 个守护集合与 test_ego / test_gui_shop_state / AITW 子集都无显著退步（不切块的图逐位同路径；POPE 7.8%、MMBench 5.2%、ScienceQA 5.4% 的图会被切块，RealWorld 多为大图）。
3. CPU：如实记录 P50 / P95 与倍数（不作门槛，写进取舍依据；> 4× 时须在 r23 方案里写明缓解，如只对截图 / 文档切块）。
- 1、2 过 → r23 候选配方加 `tiles: 2`（exp129 / exp132 全量混合，micro batch 按本实验实测），并在发布材料里写 CPU 代价。
- 1 不过 → 2×2 切块在这一数据规模上不帮助读小字；记录，不原样扩量，转向更大切块（3×3）前先看字高检查是否支持。
- 1 过、2 不过 → 切块读小字有效但扰动了大图旧能力，下一步试只对截图 / 文档切块。

**预算**：tiles 0 训练约 40 分钟 + 评测约 40 分钟；tiles 2 训练估计 2–2.5 小时 + 评测约 1 小时；CPU 延迟各 ~2 分钟。`scripts/v05/chain_exp133.sh 713465` 挂在 exp132 链之后（exp132 预计 07:00–08:00 评完），exp132 按 0.17 s/步约 03:20 训完、05:30 前后评完，exp133 约 11:00–12:00 全部完成。
