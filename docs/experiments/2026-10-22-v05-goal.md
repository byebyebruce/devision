# v0.5 目标：真实需求场景的能力突破（2026-10-22）

负责人 2026-10-22："定一下 v0.5 版本的目标，就是要在真实需求场景的能力方向，各个指标达到突破，而不是原来合成数据的指标。"

## 为什么换口径

v0.4 的进步集中在我们自己造了数据、也自己出了题的能力上（空间关系、计数、示意图）；从没用过的外部综合评测几乎没动（MMBench +2.3、CV-Bench +0.7、NaturalBench +0.3、MME −0.6），抽查里颜色和形状对应、小字、细节仍然错，贪吃蛇也不会玩。v0.5 不再以自造的 `test_*` / 合成集为主要指标。

## 主指标：ImageJevBench（Benchmark Heaven，图片决策模型的公开榜）

[ImageJevBench v0.3.0](https://benchmarkheaven.com/image-jev-bench)：2,441 题 / 2,160 张图，每次抽 300 公开 + 1,200 封存；直接按 Jev 的图片决策口径评分，同时看答对和概率质量。题目来自真实使用场景：

| 用途 | 题数（公开 / 封存） | 内容 |
|---|---|---|
| 文档检查 | 91 / 374 | 票据、文档照片、小字 |
| 图示与规划 | 62 / 239 | 示意图、流程、多面板比较 |
| 图表决策 | 54 / 230 | 图表推理、误导性图表 |
| UI 智能体操作 | 65 / 261 | 截图、密集界面、智能体安全 |
| 计数与检查 | 28 / 96 | 计数、表面检查 |

榜上 1B 以下的最好成绩是 JPT-0.8B 的 Capability 46.1（Capability = (Intelligence + Calibration) / 2）；4–9B 最好的是 Imajev-4B 的 68.0。deVision 和 Laya Vision 都还没上榜。

**v0.5 目标**
1. 正式提交并被接受上榜（满足 Jev 级的速度、成本上限）。
2. **Capability 超过榜上所有 1B 以下的模型**（当前最好 46.1）。
3. 五个用途分项都比 v0.4 显著提高（公开 300 题本地配对比较）。
4. Calibration 不低于 v0.4。

具体数值在 v0.4 的基线测出来后再定，交负责人确认。

## 辅助指标：真实照片、外部评测（不再用自造测试集当主指标）

全部按同一批题与 v0.4 逐题配对比较：

- **真实拍摄**：VizWiz（盲人用户实拍的问答，含"无法回答"判断）、RealWorldQA、NaturalBench。
- **外部综合**：MMBench-en dev、MME、CV-Bench、SEED-Bench 图片部分。
- **既有外部基准守住**：POPE、CountBench、What'sUp、laya-vision 的三个同题集合。

目标：外部综合评测平均显著提升；真实拍摄集显著提升；既有外部基准不显著退步。自造的 `test_*` 只用来防退步，不再作为进步的依据。

## 约束

- CPU 仍是主要部署场景之一。结构改动（分辨率、视觉 token、编码器）必须实测 CPU 延迟，并在榜单的速度上限内。
- 训练数据可以合成，但**进步必须在上面这些真实场景的指标上体现**；合成集上的提升不算进步。
- 评测集按图片和题目从所有训练源剔除；ImageJevBench 的封存部分只能通过提交评测，公开部分不进训练。

## 第一步

1. 跑 v0.4 的 ImageJevBench 公开 300 题，以及 VizWiz、RealWorldQA，作为基线。
2. 按分项找出差距最大的能力。预计在文档、小字、UI 截图上差距最大，256×256 的输入看不清字。
3. exp78（分辨率 256 对比 384）正在跑，它的结论直接决定 v0.5 要不要改结构。
