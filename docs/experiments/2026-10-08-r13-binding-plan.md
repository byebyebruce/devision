日期：2026-10-08。负责人要求：demo 里很简单的情况都会出错，全面考虑怎么提升，到网上找对标的模型、数据和训练方法，给出下一阶段的训练方案。轮次名 `r13-binding`（新命名规则）。

**修订 1**（2026-10-08，回应 `critic/critic.md` R13-01 至 R13-04）：筛选集与最终测试集分开；同图问两类物体与只换问题的成对题；全部失败时先停下；真实图标签规则；更正论文数字和几处过宽的说法。**负责人 2026-10-08：本项目只做研究、不商用，训练数据按能不能提升能力来选，不因许可条款排除**（发布时模型卡照常列出数据集及其条款）。

## 一、问题：模型答的是最显眼的物体，不是题目点名的物体

**现象**：三个珊瑚红的圆加两个绿方块，问"What color are the squares?"，v12 答 red（0.95）。去掉圆就答 green（0.97）；把圆涂成蓝色就答 blue。v11 也一样。

**程序化场景诊断**（`scripts/diag/binding_probe.py`，结果 `runs/diag/binding_v12.json`；300 张图，每张两种形状、两种颜色、大小随机）：

| 问法 | v12 |
|---|---|
| 只有一种形状时问颜色 | 0.987 |
| 两种形状时问其中一种的颜色 | 0.71（0.28 答成另一种形状的颜色） |
| 点名数某种形状（1–4） | 0.49 |
| "Is there a red circle?"（确实有） | 0.97 答对 |
| **"Is there a green circle?"（绿的是方块，圆是红的）** | **0.05 答对** |

- 目标物体小、干扰物大时更严重：两个小目标 + 三个大干扰物，问目标颜色只有 0.09 答对，0.87 答成干扰物的颜色。
- 目标放在图最上面或最下面，结果完全一样（都是 0.09）。这只否定了"目标在上方就更差"这种简单的位置效应，不能证明滑窗注意力机制本身没有影响。

**信息在不在视觉 token 里**：冻结 v12，在送进 ModernBERT 的 64 个视觉 token 上训一个很小的探针（每种形状一个学习到的 query，单头注意力，再接一个线性层；3,000 张训练、600 张测试，场景互不重叠）：
- 读"某种形状的颜色"：1.00；
- 读"某种形状有几个"：0.89；
- 机会水平都是 0.25。

在未压缩的 256 个 SigLIP patch 上，同一探针读颜色 0.77、读数量 0.61。这个探针没调参，这个数只说明下限。

**结论**：在合成图上，视觉编码器和投影层都把信息保留下来了。ModernBERT + 决策头没有学会按题目里的名词去取对应物体的属性，它把"红、绿、圆、方"当成一袋零散的特征。"Is there a green circle"答"有"就是典型的袋子式回答。

**和已有记录一致**：
- 第 9 轮里，合成双物体题集中训练 626 步就学到 0.998；真实物体抠图贴在灰底上也学到 0.955（`docs/experiments/2026-10-05-v9-lr-focus-plan.md`）。所以结构能学会，难的是推广到杂乱照片，以及混进大训练集后保住。
- 第 12 轮加了几万道 FigureQA / MapQA / VisOnlyQA / CLEVR，这些题多数可以靠"看最显眼的东西"蒙对，训练信号没有逼模型去绑定（训练日志 v12 一节）。

## 二、调研摘要（详见 `docs/research/binding-2026-10-08.md`）

- **对标模型**：小 VLM（SmolVLM、ModernVBERT、LFM2-VL、PaliGemma 等）都在分辨率、切图、token 数上下功夫，没有专门针对绑定的设计。和绑定直接相关的证据：
  - Foveated Probes（2026，[附录 Table 1](https://arxiv.org/html/2608.00726v1)）：冻结的 SigLIP，把全局池化换成"按问题生成 query 的注意力读出"，合成颜色-形状绑定从 3.5% 升到 93.5%；GQA 真实图成对颜色题 SigLIP + MLP 为 17.0%（oracle 33.0%），SigLIP2 + MLP 为 25.4%（oracle 37.8%）。模型、问题和计分口径都和我们不同，不能当作我们模型的上限；
  - X-VLM 等带框监督的编码器融合模型，ARO 属性绑定 0.87，CLIP 0.62；
  - FigureQA 原论文要 130 万题加关系模块才到 72%。
- **对标数据**：最对口的是**成对反事实**，即同一道题配两张只改一处、答案相反的图，并且让最显眼的物体给出错误答案。
  - 训练候选：自写生成器、GQA 还没用过的属性类题型（chooseAttr、verifyAttr、compare、sameAttr）、CLEVR-CoGenT A、TallyQA 复杂子集、PixMo-Points 两类计数、RefCOCO+ 同类干扰；
  - 只评测：SugarCrepe、ARO、What'sUp、CountBenchQA、NaturalBench、CoGenT B。
- **对标方法**：文献的主流结论是绑定靠"空间监督 / 先定位再回答"修，不靠加容量。
  - 推荐顺序：最小对照数据 > 视觉 token 级的定位辅助损失（推理时不用，零延迟）> 按问题生成的池化 token（新模块，延迟估计 +5–15 ms）。
  - 提高分辨率或 token 数、解冻 SigLIP、DINOv2、蒸馏、检测器 token：都放在后面。

## 三、做法：先短筛选，再正式训练

### 第 1 步：数据与评测（不训练）

1. **反事实合成生成器**（扩展 `binding_probe.py`，代码自写，Apache-2.0）：
   - 每张图 3–6 个物体，被问的那类不是最显眼的（面积、数量或居中程度都不占优），最显眼的物体带着一个错误候选；
   - 每个场景出 A / B 两张图，B 只改被问物体的一个属性，同一题答案相反，同批训练；
   - 题型：属性（颜色 / 形状 / 大小）、组合存在（"Is there a green circle?"）、点名计数、两处比较（"Is the red bar taller than the blue bar?"）；
   - 背景一半纯色、一半贴真实照片。
   - **防止"总选不显眼的那类"这种新捷径**（R13-02）：同一张图**两类物体都问**；显著性分三层（目标更显眼 / 目标不显眼 / 两者接近），各占三分之一；另有**只换问题、图不变**的成对题（问圆和问方，答案应不同）；改目标的属性要改变答案，改干扰物的属性不能改变答案。
   - 生成元数据里记下两个不读题目名词的基线（"总答最显眼的那类"、"总答最不显眼的那类"），报告时一并给出。
2. **真实照片题**（标签规则，R13-04）：
   - **属性题**以 GQA balanced 自带的人工核验问答为主（chooseAttr、verifyAttr、compare、sameAttr），答案来自原题，不自己推断；
   - 从场景图另出的属性题只在**同名物体在图中唯一**、目标属性有标注、错误选项是同图另一物体**已标注**的属性时才出；没标注不当作"不是"；
   - **不从场景图数物体**（场景图漏标，见 `docs/research/data-quality.md`）；计数用 TallyQA / PixMo 这类人工计数标注；
   - 沿用面积 ≥ 1.5% 的过滤和 COCO / VG 两套 id 剔除；构建报告列出各条过滤去掉多少题，并对计数、同类多实例的属性题、否定题分层抽查看图，系统性错误先修规则再重建。
3. **集合与用途**（R13-01）：筛选用 `dev_bind_*`，最终验收用封存的 `test_bind_*`，测试集在方案和 checkpoint 选择都定下来之前不打开。训练 / dev / test 按**场景族**（合成：同一场景的 A/B 和所有变体；真实图：同一张原图）隔离，重采样也按场景族。构建报告给出跨集合的身份检查。

| 集合 | 来源 | 用途 | 首次使用 |
|---|---|---|---|
| `dev_bind_cf` / `dev_bind_gqa` | 生成器留出场景；GQA **train** 中留出的一批原图 | 筛选 S0/S1/S2、选 checkpoint | 第 2 步 |
| `test_bind_cf` | 生成器另一批场景族 + 训练和 dev 都没出现的颜色 × 形状组合 | 最终验收 | 第 3 步训练后 |
| `test_bind_gqa` | GQA **val** 图（我们的留出图），同样的标签规则 | 最终验收 | 第 3 步训练后 |
| `bench_sugarcrepe_{att,rel}` | SugarCrepe 替换 / 交换属性、替换关系（val2017 图，属于我们的留出图） | 两句描述二选一 |
| `bench_whatsup` | What'sUp Controlled A/B | 介词 |
| `bench_countbench` | CountBenchQA | 新图计数 |

### 第 2 步：短筛选（worktree，从 v12 出发，每个约 2,000 步，Mac 上约 40 分钟）

同一份筛选数据：反事实合成 50% + 真实照片反事实和 GQA 属性题 30% + 回放 20%，约 1.6 万题。

| 变体 | 改动 | CPU 延迟 |
|---|---|---|
| S0 | 只换数据 | 不变 |
| S1 | S0 + 定位辅助损失：选项 / 题干位对 64 个视觉 token 的注意力，用"被问物体占哪些 token"（合成图和 GQA 场景图的框）做 KL 监督；推理时不用 | 不变 |
| S2 | S0 + 4–8 个按问题生成的池化 token：问题词向量对 256 个 SigLIP patch 做一层交叉注意力，插在视觉 token 后（**改结构，先改 spec**） | 估计 +5–15 ms，实测 |

**判定规则（看结果前写死）**，全部在 dev 集上，与 v12 逐题配对、按场景族重采样的 95% 区间。合成题的主指标是"**同图两类都问都答对**"，并按显著性三层分别报告；任何一层低于两个不读名词的基线就不算通过：

- **数据就够**：S0 在 `dev_bind_cf` 同图两类都对 ≥ 0.8（三层都 ≥ 0.7），且 `dev_bind_gqa` 提高、下界 > 0 → 正式训练用 S0 的做法。
- **需要辅助损失**：S0 合成题通过、`dev_bind_gqa` 没动，而 S1 在 `dev_bind_gqa` 上比 S0 高、下界 > 0 → 正式训练用 S1。
- **需要新结构**：S0、S1 都没让 `dev_bind_gqa` 提高，S2 提高 → 先给负责人看 CPU 延迟实测，再决定要不要用 S2。
- **都没让真实照片提高**（R13-03）：**不自动进入正式训练**。先看训练曲线和真实图样本：
  - 曲线还在升 → 只给最有希望的一个变体追加 1,000 步（上限一次），再按 `dev_bind_gqa` 判定；
  - 曲线不升 → 先查标签和训练路径（抽查题目、看 gold、看损失是否真作用在新题上）。
  - 真实照片上的冻结特征上限只是候选解释之一，需要时另提一个同一真实图集上的定位辅助对照来区分，不在本轮默认做。
- 任一变体在 `dev_mix` 上下降超过 2 个点（下界 < −2）→ 该变体不进入正式训练。

### 第 3 步：正式训练 r13-binding

- 从 v12 出发，一遍；用筛选选出的做法。
- 数据约 15 万新题 + 4 万回放：
  - 反事实合成 4 万（≤ 30%）；
  - GQA 属性类和真实照片反事实 4 万；
  - CoGenT A 2 万；
  - TallyQA 复杂子集 1.5 万；
  - PixMo-Points 两类计数 1.5 万；
  - RefCOCO+ 同类干扰 1 万；
  - 回放 4 万（其中"不存在"题至少 1 万，对应 v12 的 `test_exist` 退化）。
- 另加（负责人：研究用途，不因许可排除）：VisMin 训练集 1.5 万对（剔除 val2014 来源图）、VAW 属性负例 2 万（有显式负标注，最干净的属性绑定数据）、CounterCurate 位置 / 属性反事实 1.5 万。OVAD、Winoground、SugarCrepe 仍只评测（图片属于留出集或本来就是评测集）。
- 约 3 万步，Mac 上约 10 小时，加评测约 12 小时。

### 验收（训练前写下，看到结果后不改）

全部与 v12 逐题配对，按图片重采样 2,000 次，seed 0。

| 检查 | 规则 |
|---|---|
| **主要** | `test_bind_gqa` 提高且下界 > 0，**并且** `test_bind_cf` 同图两类都对提高、下界 > 0（三层显著性分别报告，任何一层不低于不读名词的基线） |
| 迁移（报告） | SugarCrepe、What'sUp、CountBench、`bench_lv_*`（含 ScienceQA 必须看图的 323 题）、FigureQA / MapQA dev |
| 旧能力保护 | 所有 `test_*` 与四个 `bench_lv_*` 下界 > −2；"未证明满足"和"已证明退化"分开写；`test_exist` 单独报告 |
| 概率质量警戒 | 同第 11、12 轮 |
| demo | 原来那张"三个红圆 + 两个绿方块"图，问方块颜色要答对 |
| laya-vision | `lv_report.py`，结论写进训练日志和差距文档 |

## 四、不做的事，以及原因

- **不提高分辨率或 token 数**：结构筛选 D（512 + 4×4，仍是 64 个 token，投影层只对齐了 621 步）在那个预算下没显出好处，但不能推出"分辨率不是限制"；文献里 token 数对 GQA / POPE 影响很小；CPU 延迟约翻倍。本轮先查绑定，不重开这条线。
- **本轮不解冻 SigLIP、不加 DINOv2**：合成图上信息已经在 token 里，先排除"没学会用"的原因。只有筛选判定"都不动真实照片"时才进入下一步。
- **不做蒸馏**：在 Mac 上用 7B 老师给几十万题打分要 1–2 天，老师本身的校准也没验证。
- **不加检测器或 SAM 区域 token**：CPU 代价大，收益证据弱。
