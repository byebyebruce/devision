**实施中的改动**（2026-10-08，代码在分支 `r13-binding`）：
- **S2 改为"加到原有视觉 token 上"，不再额外插 4 个 token**：插入新位置会让后面所有文字的位置后移，零初始化也做不到"第 0 步与 v12 相同"。现在每个视觉 token 加上问题词向量的平均后对 256 个 patch 做交叉注意力，结果经零初始化的输出层加回该 token。实测：给 v12 加上该模块后，答案与 v12 逐位相同，`data/r12/cpu_latency.jsonl` 上准确率相同；CPU（4 线程，机器有负载）单题 P50 180 → 175 ms，同图多题每题 96.0 → 102.2 ms（`runs/r13/cpu/`）。
- **合成图的照片背景**：COCO train2014 全部图片都在对齐阶段用过，"项目历史未见"无法满足；改为训练、dev、test 从 train2014 中互不重叠的三份图里取背景，不宣称这些背景未见过。
- **合成集规模**：训练、`dev_bind_cf`、`test_bind_cf` 各 1,200 个场景族（4,800 张图）。
- **合成数据 v2**（critic R13-I01、I03，`data/r13/synth-v2/`）：v1（`data/r13/synth/`）每个变体都重新摆放全部物体，不是最小编辑，也把不存在的组合指向另一个物体做定位。v2 每族只摆放一次：改色只改被编辑那类的实例（其余像素不变），计数只删或加一个实例；全族用同一套题（措辞和选项顺序都相同），每类问三句"Is there a <颜色> <形状>?"（本色 / 另一类的颜色 / 改后的颜色），目标被编辑时答案翻转、干扰物被编辑时不变；只有整个指代物在图里才给定位框。v1 和它上面的 v12 基线只作历史记录，所有候选比较用 v2，v12 在 v2 上重跑基线。v12 在 v2 `dev_bind_cf` 上（`runs/r13/v12-synth-v2/bind_cf.json`，数据 sha256 `1616f660…`）：同图每类都对 0.147，颜色 0.515，计数 0.364，组合存在真题 0.687 / 陷阱 0.358 / 不在场 0.782，比较 0.578；颜色 / 计数答错时 66.5% 答成最显眼那类的值；三层 0.559 / 0.417 / 0.348，门槛不通过。两种不读名词的策略：同图每类都对 0.099，三层 1.0 / 0.547 / 0.102（或反过来），门槛不通过。
- **成对同批**（critic R13-I02）：训练批次由"反事实单元"打包——同一场景族里问同一题的那几张图（基图、两种改色、计数）——每个单元整个进同一个 micro batch，单题样本补空位；步数按打包后的批次数算，续训沿用同一批次计划。
- 训练步长（MPS，45 步试跑，机器有负载）：S0 1.26 s、S1 1.19 s、S2 1.24 s，三者差别在噪声内（`runs/r13/steptime/`）。
- **v12 在 `dev_bind_cf` 上的基线**（`runs/r13/v12/bind_cf.json`，4,800 张图）：同图每类都对 0.149；颜色 0.515、点名计数 0.362、组合存在的陷阱题 0.362、组合存在真题 0.683；颜色 / 计数答错时 42% 答成最显眼那类的值。三层：目标显眼 0.484、接近 0.402、目标不显眼 0.354（不读名词的"总答最显眼"策略分别为 1.000 / 0.551 / 0.097）。

## 一、问题：模型答的是最显眼的物体，不是题目点名的物体

**现象**：三个珊瑚红的圆加两个绿方块，问"What color are the squares?"，v12 答 red（0.95）。去掉圆就答 green（0.97）；把圆涂成蓝色就答 blue。v11 也一样。

**程序化场景诊断**（`scripts/diag/binding_probe.py`，结果 `runs/diag/binding_v12.json`；300 张图，每张两种形状、两种颜色、大小随机）：

| 问法 | v12 |
|---|---|
| 只有一种形状时问颜色 | 0.987 |
| 两种形状时问其中一种的颜色 | 0.71（0.28 答成另一种形状的颜色） |
| 点名数某种形状（1–4） | 0.49 |
| "Is there a red circle?"（确实有） | 0.97 答对 |
| **"Is there a green circle?"（绿的是方块，圆是红的）** | **0.05 答对** |

- 目标物体小、干扰物大时更严重：两个小目标 + 三个大干扰物，问目标颜色只有 0.09 答对，0.87 答成干扰物的颜色。
- 目标放在图最上面或最下面，结果完全一样（都是 0.09）。上面两条是一次交互运行的观察（150 张图 × 2），逐题结果没有存盘，只作参考；生成器建好后在 `dev_bind_cf` 上按位置和显著性分层重测。这只否定了"目标在上方就更差"这种简单的位置效应，不能证明滑窗注意力机制本身没有影响。

**信息在不在视觉 token 里**：冻结 v12，在送进 ModernBERT 的 64 个视觉 token 上训一个很小的探针（每种形状一个学习到的 query，单头注意力，再接一个线性层；3,000 张训练、600 张测试，场景互不重叠）：
- 读"某种形状的颜色"：1.00；
- 读"某种形状有几个"：0.89；
- 机会水平都是 0.25。

在未压缩的 256 个 SigLIP patch 上，同一探针读颜色 0.77、读数量 0.61。这个探针没调参，这个数只说明下限。

**结论**：在合成图上，视觉编码器和投影层都把信息保留下来了。ModernBERT + 决策头没有学会按题目里的名词去取对应物体的属性，它把"红、绿、圆、方"当成一袋零散的特征。"Is there a green circle"答"有"就是典型的袋子式回答。

**和已有记录一致**：
- 第 9 轮里，合成双物体题集中训练 626 步就学到 0.998；真实物体抠图贴在灰底上也学到 0.955（`docs/experiments/2026-10-05-v9-lr-focus-plan.md`）。所以结构能学会，难的是推广到杂乱照片，以及混进大训练集后保住。
- 第 12 轮加了几万道 FigureQA / MapQA / VisOnlyQA / CLEVR 后，这些来源仍在随机水平附近（训练日志 v12 一节）。一个**未验证的假设**是：这些题多数不能靠"看最显眼的东西"区分对错，而模型只学会了那条捷径；没有对全部来源做显著性基线统计，不把它当成已证明的原因。

## 二、调研摘要（详见 `docs/research/binding-2026-10-08.md`）

- **对标模型**：小 VLM（SmolVLM、ModernVBERT、LFM2-VL、PaliGemma 等）都在分辨率、切图、token 数上下功夫，没有专门针对绑定的设计。和绑定直接相关的证据：
  - Foveated Probes（2026，[附录 Table 1](https://arxiv.org/html/2608.00726v1)）：冻结的 SigLIP，把全局池化换成"按问题生成 query 的注意力读出"，合成颜色-形状绑定从 3.5% 升到 93.5%；GQA 真实图成对颜色题 SigLIP + MLP 为 17.0%（oracle 33.0%），SigLIP2 + MLP 为 25.4%（oracle 37.8%）。模型、问题和计分口径都和我们不同，不能当作我们模型的上限；
  - X-VLM 等带框监督的编码器融合模型，ARO 属性绑定 0.87，CLIP 0.62；
  - FigureQA 原论文要 130 万题加关系模块才到 72%。
- **对标数据**：最对口的是**成对反事实**，即同一道题配两张只改一处、答案相反的图，并且让最显眼的物体给出错误答案。
  - 训练候选：自写生成器、GQA 的属性类问答（chooseAttr 等 choose 题以前已经转过，见 `scripts/data/convert.py`；verifyAttr 这类是非题因场景图漏标被 v2 排除）、CLEVR-CoGenT A、TallyQA 复杂子集、PixMo-Points 两类计数、VAW、VisMin、CounterCurate；
  - 只评测：SugarCrepe、ARO、What'sUp、CountBenchQA、NaturalBench、CoGenT B。
- **对标方法**：本轮预算优先检验数据和读出方式（空间监督 / 先定位再回答方向有多篇支持）；这不表示加容量的路线已被证伪。
  - 推荐顺序：最小对照数据 > 视觉 token 级的定位辅助损失（推理时不用，零延迟）> 按问题生成的池化 token（新模块，延迟估计 +5–15 ms）。
  - 提高分辨率或 token 数、解冻 SigLIP、DINOv2、蒸馏、检测器 token：都放在后面。

## 三、做法：先短筛选，再正式训练

### 第 1 步：数据与评测（不训练）

#### 1.1 图片身份（R13-01 补充）

建一份共享的**原图身份清单** `data/r13/identity.json`，所有集合划分和留出检查都以它为准：
- **项目训练历史**：v12 的初始化链（`v1-release-0.1` → … → `v12-ext`）各轮 YAML 里出现过的全部训练、对齐、`--val`、温度拟合文件，按当前文件读取（历史文件不是当时的快照，这一限制写进报告）；外部预训练（SigLIP2、Laya）见过什么无法追溯，不作声明。
- **身份归一**：COCO 与 VG 的 id 用 `image_identity.json` 对齐；VisMin、CounterCurate 的编辑图继承原图 id；贴背景的合成图继承背景照片的 id；来源不明的图做 dHash（≤ 2）近重复检查。
- 每个集合标出"项目历史已见 / 未见"。`dev_bind_gqa` 和 `test_bind_gqa` **只用项目历史未见的原图**；做不到的部分标为监测集，不当作未见图证据。

#### 1.2 反事实合成生成器（扩展 `binding_probe.py`）

- 每张图 2–3 类物体、共 3–6 个，**同一张图每类都问**。
- **显著性分层按题定义**：目标类总面积 ÷ 最大的其他类总面积，≥ 1.5 为"目标显眼"，≤ 1/1.5 为"目标不显眼"，其余为"接近"；生成时三层各占三分之一。成对指标按图计一次，不重复计算。
- **三种成对对照**：
  - 只改目标属性（A/B 两张图，同一题答案相反）；
  - 只改干扰物属性（答案不应变）；
  - 图不变、只换问哪类（答案应随之变）。
- 题型：属性（颜色 / 形状 / 大小）、组合存在（"Is there a green circle?"）、点名计数、两处比较。组合存在和计数的 B 图按题型各自定义（如计数 B 图增删一个目标），不机械套"只改颜色"。
- 背景一半纯色、一半贴真实照片（照片取项目历史未见、且不在任何 dev / test 里的 COCO train2017 图）。
- 元数据记下两个不读名词的基线（"总答最显眼的那类"、"总答最不显眼的那类"），报告时一并给出。
- **组合留出只对本生成器有效**：v12 已训练过 CLEVR 3.5 万和 CLEVR-Math 1 万，不声称模型从未见过某种颜色 × 形状。

#### 1.3 真实照片题（R13-04 续审）

GQA 的问答是从场景图**自动生成**的（[GQA 官方](https://cs.stanford.edu/people/dorarad/gqa/about.html)），不是人工核验，所以原题 gold 也有场景图漏标的风险。规则：
- **choose 类**（chooseAttr、chooseName 等，二选一）：两个选项都有标注依据才保留（正确选项是目标物体的已标注属性，另一个是同图另一物体的已标注属性或与正确属性互斥的同类属性）。
- **verifyAttr 等是非题**：只保留答"是"的，以及答"否"且目标物体在**同一属性类别**（颜色、材质……）里有一个不同的已标注值、被问的值没有标注的；不从"没标注"推断"否"。
- **多实例**：题目点名的物体在场景图里同名唯一；能映射到 COCO 类别的，还要求 COCO 实例数为 1（同 `v2_vg_relation.py` 的做法）。做不到就剔除。
- **不从场景图数物体**；计数用 TallyQA / PixMo。
- 面积 ≥ 1.5% 的过滤、两套 id 剔除照旧。按图片、题 id、细分题型报告**真正新增**的题（扣掉以前训练文件里已有的 GQA 题 id）。
- 分层看图抽查：计数、同类多实例属性题、否定题各 30 题。发现系统性错误先修规则再重建；抽查结果只说明所抽样本。

#### 1.4 新来源的转换定义（R13-05）

| 来源 | 原字段 → 题目 → gold | 不能做的 | 质检 |
|---|---|---|---|
| VAW（train_part1/2） | 实例的正 / 负 / 未知属性三态 → 只在该类别在图中唯一时出题："What color is the dog?"，正确项是正属性，干扰项取该实例的**显式负属性**，优先用同图其他物体有的颜色；是非题只用正属性或显式负属性 | 未知不当负；一个实例没有棕色不推出"图中没有棕狗" | 唯一性复核（VG + COCO 实例数）；抽查 30 |
| TallyQA 复杂子集 | 原始 train 的 `issimple=False`（60,879 题，其中人工的 3,902），保留 `data_source` → 计数选择题，干扰项包含"不加限定时的数量" | 不用 Cauldron 版（没有 `issimple`） | 能否凑足 1.5 万未验证，不足就不足 |
| PixMo-Points 两类计数 | 同图两条有效 counting 标注 → 问 A 的数量，选项含 B 的数量；保留原限定语 | 空 count / 空 points 不当"不存在"；不把"右边书架的书"改成"书" | 复用 `ext/pixmo_points.py` 的过滤；抽查 30 |
| VisMin 训练集 | 按 `source_image_id` 恢复原图与编辑族；两张图各问同一句"Is it true that …?"，一真一假 | HF 是展平行，不能按行数算对数 | 按编辑类别（物体 / 属性 / 计数 / 空间）各抽 30 对，某类不一致 > 15% 就剔除该类 |
| CounterCurate | 位置类用镜像图（可靠）；属性类是生成模型重生成的图 | 原 Flickr30k 图要单独获取；去掉缺图和占位 | 属性类抽 100 对，图文一致 < 90% 就不用属性类（作者自己的抽查是 84.67%） |
| RefCOCO+ | — | — | **本轮不用**：指代表达转成全图决策题需要另设计，且易由表达式泄露答案 |

所有来源的图都过 1.1 的身份清单；不为凑配额放宽规则，筛选后不足就不足，不复制补齐。

#### 1.6 训练入口的样本校验（ENG-05）

在任何训练之前：加载数据时校验题型、gold 键与选项一致、概率有限非负且和为正，错误报文件 / 行 / id；去掉"概率和为 0 时换成均匀分布"的静默处理。

### 第 2 步：短筛选（worktree，从 v12 出发）

**三个变体共用的配方**（写进同一个 YAML 模板，只差下表的开关）：
- init `runs/v12-ext/stage2`；同一份筛选数据（反事实合成 50% + GQA 真实照片 30% + 回放 20%，约 1.6 万题），seed 0；
- 2,000 步，micro batch 8；学习率 new / head 5e-5、LoRA 1e-4（与 v12 相同，YAML 显式写出，不靠默认值），warmup 100，余弦衰减到 0；
- **成对同批**：训练顺序按场景族打乱，同族的题相邻（加一个 `group` 字段，打乱时保持同组相邻）；
- 取**最后一步**的 checkpoint，不做中途选择；温度在 `dev_mix` 上拟合；
- 记录每步耗时。

| 变体 | 定义 | 训练额外开销 | CPU 推理 |
|---|---|---|---|
| S0 | 只换数据 | — | 不变 |
| S1 | S0 + **定位辅助头**：取编码器最后一层（第 28 层是全局注意力，所有位置互相可见）的输出；query = 题干 token（第一个选项标记之前的文字）输出的平均，key = 64 个视觉 token 的输出，各过一个线性层到 256 维，点积后在 64 个视觉位置上 softmax；目标 = 题目点名物体的框经同一 letterbox 映射到 8×8 网格的覆盖比例（多实例取并集，归一化，再与均匀分布按 0.9 / 0.1 混合平滑）；损失 KL(目标 ‖ 预测)，权重 0.5；只对有框且目标存在的题计算（合成图全有；GQA 用原题 semantic 里的物体框；不存在题、无框题不算） | 一个小头，读输出不读注意力权重（SDPA 不返回权重），估 < 5%，实测 | 不变（头只在训练时用，保存时不进推理路径） |
| S2 | S0 + **问题条件 token**：题干 token 的**输入嵌入**平均（不经过编码器，所以能在编码前算）→ 线性层 → 4 个 query（4 个可学的基向量加上这个偏移）；对 256 个 SigLIP patch（线性投到 1024 维）做一层 8 头交叉注意力 → 4 个 token 插在 64 个视觉 token 之后；输出线性层**零初始化**，所以第 0 步与 v12 完全相同，不需要单独的对齐；新模块学习率 1e-4；SigLIP 特征每张图算一次，条件 token **逐题**计算；保存 / 加载包含新模块 | 估 +5–10% | 估 +5–15 ms，同机同线程实测单题和多题 |

**放行规则（看结果前写死，R13-06）**。所有指标在 dev 上，与 v12 逐题配对、按场景族重采样 2,000 次的 95% 区间：

1. **资格**：一个候选只有同时满足以下三条才合格——
   - (a) `dev_bind_cf`"同图每类都答对"≥ 0.8，三层显著性各 ≥ 0.7。计分题集**对模型、两个不读名词的策略和门槛相同：颜色题和计数题**（每张图对两类都问）；"同图每类都答对"= 同一张图同一任务两类都对的比例，分层准确率按题算。组合存在题（真 / 陷阱 / 不在场）和比较题单独报告，不进门槛（批注：critic R13-I04；用全对、总答显眼、总答不显眼三种确定性预测自检，全对通过、两种策略都不通过，`scripts/r13/test_bind_report.py`）。（不读名词的两种策略在某一层是 1.0、在另外两层 ≤ 0.55，所以"三层各 ≥ 0.7"本身就排除了它们；修订前写的"三层都高于两个基线"在"目标显眼"层要求超过 1.0，不可能满足，2026-10-08 看到 v12 基线后更正，候选结果出来前）；
   - (b) `dev_bind_gqa` 相对 **v12** 提高，下界 > 0；
   - (c) `dev_mix` 相对 v12 下界 > −2，且没有任何来源下降 ≥ 3 个点且上界 < 0。
2. **在合格候选里选**：按 S0 → S1 → S2 的顺序取最简单的；只有更复杂的那个在 `dev_bind_gqa` 上相对更简单的合格候选也显著更好（下界 > 0）才选它。S2 入选前先给负责人看 CPU 延迟实测。
3. **没有合格候选**：不进入正式训练。
   - 某个变体的 `dev_bind_gqa` 训练曲线最后 500 步仍在上升 → 只对它追加一次：从它的末步 checkpoint 开始，再训 1,000 步，warmup 50，同样的峰值学习率，余弦衰减到 0；然后按同样的资格条件再判一次，不再追加。
   - 曲线不升 → 先查标签和训练路径（抽查题目和 gold、确认辅助损失 / 新模块确实有梯度）。
   - 真实照片上"冻结特征不够"只是候选解释之一，需要时另提实验，不在本轮默认做。
4. 若负责人想有意接受某个取舍（例如合成题过线、真实图没过），那是负责人单独的决定，不是默认放行。

实施前的功能验证（少量合成样本，不跑完整 2,000 步）：框到 8×8 目标的映射、辅助损失有限且非空、梯度进入目标参数、成对采样相邻、多题请求与逐题输出一致、保存再加载输出不变。

## 四、不做的事，以及原因

- **不提高分辨率或 token 数**：结构筛选 D（512 + 4×4，仍是 64 个 token，投影层只对齐了 621 步）在那个预算下没显出好处，但不能推出"分辨率不是限制"；文献里 token 数对 GQA / POPE 影响很小；CPU 延迟约翻倍。本轮先查绑定，不重开这条线。
- **本轮不解冻 SigLIP、不加 DINOv2**：合成图上信息已经在 token 里，先检验"没学会用"这个解释。这是本轮的预算选择，不表示这些方向无效。
- **不做蒸馏**：在 Mac 上用 7B 老师给几十万题打分要 1–2 天，老师本身的校准也没验证。
- **不加检测器或 SAM 区域 token**：CPU 代价大，收益证据弱。

## 六、筛选结果与下一步提议（2026-10-09；修订：第 5 轮评审 R13-I08–I10，待负责人决定）

**结果**（详见实验记录 `docs/experiments/2026-09-30-rlcd-plateau.md` 末尾"绑定短筛选没有合格候选""筛选结果的排查"及"更正：筛选结论与排查的证据边界"三节；产物 `runs/exp13-s*/`、`runs/r13/screens/`、`runs/r13/diag/`）：按第 2 步写死的放行规则，S0、S1、S2 与 S2 的一次追加（`exp13-s2x`，按规则 3 触发：S2 的 GQA 监测在 1,500 → 2,000 步从 0.668 升到 0.676）都不合格，不进入第 3 步。S2 是唯一满足 (b) 的（+2.61 [+0.33, +4.90]），追加后为 +2.14 [−0.26, +4.63]；S2 对 S0 +1.14 [−0.41, +2.81]，不能归因于新模块。合成"同图同任务两类都对"0.15 → 0.51–0.54，未到 0.8。(c) 通过，但 S2 的 A-OKVQA −2.78 [−4.96, −0.60] 有退步（未触发联合警戒）。

### 提议二的执行设计与解读规则（负责人 2026-10-09 批准；运行前写下）

- 代码与配置：分支 `r13-binding` 的 `scripts/r13/hard_slice.py`、`configs/exp13-hard.yaml`（ccd755c）。
- 训练组：S2 在筛选中**实际训练过**的合成族里，照片背景且基图中某类有 3–4 个物体的全部 61 族中取 60 族（seed 0）：240 张图、2,640 题，其中正确答案为 three / four 的计数题 262 道（`data/r13/hard/hard_train*.jsonl`）。
- 对照组：`dev_bind_cf` 中同样条件的 439 族里取 60 族（240 张图、2,640 题；计数 3–4 的 255 道），场景从未训练过。
- 训练：从 S2 末步 checkpoint 出发，对训练组重复 3 遍 = 990 步，warmup 50，学习率同筛选，余弦到 0；视觉主干冻结，结构同 S2。每 250 步在四个集合上监测（训练组 / 对照组 × 计数 3–4 / 全部题）以及 `dev_mix`。
- 解读（以末步为准；对照组的变化与起点 S2 逐题配对、按族重采样 2,000 次）：
  - **拟合**：训练组计数 3–4 ≥ 0.8 → 该配方能拟合这批困难题；< 0.6 → 重复训练也拟合不了（结构 / 读出 / 优化在这一切片上受限，具体哪一个仍待区分）；之间 → 部分拟合。
  - **迁移**：对照组计数 3–4 相对起点提高且下界 > 0 → 拟合的东西能迁移到新场景；否则写"未证明迁移"。
  - 组合：能拟合但未证明迁移 → 泛化问题仍在；两边都弱 → 原因待区分，**不能**据此认定视觉特征里没有计数信息。
  - 只作诊断，不产生候选，不与筛选门槛比较；`dev_mix` 只看有没有明显遗忘。
