## 1. 当前起点与目标

当前模型：r15-vision，训练完成 10,235 步，seed 1，r14b 的 81,875 题混合；SigLIP2 顶部 4 层及最终归一化层曾以 `5e-6` 更新。模型发布标签 v0.3；发布权重 SHA256 为 `110fea95889947c373258c88a396ad3eec574971815ee437b9c7cc3df8a5d2d5`。本地训练 checkpoint 与导出包的文件哈希不要求相同，执行时分别记录本地权重与配置哈希，并验证同一固定输入的起点概率。

下表的成绩是已观察结果，“下一阶段目标”是工程目标，不是收益预测，也不直接替代后面的统计判定。变化单位为百分点。

| 能力 / 风险 | v12 | r15 / v0.3 | 下一阶段目标 |
| --- | ---: | ---: | --- |
| CountBench 准确率 | 18.94% | 35.64% | 保留主要收益；相对 r15 的损失容忍边界为 2 点，不能只凭点估计过线宣称守住 |

| VSR 准确率 | 67.92% | 66.15% | 恢复到接近或超过 v12，同时检查正负类表现 |

CountBench 倒序准确率也从 19.76% 提高到 37.68%，“两种顺序都答对”从 15.07% 提高到 26.48%。所以 r15 的收益不能解释为只记住选项位置；顺序稳定性是收益之外需要修复的另一项问题。VSR 正例召回下降约 5.31 点，而负例正确数增加，不能只看总准确率。What'sUp NLL 从 1.4724 上升至 1.4909、ECE 从 0.2089 上升至 0.2447，下一轮还需保护概率质量。

## 2. 为什么先做这个小实验

本次对现有 JSONL 的只读统计显示：

- r15 的 VSR 共 1,053 题、978 张图，其中显式 VSR 块 1,000 题；现有 `data/ext/train_mix.jsonl` 的 VSR 训练池有 5,400 题、3,716 张图。可以提高这类训练信号的占比，但大部分属于历史回放，不能称为首次学习的新图片。
- r15 的 A-OKVQA 已有 2,475 题、2,463 张图，与上述训练池的 A-OKVQA 数量一致。“多抽 A-OKVQA”主要增加曝光权重，不能直接增加知识覆盖或数据多样性。
- r14 的计数转换器已在生成数据时打乱候选一次；`rlcd._items` 和 `question_item` 保留该顺序，训练重排的是题目 / batch。单 epoch 中再随机一次候选，并不让同题获得多种顺序监督。

因此，下一轮有两个待检验问题：修复与回放混合能否找回旧能力；在相同曝光次数下，同题第二种排列能否降低顺序敏感。A 组对 r15 观察整套修复配方，B 对 A 隔离排列增强的增量作用。A 对 r15 同时改变了数据配比、训练预算、学习率和可训练参数范围，不能单独归因于某个数据源。

[ICML 2024 的置换研究](https://proceedings.mlr.press/v235/zong24b.html)发现视觉语言模型也受候选排列影响，并在纯文本模型上验证过全排列微调的改善。它支持做小实验，不证明我们每题两种顺序必然有效。实现与研究边界见[调研笔记](../research/2026-10-14-option-order-training.md)。

暂不把以下方案叠加进本轮：扩大模型 / 分辨率、S2、继续大幅解冻、教师 KL 或新的大规模数据下载。理由是缺乏本轮所需的直接证据，并且会降低对照的可解释性：

- [exp18](2026-10-13-exp18-distill-plan.md) 的 v12 教师约束未改善预写的旧能力 NLL 主指标（D−B 约 +0.0007，区间跨 0）。这只否定该设置，不否定所有蒸馏；不能直接把同一设置作为默认修复方案。
- [exp15](2026-10-12-exp15-steps.md) 的 CoSyn 科学块和 GQA / VisMin 绑定块没有达到短程准确率目标。照搬相同来源与配方缺少新信息收益。
- [历史记录](2026-09-30-rlcd-plateau.md)中的 512 分辨率迁移、磁铁图学习和 R13 S2 长程均有明确限制或损失，不能预设扩大输入或加模块一定解决问题。

## 3. 固定训练配方：8,000 道原题，各曝光两次

以下是待构建配额，不是已经生成的数据。按 `(canonical image, 原始问题身份)` 去重后选 8,000 道原题；每题两次，共 16,000 题次。来源之间重叠时先去重再补足，统计题数、图片数和场景族数。不能将两视图计为两份新数据。

| 训练块 | 不同原题 | 比例 | 构造要求 |
| --- | ---: | ---: | --- |
| 计数保护 | 1,600 | 20% | 宽候选 600、窄候选 500、原格式 500；宽候选的 0–2 / 3–5 / 6–10 三桶各 200，保留来源覆盖 |
| VSR 修复 | 1,200 | 15% | true / false 各 600，优先不同图片；按能核实的关系类型分层，不只增加正例 |
| A-OKVQA 回放 | 800 | 10% | 从已有 2,475 题均匀抽取不同题，尽量一图一题；不根据测试错题挑选 |
| 存在性保护 | 1,200 | 15% | 是 / 否各 600，同时检查物体类别与正负例先验；抽查负例标注遗漏 |
| 科学保护 | 800 | 10% | ScienceQA 400、AI2D 200、TQA 200；报告需要图 / 可只靠文本的覆盖，不盲目追加 CoSyn |
| 一般能力保护 | 800 | 10% | VQA yes/no 200、GQA 200、VQA choice / V7W 各 100、关系与大小各 100；排除已进其他块的同题 |
| 扩展能力保护 | 1,200 | 15% | r14b 的 10 个扩展来源各 120；与计数块一起覆盖另外 3 个 dev_ext 来源 |
| 左右镜像保护 | 400 | 5% | 200 个完整原图 / 镜像题对，来自既有训练池，原题对不可拆散 |
| **总计** | **8,000** | **100%** | 展开后两组均为 16,000 题次 |

这是有限预算内的候选配方，不是最优比例。VSR 权重明显高于 r15，可能损害其他能力，必须按第 6 节保护；A-OKVQA 增权可能只改善训练熟悉度，不预先解释成推理提升。扩展回放比例低于 r15，因此 dev_ext 来源等权结果必须保留。

制作前重新核对所有历史训练、对齐、校准、验证和最终评测的图片身份，包含 COCO / VG 映射与镜像原图映射；禁止把评测图片重新加入训练。抽样不使用候选模型的评测错误。上述目标数量尚未经过这次排除与去重后的可用性核对，若不足，先报告缺口并修订方案，不能静默重复填充。各关系细分标签必须能回溯源标注；不能把现有空 `axis` 字段当作完整关系分类。

## 4. A/B 两组具体如何做

| 项目 | A：重复回放对照 | B：候选排列增强 |
| --- | --- | --- |
| 初始化 | r15 最终模型权重，新的优化器与调度器 | 完全相同 |
| 原题 / 图片 / 题次 | 同一 8,000 道原题，每题两次 | 完全相同 |
| choice 的两次曝光 | 原排列、原排列 | 原排列、一个保证不同的排列 |
| noul 的两次曝光 | 原样两次 | 原样两次，不改 false / true 语义 |
| 目标函数 | 现有 RLCD + gold 监督 | 完全相同，无新增一致性损失 |
| 组批、种子、预算与参数 | 固定 | 与 A 相同 |

两选项 choice 的第二视图互换；更多选项使用独立的制数 RNG，随机取一个不同排列，不专门复刻评测倒序。只调整 `criteria` 的枚举顺序，候选键、描述、问题、图片、state_text 和语义 gold 都保持对应。需要比较概率时按候选键映回同一语义，不能按位置直接比较。

A/B 的样本 ID 和问题 ID 对应关系、样本排列、group 大小一致。不同视图使用不同样本 ID，保留 canonical 原题身份；`qid` 不加视图后缀，以免现有 `(group, qid)` 组批把同题视图拆开。同题两视图放入同一 group；镜像原题对展开后为 4 题的完整组。核对现有分组无意外大于 micro_batch 的单元。两组按同一原题映射导出实际 batch 清单并比较；如果因分组产生不足 8 题的 batch，按实际计划统一步数，而不是伪称必为 2,000。

制数 RNG 不消耗训练 RNG；先核对每道 choice 的 token 长度、候选 marker 数量和截断行为在置换后正确，避免额外改变噪声张量形状。换序本来就会改变训练 logits，因此不要求 A/B 第一步训练 NLL 相同；要求**同一未换序监控清单的第 0 步概率**匹配，最大绝对差不超过 `1e-5`。先做 A，第 0 步可作为 B 的 `start_check`；另外核对 A 的起点确为 r15 权重。

拟采用如下超参，两组一致，实施前冻结一次，不根据中途分数扫参：

| 参数 | 建议值 | 用意 |
| --- | --- | --- |
| 初始化 / resume | r15 最终权重；不加载旧 resume.pt | 以已发布模型为新起点，不继承已结束的一轮调度器 |
| epochs / micro_batch | 1 / 8 | 约 2,000 步；题次与实际 batch 计划一致 |
| SigLIP | `vision_unfreeze_top=0` | 保留 r15 已学到的视觉权重，本次冻结，先检验决策侧小修复 |
| projector `lr_new` | `1e-5` | 比 r15 峰值小 |
| decision head `lr_head` | `5e-6` | 比 r15 峰值小 |
| ModernBERT LoRA `lr_lora` | `2e-5` | 温和继续训练；r=16、alpha=32，文本原始权重继续冻结 |
| warmup / schedule | 100 步 / 全预算 cosine 到 0 | 为这次约 2,000 步重新定义完整调度 |
| RLCD | sigma 0.4 → 0.1，group_size=4 | 保持现有目标，避免同时更换学习算法 |
| S1 / S2 / distillation | 关闭 | 无新模块、无教师前向 |
| seed / precision | 1 / 当前 MPS FP32 | 两组同设备、精度；不把 CUDA / BF16 混作实验变量 |
| monitor / save | 0、1,000、末步 / 每 500 步 | 周期只跑必要监控，保留第 0 步逐题明细 |

冻结视觉是为了降低成本和控制继续遗忘，不代表已证明视觉层导致退化，也不会把视觉权重恢复为原版 SigLIP。若任务损失下降而需要看图的指标始终不改善，先判断该小实验失败，不能临时继续解冻并沿用同一实验结论。

## 5. 监控清单、统计单位与校准

每次周期评测用固定清单；A/B 与 r15 第 0 步基线同题、同顺序、温度 1。不在训练中调用全量外部 bench。

| 清单 | 题数 | 用途 |
| --- | ---: | --- |
| `data/r13b/val.jsonl` | 3,892 | 总体；直接切出 VSR 280、A-OKVQA 503，避免重复推理 |
| `data/ext/dev_ext.jsonl` | 3,408 | 13 个来源等权 macro accuracy / soft-gold NLL |
| `data/r13b/panel_science.jsonl` | 577 | 科学保护 |
| `data/r13b/panel_exist.jsonl` | 736 | 存在性、正负召回保护 |
| `data/v6/dev_lr_pairs.jsonl` | 1,544 | 原图与镜像的准确率、两题均对 |
| `data/r13b/count_wide.jsonl` + `data/v11/dev_count_transfer.jsonl` | 300 + 300 | 宽 / 窄计数保护；共享图片，不能当成 600 张独立图 |
| 上述宽 / 窄计数各一个倒序视图 | 300 + 300 | 顺序变化率与两种顺序都答对；主指标只取宽候选，窄候选作保护与报告 |
| **每次合计** | **11,357** | 第 0 步、1,000 步、末步 |

上述 val 明细存在重复 `(sample_id, qid)`，按现有 `same_start` 的 occurrence 配对，并逐副本核对图片、gold 和候选；不默默去重。VSR dev 与 val 同题，计数等面板与校准池也有重叠。所有这些是监控 / 校准用途，不称为新 heldout。A-OKVQA 503 题只是现有池上的监控规模，不能保证检测出约 1 点收益。

统计约定：accuracy 依现有 gold / 预测定义；VSR 同时报 TPR、TNR、`BA=(TPR+TNR)/2`、预测 true 比例和 NLL；概率指标使用原 soft gold。扩展 macro 先算每个来源指标再对 13 来源等权，不按题量加权。单个面板按 canonical 图片做配对 cluster bootstrap，镜像按原图聚类，重复题和所有顺序视图跟随原图一起抽样。跨面板联合指标如需计算，要保留共享图片的抽样关联。固定 10,000 次重采样及种子，原始差值判断不四舍五入。

顺序变化率 F：同题原顺序与倒序的**候选键 argmax 不同**的比例，概率先语义对齐。J：两种顺序均答对比例。相同最高概率的并列项用固定候选键顺序打破并列，记录并列率，避免枚举顺序自身制造翻转。

训练期用 T=1 分离权重变化与校准变化。现有训练末尾自动拟合温度可以保留，两组仅用同一个既有 val；不得拿最终 bench 调温度。选择依据仍用固定 T=1 的末步明细。最终产品比较再同时报告各自实际温度的概率质量与 T=1 诊断，不能把温度变化当作视觉能力变化。

## 6. 写死的小实验出口与停止条件

这是**实验筛选**，不是自动替换 v0.3 的发布门槛。唯一固定读点为末步，不从中间 checkpoint 挑最好一刻。

主要问题是 B 的排列增强是否值得继续。建议同时满足：

1. 宽计数面板的 F：B−A 点估计 ≤ −5 点且 95% 区间上界 < 0；B−r15 的区间上界也 < 0。
2. 宽计数原顺序准确率、倒序准确率、J，以及窄计数原顺序准确率，相对 r15 的差值区间下界都 > −2 点。仅仅一致地答错不能通过。
3. VSR BA、A-OKVQA、科学、存在性、镜像、ext macro 没有相对 r15 的“点估计 ≤ −3 点且区间上界 < 0”损失；各块 soft-gold NLL 没有“增加 > 0.02 且区间下界 > 0”警戒。**本条只是小实验损害筛查，不证明每一项均已守住 2 点非劣边界。**

VSR 召回恢复与 A-OKVQA 恢复为预先记录的次要目标：报告 A−r15、B−r15；VSR 必须同时看 TNR / BA。未达到不能宣称已修复这两项。B 若只改善顺序稳定，可作为该用途继续验证，不以此宣传全面恢复。

第 1,000 步只作运行安全检查：任何保护块准确率点差 ≤ −5 点且区间上界 < 0，或出现非有限输出 / 设备失常，建议按预先编排停止该组；较小差异记警告，到末步按规则统一判断。周期警报存在多重观察，不能把这里的名义区间当作控制了整个实验误报率的显著性检验，也不因一次 300 题面板的边界波动追改阈值。

出口：

- B 通过上述三项：值得做一次复现和最终检查；不是直接宣布下一版本。
- B 未通过，但 A 对 VSR / A-OKVQA 有收益：说明回放配方值得另立小实验，不能把它当作排列增强成功，不能临时重定义本轮主指标。
- F 降低但准确率 / J 下降：失败，不靠“更稳定”掩盖损伤。
- A/B 都无改善或明显损害：保留 v0.3，本轮结束；先看分层错误与数据，不自动加步数或扫权重。
- 区间宽、证据不足：明确保留不确定性。优先核对面板和误差，不把“未显著变差”写成等效，也不为了过门槛直接扩训练。

## 7. 小实验之后如何投入算力

若 B 通过，固定相同原题池和规则，再用 seed 2 重复 B 一次。两次方向一致且各自无损害警戒，才进入发布候选检查。只复现 B 只能检查该配方稳定性，不能声称 B−A 的因果收益已经跨种子复现；若要作该声明，需连 A 的 seed 2 一起跑。禁止在两个种子里事后挑最高分作为唯一证据。

随后对候选一次性执行既有完整外部评测和原图 / 配错图 / 候选倒序对照，对比 r15 为主要基线、v12 为历史参考。正式保护集合建议沿用 `scripts/r14/accept.py` 的 PROTECTED，再加 CountBench 与 What'sUp，accuracy 差值下界需 > −2 点，并检查原来的 NLL 警戒；这是**提议的新版本门槛**，需要在最终检查前冻结。r14 原来的主条件是计数继续提升，不适合本轮稳定性目标，不能直接复用它的 `candidate` 布尔值。

全量比较包括 VSR 正负类与关系分层、A-OKVQA、ScienceQA 的需图切片、计数答案范围和来源、What'sUp 概率质量。统计上只够支持“尚未守住”时如实保留；负责人可以取舍采用，但不能改写自动判定。旧 bench 已适应性使用这一限制继续披露。

可并行筹备一份真正新图片的确认集，先做历史身份排除再确认数量。不能把历史训练池分出一块重新命名为新测试，也不能保证现有 VSR 池仍有足够未见图片；VSR 官方划分在此前构建中已合并后重分，官方 split 名称不是隔离证明。这个清单建设不必拖住上面的有限预算筛选，但它决定我们能否提出新的泛化主张。

只有小实验有收益、末步仍有改善趋势且保护成立，才考虑较长训练。若新计划定为 4,000 步，应从 r15 权重重新开始，并预先固定 4,000 步调度；本轮 2,000 步 cosine 已到 0，不能把其 resume 直接拼接为一条预先定义的长训练曲线。更不能未经判断自动恢复到 10,235 步。

长期的下一条能力主线建议是**真实照片中的属性 / 相对关系绑定，然后才是图表阅读**。先依据 r15 错题区分物体漏检、关系方向、实体指代与文字识别，再收有困难负例、同图最小变化的真实题；使用未受训练污染的图片评估。科学专项应使用必须看图才能回答的监督，通用 CoSyn 数学计数题不能自动填补这类缺口。具体新来源和配额留给该主题，不与本次修复实验捆绑。

## 8. 执行工作量、验证与预算

建议执行者新增独立的制数 / 报告脚本及两份配置，复用现有训练器、样本校验、分组、`start_check` 和逐题明细。默认不需要修改网络或增加训练损失。

按历史 MPS 日志，冻结视觉的训练约 1.2 秒 / 步；2,000 步纯训练约 40 分钟。周期评测按过去约 0.064 秒 / 题估算，三次 11,357 题约 36 分钟，再加存盘、校准与初始化，**每组约 1.3–1.7 小时，A/B 合计约 2.6–3.4 小时**。两视图已计入 16,000 题次，没有额外 KL 前向；现有实现也不会自动复用重复图片的视觉特征。

通过后追加一次 B seed 2 约 1.3–1.7 小时，既有全套最终评测与对照约 2.5–3 小时，连同余量，建议本主题首批总机器预算 **7–9 小时**。如连 A seed 2 也复现，再加约 1.3–1.7 小时。预算不含人工标注、下载与制作新确认集；新混合的序列长度、MPS 状态会影响耗时，首个稳定日志窗口核对预计完成时间，不承诺 A100 加速倍数。
