# exp46 方案：对象差异经过查询、区域注意力与决策的因果诊断（冻结 EXP45-G；CPU 准备完成，未运行，等评论家的模型许可）

日期：2026-10-18。依据：评论家 EXP46-PREP-01..03。不训练，不改权重，不加数据。这是诊断，不是产品能力的证据。

## 问题

EXP45-G 的注意力更多落到了数字标注所在的区域，但对两个对象同字段的框分得一样多，同图 A / B 两问几乎不切换；决策也没有改善。

- "按字段条件定位"和"每个 head 的行为"都没有单独证明过。
- 本诊断用单变量干预来定位：对象差异在 查询 → 区域注意力 → 决策 这条路上，是在哪一段失效的。

## 固定输入（`scripts/exp46/select.py` → `data/exp46/units.jsonl`，sha256 `ad68597e…`）

- 48 个"图片 × 字段"单元，每个单元保留两问（A / Pair 1 在前），共 96 题。
- 分层：字段（质量 / 速度 / 距离）× 版式（原图 / L）× 划分（fit / tune）共 12 格；每格 4 个单元，其中第一对象画在左、画在右的各 2 个。
- 条件：两问的 gold 不同，且共享图片和 state_text。
- 选取：每格每侧按 sha256("set|图片|字段") 从小到大取，不看模型预测。全部格子都够数，不需要替换。
- 来源：EXP42 的四个读出集（EXP45-G 的冻结记录正是在这些集合上评的），以及 EXP45 的 readout sidecar。MANIFEST 记录了规则、全部键、来源和图片的 sha256、分布。

## 六种模式（`scripts/exp46/diagnose.py`）

只在 QuestionConditioning 这一步干预，图片、问题 token、选项、文本编码器和决策头都不变。每个单元的两问放在同一次前向（batch 2）。

| 模式 | 做法 |
|---|---|
| baseline | 模块原样，并记录中间量 |
| swap_query | 只交换两问的投影向量 p = question(q) |
| amplify_difference | c = (pA + pB) / 2，d = (pA − pB) / 2；查询改为 V + c ± αd，α = max(1, min(1000, 0.1 × RMS(V + c) / max(RMS(d), 1e-12)))，一对共用一个 α，记录是否触顶 |
| oracle_target | 在 softmax 之前把所有 head 的注意力限制到被问字段框覆盖的 patch，框内重新归一化（只有这一个模式和下一个模式用框） |
| oracle_other | 同上，但限制到另一对象的同字段框 |
| no_residual | 模块加回的残差置零，原来的 64 个视觉 token 保留 |

- 模块的 forward 只在 `with` 块内替换，每个模式结束后恢复；结束时核对模块权重没有变化。
- **baseline 复现**：先跑不打补丁的前向（即 decide 的路径），要求与 G 冻结的 raw 概率最大差 ≤ 1e-5、预测一致，否则停止诊断。另外记录插桩后的 baseline 与不打补丁前向之间的差。
  - 风险：冻结记录是按图分组请求的（同一请求里可能有其他题），这里是每次 2 题，padding 不同。理论上结果只差浮点误差；如果在 MPS 上超过 1e-5，按规则停止并回报，不放宽阈值。
- **逐题记录**：
  - 概率、预测、对错；
  - 每个 head 在 query 上取均值的注意力，在被问框 / 另一对象框上的质量（按 head 和 head 均值）；最高 patch；
  - A / B 两问注意力的 L1；
  - V、残差的 RMS，p 的范数，两问差分 d 的 RMS，α；
  - 两问输入里不同 token 的位置。
  - query-key 的"对象差分分数"没有在模块之外重算，记为 missing。
- **汇总**（按模式，以及 split / layout / field）：答对数、两问都对的单元数、目标框 / 另一对象框质量、两问都更偏向自己目标框的单元数、A / B 最高 patch 不同的单元数，以及相对 baseline 的错→对、对→错、预测改变。
- 样本小，只作诊断，不作泛化或发布证据；需要区间时在模型结束后另算。

## 解读（预写）

- 放大对象差异后，自动区域选择被救回（两问都更偏向各自目标框），且普通概率和读数也朝正确方向变：下一步优先检验查询的尺度或池化。
- 只有 oracle 救回：下一步优先检验问句到区域的学习。
- oracle_target 优于 oracle_other：只说明在 oracle 路由下，这个冻结模型有利用目标区域的空间；不证明自动定位、可读性或迁移已解决。
- oracle 和 no_residual 对决策的影响都很小：先研究这个分支到决策的使用，不继续增大 region_weight。
- 混合或都不支持：给出精确结果和未排除的解释，不延长、不换样本、不启动训练。

## 第 1 轮评审补正（EXP46-R1-01..04）

- **R1-01 插桩保真**：每个单元先跑不打补丁的前向，再跑插桩 baseline；插桩 baseline 要概率有限、与不打补丁前向和 G 冻结 raw 记录的最大差都 ≤ 1e-5、预测一致（`baseline_check`）。不满足就立即停止，该单元的其余模式都不跑。
- **R1-02 追踪量**：每题写入（干预前的量）原始 q 的范数、两问 q 的差分 RMS、p 的范数、d 的 RMS、RMS(V + c)、是否零差分、α 和是否触顶，以及 input_ids 和 question_mask 的 sha256、两问不同 token 的位置 / id / 解码。残差分为"计算出的"（residual_rms_computed）和"实际加上的"（residual_rms_applied；no_residual 为 0）。α 可以用 vc_rms / d_rms 复算。
- **R1-03 incomplete**：明细逐单元追加写入，status.json 逐单元更新；中途停止时写下原因和报告。run.sh 在有界运行之后，总会不加载模型调用一次 `--finalize`：只有六种模式都覆盖了全部 96 题才是 complete，否则为 incomplete，并写明各模式完成数和缺项数。
- **R1-04 输入身份**：在加载模型之前，按 data/exp46/MANIFEST.json 核对 units、四个来源、sidecar 和 48 张图的 sha256，START 记录 MANIFEST 的 sha 和核对结果；逐题核对选题、来源和冻结记录的图片、gold、选项顺序一致，不一致即拒绝。在真实数据上（不加载模型）核过：96 题，不一致 0。
- 预算说明修订：48 次不打补丁的前向（batch 2）+ 6 种模式 × 48 次（batch 2）= 336 次 batch 2，即 672 次题目前向；总时长上限仍是 10 分钟，单次，不重试。

## 运行（`scripts/exp46/run.sh`）

- **启动前检查**：没有其他模型进程；`freeze.py check runs/exp45-g`；units 和 regions_readout 的 sha；runs/exp46 原本不存在。
- **截止**：启动后 10 分钟，最后 60 秒留给报告；一次有界运行（TERM，15 秒后 KILL）；不重试。
- **规模**：96 题 × 6 种模式 = 576 次题目前向（每次 2 题，共 288 次），加 48 次不打补丁的 baseline。估计加载约 0.5 分钟，前向约 1–2 分钟。

## CPU 验证（`scripts/exp46/test_exp46.py`；第 1 轮补正后 11 项，新增的 4 项在列表末尾）

1. 插桩的 baseline 等于模块自身的计算（输出层非零）；no_residual 原样返回 V。
2. swap 等于把另一问的词向量喂给模块；amplify 的 α 按公式计算并记录是否触顶。
3. oracle 的注意力只落在给定的 patch 上、每个 head 和 query 之和为 1；oracle_other 用的是另一对象的框。
4. 出错时模块 forward 也会恢复；不产生梯度，权重不变。
5. 选题完整且平衡：48 个单元，24 个格子各 2 个，两问 gold 不同，第一对象的左右与记录一致。
6. 在 tiny checkpoint 上完整跑通：6 种模式、baseline 复现、oracle_target 的目标框质量约为 1。
7. 冻结记录的概率被改动 1e-3 时停止（incomplete）；重复的题拒绝；冻结记录的 gold 不符时拒绝。
8. 只有插桩 baseline 的概率偏离（1e-3）时停止，该单元的其余模式都没有跑（各模式完成数为 0）。
9. baseline_check：差 8e-7 但预测翻转时拒绝；概率非有限时拒绝。
10. 改一个来源文件或一张图：在加载模型之前就因 MANIFEST 不符而拒绝，不写 START。
11. 最终明细包含全部追踪字段，α 可以复算，no_residual 实际加上的残差为 0；把明细截到第一个单元并改成 running 状态，finalize 给出 incomplete，各模式完成 2 题、缺 2 题。
