# exp17：v12 与 r14 的权重插值

日期：2026-10-13。负责人同意先试"新训练方法"的第一步（"可以"）。不训练，只做权重运算和评测；不算一轮。选择规则和采用规则在评测前写下，结果出来后不改。

## 为什么

最近几轮（r13、r14、r14b）都是从 v12 接着训，新能力和旧能力在同一组权重上相争：r14 的 CountBench +14.5 [+10.0, +18.9]，但左右 / 关系类掉 0.7–1.4 个点，五个保护集合的下界 ≤ −2，What'sUp 校准后 NLL +0.051。

微调后的模型与起点之间做权重线性插值（WiSE-FT，[Wortsman 等 2022](https://arxiv.org/abs/2109.01903)），常能保住大部分新收益、找回被冲掉的旧能力。r14 与 v12 结构相同（420 个张量，全部 FP32，冻结的 SigLIP2 两边逐位相同），可以直接插值。

## 做法

- 权重：θ(α) = θ_v12 + α·(θ_r14 − θ_v12)，α ∈ {0.3, 0.5, 0.7, 1.0}。`scripts/exp17/interp.py`，输出 `runs/exp17-interp/a030` 等。
- 温度：每个 α 在 `data/r13b/val.jsonl` 上重拟（`devision-calibrate --in-place`），和基线 `runs/r13b-v12-base/stage2-recal`（v12 在同一 val 上重拟）、r14 训练时拟温度的口径相同。
- α = 1.0 就是 r14 的权重，只用来画出整条曲线、补上 r14 没评过的 `flip` / `vsr` 面板，不参与选择。
- 编排：`scripts/exp17/chain.sh`，每个 α 一个只评测 YAML（`configs/exp17-a*.yaml`）。

## 第一步：在开发面板上选 α（评测前写下）

面板与 r14b 相同：`exist`、`science`、`ext`、`bind_gqa`、`count_narrow`、`count_wide`、`flip`（`data/v6/dev_lr_pairs.jsonl`）、`vsr`（`data/v5/dev_vsr.jsonl`），都是 monitoring 用途，不碰任何 `test_*` / `bench_*`。

判定用 r14b 冻结的末步面板规则（`scripts/r13b/judge.py --rules scripts/r14b/rules.json final <候选> runs/r13b-v12-base/stage2-recal`）：完整候选计数提高且下界 > 0；原格式计数、存在性、科学、绑定、扩展宏平均、VSR、镜像对的下界 > −2 个百分点；存在性误报率上界 < +2；计数、科学的 NLL 不超警戒。

**选择**：{0.3, 0.5, 0.7} 中通过全部面板规则的**最大** α。都不通过：到此为止，报告曲线，不做全量评测。

## 第二步：选中的 α 做全量评测（评测前写下）

评测集合与 r14-count 完全相同（含四个 `bench_lv_*`、对照），配置 `configs/exp17-full.yaml`（`chain.sh` 只把 `checkpoint` 换成选中的 α，写到 `runs/exp17-interp/full.yaml`）。采用规则与 r14 相同，比较对象 v12（`scripts/r14/accept.py --cand runs/exp17-interp/a<α>`）：

1. **主要条件**：`test_count_fresh` 或 `bench_countbench` 准确率提高，且差值下界 > 0。
2. **旧能力保护**：所有 `test_*`、`bench_pope`、四个 `bench_lv_*` 的差值下界 > −2 个百分点；"已证明退化"（上界 < 0）单独报告。
3. **概率质量警戒**：任一集合校准后 NLL 升高 > 0.02 且下界 > 0。

1、2 满足且 3 未触发，即作为 v0.3 候选交负责人决定；否则保留 v12。另跑 `scripts/lv_report.py` 与 laya-vision 详细比较。

## 已知限制

- α 是在开发面板上选的，第二步的测试集只看一次，不再回头换 α。
- `flip` 面板 1,544 题里 462 题也在温度拟合集里；只有 596 张原图，按题重采样会低估区间宽度（评审 R14-R1-N01；按原图复核过的 r14b 结论不变）。
- `vsr` 面板的 280 题全部在温度拟合集里，按共享题数本应标为 calibration_fit；沿用 r14b 的 monitoring 标注，和基线同一口径。
- 只有 r14 一个端点；插值有效时，"专门训、再插值回去"可以作为以后每轮的固定步骤，但这一点本实验只给一个例子。
- 按负责人"可以"直接开始，未先请评审审设计。

### 解读

- **插值的作用和预期一致**：计数收益随 α 平滑增长（+13.7 → +27.0）。α ≤ 0.7 时，除 VSR 外的面板都通过预设的保护规则（下界 > −2）；α ≤ 0.5 时这些面板的点估计都 ≥ −0.1。计数 NLL 在 α = 0.3 / 0.5 时显著下降（−0.019 [−0.031, −0.009] / −0.023 [−0.041, −0.006]，区间上界 < 0），α = 0.7 / 1.0 的区间含 0。r14 自身没过的原格式计数，在 α ≤ 0.7 时都过了。（2026-10-13 按评审 EXP17-R1-02 修订：原句"旧能力的损失随 α 减小而消失"和"下界 < 0"说过头或引错了界。）
- **挡住的只有 VSR 一个面板，现有区间不足以排除超过 2 个点的损失**：
  - α = 0.3 时 280 题里有 10 题对错改变（错→对 4、对→错 6），点估计 −0.7，下界 −2.8；α = 0.5 时 16 题改变（7 / 9），下界 −3.5。
  - 面板只有 280 题、165 张图，且全部在温度拟合集里，按图重采样的区间较宽。下界能否过 −2 取决于净差和按图的分组结构，不只是改变了多少题；这里不能说"规则只是在检验有没有题改变"。（2026-10-13 按评审 EXP17-R1-02 修订。）
  - 本实验不改规则，也不回头改判定；面板大小的问题记下来，给以后定面板时参考（同评审对 300 题计数面板的意见）。
  - 补充（评审 EXP17-R1-02 引 R14-R1-N01）：开发 flip 面板按 596 张原图把原图和镜像一起重采样，a050 为 +0.19 [−0.53, +0.91]，其他三个 α 也仍通过 flip 保护（评审在内存复算，执行者未另跑）。
- **不能说的**：不能说 VSR 守住了（区间下界确实低于 −2），也不能说它退化了（区间都含 0，α ≤ 0.5 点估计只有 −0.7）。测试集一次都没看，插值对 `test_*` / `bench_*` 的效果未知。

### What'sUp NLL 警戒：校准和权重各占一部分（评审 EXP17-R1-01，只读诊断）

What'sUp 全部是四选一。v12 发布温度 1.979，a050 是 1.879（同一 val 上重拟的 v12 是 1.892），所以正式比较的 NLL 差混合了权重变化和温度变化。用已有逐题概率按 `p ∝ p_old^(T_old / T_new)` 换算，不重新前向、不拟合温度、不在 What'sUp 上选温度；按 205 个四图场景组重采样 2,000 次：

| 口径 | v12 NLL | a050 NLL | a050 − v12 [95%] |
|---|---:|---:|---|
| 各自的实际温度（正式判定） | 1.4724 | 1.5049 | +0.0326 [+0.026, +0.040] |
| 两边都用 v12 原温度 1.979 | 1.4724 | 1.4875 | +0.0152 [+0.010, +0.021] |

（执行者独立复算，点估计与评审一致；区间端点因重采样实现不同有约 0.001 的差别。评审另给出重拟 v12 温度、T = 1 两种口径：+0.0171 [+0.011, +0.023]、+0.0624 [+0.049, +0.075]。）

- 固定为 v12 原温度时，总差中约 0.017（约 53%）来自温度变化；这个比例依赖参照温度，不是唯一的分解。
- 固定温度后差值仍是 +0.015，区间不含 0：**一部分来自校准，固定温度后权重本身仍有概率退化**。两边错题中的平均最高概率 0.481 → 0.509，支持"错的时候更自信"，但两边错题不完全相同，不能说同一批错题逐题都更自信。
- 正式判定不变：警戒按原结果仍然触发。不能因为共同温度下差值低于 0.02 就宣告原规则通过，也不在 What'sUp 上拟温度。

**状态不变**：`compare/accept_vs_v12.json` 为 `candidate=false`，开发面板的原始失败（`judge_final_panels_r14b.json`）和负责人豁免（`CHOSEN`）保留，继续保留 v12。
