从这些数字和前 18 轮的记录归纳出三个**结构性**问题（不是某一份数据缺了几千题）：

1. **监督信号本身有问题。** 每一轮都只用人工标注的 gold：数量受限（每项能力几千到几万题）、大量 0/1 硬标签、部分来源自带噪声（GQA 场景图漏标、VQAv2 标注者分歧）。后果在日志里反复出现：硬标签让 logit 走极端（r16/r17 的 POPE 过度自信，r17 答错的题一半 p > 0.99）；每加一块新能力，就要靠手工配比回放来防遗忘，而回放比例稍偏就退（r13 的 POPE、r14 的镜像、r16/r17 的 ScienceQA）。
2. **视觉读出可能是瓶颈。** 一直只取 SigLIP2 最后一层（`model.py:257` 的 `last_hidden_state`），256 px、64 个 token。Perception Encoder 论文的核心结论是「最好的视觉特征不在网络输出层」，中间层对定位、细节类任务更好；这在本项目从没试过，而且**不增加 CPU 延迟**（只是多取几层已经算出来的特征）。以前试过的 256 token、512 输入都是 2,000 步短程、数据少，结论不可靠，但成本高，放在后面。
3. **评测不全。** 「全面提升」要能被证明：本机还缺计数、What'sUp、绑定、CoGenT B；而且现有集合几乎都是本项目自己造的、已被多轮适应性使用。需要一批从没碰过的外部公开评测。

## 2. 核心思路：用一个强 VLM 当教师，给每道题一个概率分布

不再「找新数据 → 手工配比 → 训一轮 → 看哪里退了」，而是把监督信号换掉：

- **教师**：Qwen3-VL（Apache-2.0，2025-09 发布），候选 4B-Instruct（bf16 约 9 GB，本机 12 GB 能放下）和 8B-Instruct（4-bit 或 FP8）。只做一次前向，读选项字母（或 Yes / No）的 logit 得到选项上的分布，不生成文字，吞吐估计每秒 15–30 题。
- **为什么对症**：
  - 校准：教师给的是软分布，模型学到「这题不确定」，直接针对 POPE / 存在类过度自信（r18 的 label smoothing 只是均匀地软化，不知道哪题难）。
  - 遗忘：所有能力用同一个、固定的教师打分，旧能力的题也有一致的软目标（「Learning without Forgetting」的思路，但教师比 v0.3 强得多，不是在拉回旧模型的错误）。
  - 噪声：gold 与教师强烈不一致的题，是标注噪声的候选，可以降权或检查。
  - 数据量：手头已经下载的 131 GB 数据 B（Cauldron 的 AI2D / TQA / IconQA / ScienceQA 等、Objects365、TallyQA、CLEVR、VisMin、PixMo、VSR、V7W……）加上 data-n1，有上百万道选择 / 是非题。教师让这些不同来源、不同标注规范的题都用一个口径的软目标，不用再逐源调配比。
- **训练目标**：每题 target = λ·gold + (1−λ)·教师（教师先用 dev 上的 gold 拟合温度）；没有 gold 的题只用教师。λ 只取 0.5 一个值（不扫）。gold 与教师的 top-1 不同、且教师置信度 > 0.9 的题单独统计，先只报告。
- **前提要先验证（门槛，打分 100 万题之前做）**：在每个开发集上抽约 500 题，比较教师与 v0.3 的准确率和 NLL。教师在某个集合上没有明显强于 v0.3（例如 ScienceQA 看图题、VSR、计数），该集合的训练题就只用 gold。这一步大约 1 小时 GPU，决定整条路线值不值得走。

## 3. 补全评测（与教师打分并行，CPU / 网络任务）

- **本机缺的集合**：数据 B 已经下好（`data/prefetch_b.log`：131 GB、0 失败），用已有转换脚本生成 `bench_countbench`、`bench_whatsup`、`test_bind_gqa`、`test_count_fresh`、CoGenT B，v0.3 补评。
- **新加的外部公开评测**（都能映射到 noul / choice，下载小）：MMBench-en dev、SEED-Bench（图片部分）、CV-Bench（2D 关系 / 计数 / 深度 / 距离）、NaturalBench（成对的对抗是非题）、MME（是非）。按 image id / 图片哈希从所有训练源剔除（含教师打分池）。在训练前冻结评测集和验收规则。
- 教师也在这些集合上评一次，作为「上限」参考。

## 4. 视觉读出（第二步，短程对照）

- **多层特征**：把 SigLIP2 第 6 / 9 / 12 层的输出拼接（或学一个层权重）后再进投影层。延迟几乎不变。和主线同一份蒸馏数据的前 N 步做两臂对照，判据训练前写下。
- **更高分辨率**：`google/siglip2-base-patch16-384`（144 个视觉 token），只有在蒸馏后 ScienceQA 看图题 / 计数仍然明显落后时才做，先实测 CPU 延迟。

## 6. v0.4 验收（训练前冻结；对 v0.3 逐题配对，按图片重采样 95% 区间）

- 全部评测集（含新补的和外部的）：没有任何集合准确率差值上界 < 0；
- 多数集合点估计为正；ScienceQA、VSR、计数、A-OKVQA 至少三项下界 > 0；
- 校准：没有集合的 NLL 比 v0.3 显著变差（重点 POPE、存在、大小）；
- CPU 延迟实测并写进发布说明。

不满足时不发布，把结果和取舍交负责人决定。

## 7. 风险

- 教师在本项目的某些题型上未必强（如合成图、镜像左右）——由第 2 步门槛逐集决定是否用教师。
- 学生容量（约 0.5 B 参数、64 token）可能学不到教师的全部能力；蒸馏仍能改善校准和遗忘，准确率收益要实测。
- 网络慢：教师 9 GB、外部评测几 GB，下载前确认镜像速度。
- 许可：Qwen3-VL 为 Apache-2.0，与本项目一致；教师输出参与训练要在模型卡里写明。
