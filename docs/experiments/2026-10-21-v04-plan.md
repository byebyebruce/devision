## 2. 阶段

### 第 0 阶段：补全评测，冻结验收
1. 用数据 B 和已有转换脚本生成本机缺的集合：`bench_countbench`、`bench_whatsup`、`test_bind_gqa`、`test_count_fresh`、CoGenT B（合成图脚本的 Mac 字体路径改成可配置）。
2. 新增外部公开评测（英文单图，noul / choice）：MMBench-en dev、SEED-Bench 图片部分、CV-Bench、NaturalBench、MME，经 hf-mirror 下载。
3. v0.3 补评全部集合作为基线，r17 补评作参照。
4. 冻结评测集清单、文件哈希、验收规则（`docs/experiments/2026-10-21-v04-eval-freeze.md`）。评测图片从所有训练池剔除。

### 第 1 阶段：错误分析（只用开发集）
v0.3 与 r17 的错题按子类型归纳：ScienceQA 按技能、VSR 按关系、计数按数量段与物体大小、POPE 漏报按物体大小与类别；每个子类型给出配错图准确率和看图收益。产出「失败簇 → 补什么数据 → 多少题」的表，第 2 阶段只造表里的东西。

### 第 2 阶段：data-n2（每块一个脚本，带测试和 MANIFEST）

| 块 | 补什么 | 来源 |
|---|---|---|
| A 示意图 / 科学 | ScienceQA 看图题 | ScienceQA 训练集全部带图题；AI2D、TQA 全量；IconQA、MapQA；第 1 阶段指出的高频失败技能在真实数据不够时程序生成 |
| B 空间关系 | VSR、What'sUp 类 | VSR 全部训练划分、SpatialSense；COCO 掩码自造接触 / 重叠 / 包含，框造上下左右（严格边距） |
| C 计数 | CountBench | COCO 无 crowd 的类别、PixMo-count、TallyQA simple；选项一律 0–10 全集 |
| D 存在 / 幻觉 | POPE 准确率与过度自信 | LVIS 人工核过的「不存在」类别（1,203 类）；正例覆盖各种大小；高共现类别做对抗负例 |
| E 常识 | V7W、A-OKVQA | V7W telling 全量；A-OKVQA 全部训练集；OK-VQA 转选择题 |
| F 对比对 | 逼模型看图 | 同一问法、两张答案相反的图，同一 batch |

质量门（每块都过）：
- 不能靠文字猜：用 v0.3 配错图答，仍高置信答对的题删除；MANIFEST 报告只看题目的基线。
- 标签可靠：程序生成的标签可验证；人工标注取一致度高的，分歧大的用票数占比作软 gold。
- 均衡：同一问法下每个答案有上限，是非题各半。
- 隔离：评测图片按 COCO / VG id 加图片哈希剔除，题目与评测集去重；每块按图片划约 2% 开发集。

### 第 3 阶段：r19（一轮，从 v0.3 出发）
- 数据：n1（VQAv2 / GQA 降到约 40 万）+ r17 存在题 + data-n2；各能力设最低占比（示意图 / 科学、空间、常识 ≥ 8%，计数 ≥ 6%，第 1 阶段后定稿）。约 90–110 万题。
- 设置同 r16（bf16、2e-5 / 1e-5 / 5e-5、解冻 SigLIP 顶部 4 层）。
- 每 1 万步在各能力开发集上监测；止损规则训练前写下（任一能力开发集比 v0.3 低 ≥ 3 点且上界 < 0）。
- 训后：拟合温度、全量评测（含对照）、与 v0.3 / r17 逐题配对、`lv_report.py`、训练日志。

### 第 4 阶段：补洞（需要时）
某能力不达标：针对它加数据从 r19 短程续训（r20）。个别集合小幅退步：v0.3 与候选之间权重插值，开发集上选比例，测试集只看一次。

### 第 5 阶段：发布 v0.4
验收（对 v0.3 逐题配对，按图片重采样 95% 区间）：
- 任何集合准确率差值上界都不低于 0；
- 多数集合点估计为正；
- ScienceQA、VSR、计数、A-OKVQA、V7W 至少四项下界 > 0；
- 任何集合 NLL 不显著变差。

再测 CPU 延迟（结构不变，预计同 v0.3），`hf.py build / verify`；publish、PyPI tag、合进 master 前问负责人。
