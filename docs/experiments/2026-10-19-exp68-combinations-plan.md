# EXP68 方案：用新的反捷径温度组合替换旧温度题，同预算普通 CE（EXP68-PREP-01；CPU 准备，未运行）

日期：2026-10-19。依据 EXP65-RESULT-01：

- EXP65 两臂都通过了 EXP63 的原门槛，但两类冲突仍没学会：「质量较大者胜」C 38 / 80、W 35 / 80；C / W 在该类的 42 / 45 个错答都选了速度较大者。
- 旧训练集里，52 道质量胜题只有 26 个不同的数值组合，96 道速度胜题只有 48 个。W 只改了旧题的权重，没有提供新组合。
- 假设：在同样的 9,600 题 / 1,200 次更新下，用从未出现过、成对的反捷径组合做监督，两类冲突能否都泛化。
- 这是另一套数据配方，不是 EXP65 的续跑。类别配额与组合多样性同时改变，结论只归于整个新数据配方，不单独归功于「多样性」。candidate_eligible 恒为 false。

## 不变的部分

- 起点 EXP63 端点（3e8443e9 / 70c302c4）；普通 text_only CE，权重全 1；LoRA r16、lr_lora 5e-5、lr_head 1e-5、warmup 100、seed 1、micro / eval batch 8、末步，与 EXP63 / EXP65-C 相同。
- 磁力：data/facts/train.jsonl 的 1,200 行（每行 3 题）逐字节复制、顺序不变。
- EXP65-C 的冻结结果（runs/exp65-c 端点 382e0a44 / cb7419ab 及其已登记的明细）作为同预算旧数据的参考，不重跑。

## 新的温度数据（`scripts/exp68/build.py` → `data/exp68/`）

- **规模**：六类各 100 个不同的 canonical 数值组合，每个组合两视图（A / B 互换），共 600 组合、1,200 行、6,000 题（比较题 + 4 道读数）。加上磁力 3,600 题，共 9,600 题，与 EXP65 相同。
- **构造**：用生成器自己的 `real_layout.temp_items`（题目、打乱的选项、两视图共用的读数候选）和 facts 的 `row_of`（state = 提示 + 金标数值表，exp55 的 serialise / fmt；选项按 sha256(行 id + qid) 重排）。标签按生成器规则（m·v² 较大者；两者都相等时为相同）。
- **冲突配对**：两类冲突共 100 对。每对的「质量胜」组合与「速度胜」伙伴共享四个数中的三个，只改一个数就翻转答案：
  - 偶数对：把轻者的速度调高（50 对）；
  - 奇数对：把重者的质量调低、仍比轻者重（50 对）；
  - 新值在所有能翻转答案的取值里均匀抽取。
- **数值词汇**：只用旧 train 自己的取值（43 个质量值、174 个速度值）；读数干扰项由生成器规则产生。
- **只用文字**：行里的 image 是 "text-only:exp68"，从不被打开（夹具：把 rlcd 的取图函数换成抛错，text_only 训练照常完成）。
- **排除**（canonical 组合，含两种顺序）：data/real_layout（train / tune / confirm）、data/cmp、data/facts 共 4,036 个；EXP65 diag 240 个；转录的 12 个温度组合。新 train 与这些的交集为 0。
- **新的开发诊断**（`data/exp68/diag.jsonl`，480 个请求）：六类各 40 个组合，seed 6868，两种顺序各问一次，格式与 EXP65 diag 相同；与新 train 和所有排除集的交集都为 0。它只是开发诊断，不是发布确认集。
- **逐行核对**（全部 1,200 行）：表里的四个数等于读数题的金标；比较题的金标等于规则；类别等于 axis；两视图互换。
- **反捷径审计**（只报告）：区分「质量胜」与「速度胜」时，单个数（重者质量、轻者质量、慢速、快速、质量比、速度比）用一个阈值能达到的最好准确率：

| 特征 | 新 train（各 100） | 旧 facts train（26 / 48） |
|---|---|---|
| 重者质量 | 0.680 | 0.662 |
| 轻者质量 | 0.500 | 0.770 |
| 慢速 | 0.500 | 0.743 |
| 快速 | 0.635 | 0.662 |
| 质量比 | 0.660 | 0.757 |
| 速度比 | 0.630 | 0.811 |

  - 修正（评审 EXP68-NOTE-01）：阈值只取在不同取值之间，不在相同取值内部切分。原表有几项因此偏高。重者质量一项，新数据（0.680）略高于旧数据（0.662），所以不能概括为「所有单特征捷径都减弱」；其余五项新数据更低。train / diag 的字节没有变，只有 MANIFEST 的描述性审计重算了。
- **动能比分层**（只报告，不按结果改门槛）：near（较大动能 < 2 倍）/ large（≥ 2 倍）：

| 类 | 新 train near / large | 新 diag near / large |
|---|---|---|
| 质量较大者胜 | 75 / 25 | 28 / 12 |
| 速度较大者胜 | 91 / 9 | 16 / 24 |
| 同质量 | 38 / 62 | 16 / 24 |
| 同速度 | 53 / 47 | 21 / 19 |
| 同向 | 10 / 90 | 2 / 38 |

  - 披露：「只改一个数就翻转」的配对天然靠近判定边界，所以新 train 里速度胜以 near 为主（91 / 100），而新 diag 是独立随机抽取，速度胜 large 较多（24 / 40）。两者分布不同，按层分别报告；本轮不为此调整规则。
- **身份**：train.jsonl 1798d1e8…，diag.jsonl 3a96c3f7…，MANIFEST.json 和 PLAN.json 重建后逐字节相同。

## 第 2 轮修正（评审 EXP68-R2-01；未运行）

- **问题**：原实现中，新 diag 缺失或无效时只记在 states 里，路线仍按实用条件给出，原夹具甚至把「两份新 diag 都缺失」断言为「满足」。
- **修正**：
  - 读取失败时区分两种状态：details 文件不存在记为 missing；文件存在但登记、身份或逐题核对不过，记为 invalid: 原因。
  - new_diag_evidence：X 和 C 的新 diag 都 completed 才是 completed；有一份 invalid 就是 invalid；否则是 incomplete。
  - 最终路线 = route(new_diag_evidence, practical)：只有证据 completed 时才按原数值条件给出；incomplete / invalid 都不给路线，已算出的指标照常保留。
  - practical 的计算和全部数值门槛都不变；新 diag 的分数仍然只报告。
- **夹具**（test_exp68_runner.py 共 10 项，加上数据夹具共 16 项，全过；pyright 0 错误）：
  - 两份新 diag 完整有效、但 X 的分数很低（全答 "sample B"）：仍判「满足」；
  - X 的新 diag 缺失、C 的新 diag 缺失：都给 incomplete，没有路线（practical 仍算出为 true）；
  - X 的新 diag 登记后被改、某条记录的 prediction 换成另一个合法选项但不是 argmax：都给 invalid，没有路线。
