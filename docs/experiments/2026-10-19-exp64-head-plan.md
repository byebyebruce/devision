# EXP64 方案：固定选择器，单独适配字符读出头（EXP64-PREP-01；CPU 准备，未运行）

日期：2026-10-19。依据 EXP62 终点裁决（EXP62-RESULT-01 / 02）：

- 新版式上，自动路径的 365 个错误中有 295 个换成 oracle 框后仍错；距离有 170 题在两种框下都错。
- 所以先固定选择器和视觉，单独检验读出头在新版式和预测区域上的适应性。
- c92b7b7e（EXP62 的选择器）只作研究对照，不是产品端点。candidate_eligible 恒为 false。

## 冻结与唯一训练部件

- **冻结**：EXP62 选择器 c92b7b7e（使用其登记的框）；EXP50-T / EXP57 视觉（962503fb）；网格 n12 / 0.25；区域规则（`reading.region`）；决策模型。
- **唯一训练的部件**：同构的字符读出头（`reading.CharHead`），以 EXP51-T 的 0b548142 初始化；0b548142 本身同时是基线。
- **配方**：AdamW lr 1e-4、wd 0.01；前 50 步线性预热，之后保持常数（评审只规定了 warmup 50，没有指定衰减）；seed 0；固定 1,000 次更新，取末步；损失沿用 EXP49 的逐样本槽位 CE。

## 数据（`scripts/exp64/build.py` → `data/exp64/`，只用 CPU，不跑视觉塔）

- **训练记录 3,552 条**：fit_O + fit_L 1,152、train_V 1,200、train_P 1,200，与 EXP62 相同。
  - 每条用 EXP62 已登记的新选择器框（boxes.jsonl / boxes_parents.jsonl，核对过 registry），目标是训练源的实际数值；
  - 不用 tune、confirm、dev24 的 gold、失误或 oracle 框；
  - train.jsonl SHA 5888e7ce…。
- **框的忠实性**：在 rl_tune 的 1,800 题上，登记框与实时产品路径的框最大相差 0.0002 px（> 1 px 的 0 个）。
- **批计划**（plan.jsonl cd4e4c11…）：与 EXP62 同一个生成器（scripts/exp62/build.plan，seed 0 / 1），步数改为 1,000。
  - 每批 24 对父图 / 裁剪图（相邻、不拆）+ 16 行回放；
  - 64,000 次曝光 = 父图 24,000 + 裁剪 24,000 + 回放 16,000；每对 20 次，回放每行 13–14 次；拆开 0；按字段约 21.3k / 21.3k / 21.3k；340 个族。

## 审计（`data/exp64/audit.json` 4f0bcce9…；只作描述，不作训练输入）

- **口径**：
  - 「框装下目标」：预测框是否包含文字框（变体 / 父图用 text_box；exp49 的集合用字段行带，所以更严）；
  - 「覆盖」：被选中的 cell 覆盖文字框的比例，全图视图和局部视图分开计。
- **主要观察**：

| 集合 / 字段 | 框装下目标 | 全图 token 中位 | 局部 token 中位 | 局部覆盖 p10 |
|---|---|---|---|---|
| 训练 train_V / train_P（各字段） | 0.995–1.000 | 16 | 99–235 | 0.977–0.995 |
| 训练 fit_O 距离 / 质量 / 速度 | 0.80 / 0.81 / 0.81 | 16 | 235 / 99 / 128 | ≥ 0.99 |
| 开发 tune_V 自动（距离 / 质量 / 速度） | 0.993 / 0.915 / 0.892 | 16 | 235 / 123 / 99 | 0.98–0.99 |
| 开发 rl_tune 自动（相对字段行带） | 0.54 / 0.24 / 0.35 | 16 | 235 / 120 / 128 | 0.92–0.99 |
| dev24 自动（距离 / 质量 / 速度） | 0.917 / 0.708 / **0.000** | 16–17 | 196 / 136 / 136 | 0.98 / **0.74** / 0.99 |
| dev24 EXP60 oracle | 1.000 | 3.5–7 | 36–69 | ≥ 0.99 |

- dev24 自动速度框没有一个完整装下文字框，但按 cell 计的名义覆盖中位是 1.0。相交 cell 比像素框粗，名义覆盖不等于读得出；dev24 的坐标也不转成任何产品规则。
- tune_V 自动的距离框 99 % 装下文字、覆盖完整，但距离读数约 0.71：与「距离错误多半不是框的问题」一致。
- **特征体积上限**（token × 768 × float16）：训练 605,811 个 token（0.93 GB），开发 969,275 个 token（1.49 GB）。只缓存训练特征（磁盘上的 memmap）；开发集逐图在线编码一次，新旧头用同一份 token，不缓存开发特征。

## 保真与判定

- **保真（先做，不过就停止）**：旧头在同样的输入上，必须逐字符串、逐有效性复现已登记的读数，分四组核对。任何一组不符就停止，报告给 invalid。
  - rl_tune：对 EXP62 的 rl_tune_new；
  - tune_V 自动：对 EXP62 的 tune_V_new；
  - tune_V oracle：对 EXP62 的 tune_V_oracle；
  - dev24 自动：对 EXP62 的 dev24 明细；dev24 oracle：对 EXP60 的 oracle 明细。
- **报告**：新旧头 × 自动 / oracle × 三字段，统计同 EXP61（异值对象对、字段宏平均、case 簇、合法 0）。
- **预写判定**（按此顺序）：
  - 头的有效性（EXP49 的线）：新头在 fit_O 和 fit_L 上整串 ≥ 0.90，且每字段 ≥ 0.75；train_P / train_V 另报。不过就判为「瓶颈未定位」；
  - 旧版式：rl_tune 新头的 exact 和每字段，相对 EXP56 的原生产读数（旧选择器 + 旧头）下降 ≤ 0.03；
  - 新版式：tune_V 自动新头达到 EXP53 投资线；
  - 归因：tune_V 自动「新头 − 旧头」（同一 EXP62 选择器）的整串差，case 簇区间下界 > 0。不满足就不归功于读出头；
  - dev24：新头自动速度 ≥ 18 / 24，且相对原始自动（EXP60 auto，0 / 24）的改善下界 > 0；另报新头 − 旧头、oracle 新旧头。
  - 缺项给 incomplete，不放宽投资门槛。
- **之后**：失败不自动重试，也不改成联合训练。成功只进入「实时读取 + 决策组合验证」的准备，并且要另行许可。

## CPU 夹具（`scripts/exp64/test_exp64.py`，13 项，全过；不加载模型）

- 3,552 条训练记录的框都等于 EXP62 登记的新框，没有任何 dev 记录；计划 1,000 × 64、对子相邻、所有 key 都在训练集里、每对 20 次。
- 头只从给定状态训练：空计划时等于起点；有计划时改变；同 seed 可复现；参数集合不变。
- 旧头复现的比较同时看字符串和有效性，缺读也算不符。
- 8 个门槛 / 分支用例：有效性优先，缺项给 incomplete。
- START 之后改了训练目标（即使同步更新 MANIFEST）被拒绝，报告给 invalid；EXP62 选择器的哈希不符时被拒绝。
- run.sh stub：顺序 start → features → train → reads → report；train 失败时不跑 reads，直接 finalize。
