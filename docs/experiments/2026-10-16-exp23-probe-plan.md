# exp23 方案：冻结特征上的数字可读性探针（修订 1，按评审 EXP23-I01 收窄判定；代码与测试已写，未运行模型）

日期：2026-10-16。负责人："可以"（exp22 之后的推荐）。不训练模型、不改任何权重；只在冻结 checkpoint 的特征上训练小探针。不算一轮。

## 要回答的问题

exp21、exp22 里 r15 学不会从图里选出印刷数字（exp22 只训 16 px 读数题，nll 全程停在 ln 3 附近，连训练题都没拟合）。但那两次只改了训练数据，"表示里有没有数字"和"决策训练用不上"分不开。

这里直接问：**一个两位数印在白图上，它的十位和个位能不能用两种小探针从下面三层特征里解出来（可读性）？各层的可读性是什么走向？** 结果只描述可读性，不判定信息在哪一层被删除（评审 EXP23-I01）。
- `siglip`：视觉塔最后一层的 256 个 patch 特征；
- `projector`：2×2 合并 + MLP 后送进 ModernBERT 的 64 个视觉 token；
- `encoder`：ModernBERT 最后一层在这 64 个视觉位置上的状态（输入 "[CLS] <视觉> [SEP]"，不带问题）。

另报 v12（原始冻结的 SigLIP2）的 `siglip` 层，看 r15 解冻顶部 4 层有没有影响（只报告）。

## 设计（`scripts/exp23/probe.py`）

- **图**：256×256 白底，一个两位数（10–99），位置随机，黑色 Arial；数字墨迹高 6 / 8 / 16 / 48 像素（字号由像素实测选出，沿用 exp21 的 `font_for`；48 px 是难度对照）。每个字号训练 3,000 张（seed 1）、测试 1,000 张（seed 2），按像素哈希去重：训练集内部不重复，测试图不与任何训练图相同（评审 EXP23-N02；原先 16 px 有 2 张、6 px 有 1 张重合，48 px 训练集内有 2 张重复）。已核对四个字号都是 3,000 / 1,000 张唯一图、交集 0。
- **标签**：十位（1–9）和个位（0–9），机会约 0.10。
- **探针**（两种，都在 CPU 上训，特征按 float16 缓存，checkpoint 不变）：
  - `pooled`：token 的 [均值; 最大值] → LayerNorm → 线性分类；
  - `attention`：4 个可学的查询对 token 做注意力池化 → 线性分类（能挑出数字所在的位置）。
  - AdamW，lr 3e-3，60 遍，seed 0。
- **一层的数字准确率** = 两种探针里较好的那个，十位、个位准确率的平均（运行前定下）；95% 区间按测试图重采样。

## 判定（运行前写下，结果出来后不改）

阈值（16 px，6、8 px 只报告）：每层可读性 **高** ≥ 0.60，**低** ≤ 0.20（机会约 0.10），其余为**中间**。标签只描述这两种小探针下的可读性，下一步都是待验证的候选，不自动推出必须换哪个模块。

| 条件（16 px，按顺序判断） | 标签 | 待验证的候选（另写方案，不自动启动） |
|---|---|---|
| siglip 在 48 px < 0.90 | 难度对照未过线，本轮不作层间解读 | 先查探针优化设置；也可能是冻结表示本身的限制 |
| 任何后层为高、而它之前某层不是高（下游恢复） | 非单调可读性，瓶颈未定位 | 只说明可读性随层不单调，不归罪上游 |
| 三层都低 | 三层在 16 px 上可读性都低 | 更高分辨率 / 擅长文字的编码器；更强的解码器 |
| siglip 高，projector < 0.60 且比 siglip 低 ≥ 0.20 | 投影后可读性下降 | 读字式对齐阶段（训投影层） |
| siglip、projector 高，encoder < 0.60 且比 projector 低 ≥ 0.20 | ModernBERT 视觉位置的可读性下降（输入不带问题） | 文本侧的训练改动 |
| 三层都高 | 三层在白底两位数任务上均可读；原决策失败的原因待区分 | 改训练方式；另立与原任务匹配的读出对照 |
| 其他 | 不确定 | 交负责人 |

能说 / 不能说：
- "可读性高"只说明在干净的白底单数字图上，这两种小探针能从冻结特征里解出来；不等于 ScienceQA 的复杂图里也能，也不等于模型会用。
- "可读性低 / 下降"只说明这两种探针解得差；可能是信息不在了，也可能是表示方式变了、这类探针更难优化，不能写成"信息丢失"。
- `encoder` 层的输入只有 "[CLS] <视觉> [SEP]"，没有问题、候选项、选项 [MASK] 和后面的两层决策头；它和 exp22 的实际决策路径不同，三层都高也不能定位 exp22 的失败原因。
- 每层取两种探针中较好的那个是在测试集上选的，所以这个数和它沿用的区间都是探索性的（评审 EXP23-N01）；两种探针的原始结果都保留在报告里，接近阈值时不下强结论。
- 不碰 ScienceQA 数据，不评任何集合。

## 实施（已写好，未运行模型）

- `scripts/exp23/probe.py`：生成图 → 三层特征（`model.image_features` 与 `model.encode`，`torch.no_grad`）→ 两种探针 → `runs/exp23-probe/report.json` 和终端表。
- `scripts/exp23/test_probe.py`（18 项，无真实模型）：
  - 图里的数字墨迹高度符合字号（误差 ≤ max(1, 5%)）；
  - 两种探针都能学会"墨迹 token 位置随机、带数字"的玩具信号（> 0.9），学不会"有墨迹无数字"的噪声（< 0.25）；
  - 判定的每个出口和边界（含 projector 低于 0.60 但比 siglip 低不到 0.20 → 不确定），三种下游恢复反例（0.15/0.90/0.90、0.90/0.30/0.90、0.40/0.40/0.90）都输出"非单调可读性"，所有标签都不含"丢失 / 不携带 / 没用上"这类因果措辞；变异检查：去掉非单调分支，3 项测试失败（已还原）；
  - 训练 / 测试图的像素哈希不重合（正式规模 16 px）；
  - tiny 模型端到端跑通四层（含 base）。
- `scripts/data/exp21_reading.py` 的 `font_for` 搜索上限从 60 号放宽到 90 号，以便画 48 px；exp21 已用的四个字号（8 / 11 / 15 / 22 号）不变，exp21 测试 8 项仍通过。
- pyright 0 错误。

## 预算（估计）

16,000 张图，每层一次前向（视觉塔共 4 次），MPS 上约 10–15 分钟；32 次探针训练在 CPU 上约 20–30 分钟。合计约 40 分钟，最多 1 小时。

命令：`uv run python scripts/exp23/probe.py --checkpoint runs/r15-vision/stage2 --base runs/v12-ext/stage2 --out runs/exp23-probe`

## 结果（2026-10-16 12:16）：三层在白底两位数上都读得出

运行身份：提交 `9ca9ad9`（评审第 2 轮放行），命令 `uv run python scripts/exp23/probe.py --checkpoint runs/r15-vision/stage2 --base runs/v12-ext/stage2 --out runs/exp23-probe`，特征在 MPS 上提取，探针在 CPU 上训练。11:37:04 开始，12:16:29 写出报告，约 39 分钟，退出 0，一次跑完。产物：`runs/exp23-probe/report.json`，终端日志 `runs/exp23-probe.out`。

数字准确率（十位、个位平均，机会约 0.10；每格 pooled / attention，1,000 张测试图）：

| 层 | 6 px | 8 px | 16 px | 48 px |
|---|---|---|---|---|
| r15 siglip | 0.937 / 0.975 | 0.982 / 0.993 | 0.998 / 1.000 | 1.000 / 1.000 |
| r15 projector | 0.826 / 0.838 | 0.921 / 0.941 | 0.984 / 0.993 | 1.000 / 1.000 |
| r15 encoder（输入不带问题） | 0.694 / 0.711 | 0.801 / 0.852 | 0.906 / 0.950 | 0.990 / 0.996 |
| v12 siglip | 0.946 / 0.975 | 0.986 / 0.994 | 0.999 / 1.000 | 1.000 / 1.000 |

- 48 px 难度对照通过（siglip 1.000）。16 px 三层取较好探针：siglip 1.000、projector 0.993、encoder 0.950，都 ≥ 0.60。**按预写规则：三层在白底两位数任务上均可读；原决策失败的原因待区分。**
- 只报告：字越小，层越往后，可读性越低（6 px：0.975 → 0.838 → 0.711）。但即使 6 px、ModernBERT 视觉位置，探针也能解出七成。r15 解冻顶部 4 层前后的 SigLIP（v12 对 r15）几乎一样。
- "较好探针"是在测试集上选的，是探索性的数（评审 EXP23-N01）；两种探针的原始结果都在上表。

### 解读（探索性，只限于这次的设置）

- 能说的：在干净的白底单个两位数图上，r15 冻结的 SigLIP 特征、送进 ModernBERT 的 64 个视觉 token，以及 ModernBERT 在视觉位置上的状态，用小探针都能解出数字；6 px 也大多能解出。
- 和 exp21 / exp22 放在一起看：数字在表示里是可读的，但决策训练 2,000 步没学会用它来选对应的候选数字。这把"视觉塔 / 分辨率 / 投影层是瓶颈"这几个候选放到了后面，更可能的问题在读出：问题、候选项文字、[MASK] 与视觉位置之间的对应。这仍是推断：encoder 层的输入不带问题和候选项，和实际决策路径不同（评审 EXP23-I01）；合成面板图也比白底单数字复杂。
- 待验证的候选（另写方案，不自动启动）：读字式的对齐训练（让 ModernBERT 从视觉 token 补出被遮住的数字）、更高的文本侧学习率或解冻更多文本层、辅助损失。
