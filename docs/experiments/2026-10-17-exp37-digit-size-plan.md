# exp37 方案：同 256 输入下的数字可读性对照（评论家 EXP37-RUN-01 放行，已运行一次，结果见文末：大字救回，四条投入门槛全部满足）

日期：2026-10-17。依据：评论家 EXP36-RESULT-01 / 02、EXP37-PREP-01 / READOUT-01。

exp36 的全遮监督提高了完整数字补全，但没有建立随数值变化的正确读数和绑定。现在还分不清是字形可见性、区域对应还是优化不足。这里只改一样东西：数字在 256 输入里的墨迹高度。

## 要回答的问题

**同一个起点、同样的语义、同样的版式和训练，只把数字从原来的小字（S）放大到 256 输入里墨迹约 16 px（L），完整数字补全和标签绑定能不能被救回来？**

## 两臂

| | S（对照） | L（实验） |
|---|---|---|
| 配置 | `configs/exp37-s.yaml` | `configs/exp37-l.yaml` |
| 数字大小 | 场景原来的字号（256 上墨迹 2–9 px） | 256 上墨迹 15–17 px |
| 训练数据 | `data/exp37/align_mix_S.jsonl`（`16dc3aa8…`） | `align_mix_L.jsonl`（`51565039…`） |

- **共同部分**：
  - 都从 A2（`8476145e…e297`）各自独立起跑，都用 exp36-B 的双侧全数值遮罩（`number_mask_sources`），各 1,000 步；
  - batch 16、学习率、LoRA、冻结方式、warmup、seed 0、44 token、损失定义都与 exp36-B 相同；

  - 不加 RL / 决策 CE，不换骨干，不用 512 输入，不加视觉 token。
- **语义和样本**：复用 exp36 的 4,000 族（每族两视图）、8,000 张 COCO 和 16,000 行顺序；600 张 tune 和 200 张 fit 也用原来的族、说明文字和数值。
  - 两份列表去掉 image / variant 两个字段后，与 exp36 原列表逐行相同（`scripts/exp37/build.py` 内断言）。
  - COCO 行原样不动。
  - 新图写到独立路径 `data/exp37/images/{S,L}/`，不覆盖原图和原数据。
  - 不引入 confirm、exp31、75 题属性和 80 题 ChartQA。

## 画法：共同排版，只有数字框里不同（`scripts/exp37/render.py`）

- **场景**：`real_layout.families()` 按原来的随机抽取逐个重放场景，不重新抽。这是把 build 的循环抽成生成器得到的，重建出来的 real_layout MANIFEST（全部 JSONL 的 sha256）与原数据完全相同，抽查的图片也逐字节相同。
  - 粒子、磁铁、颜色、左右、孪生图都与原场景一致。
- **共同排版**：只做一次轻量重排，S 和 L 共用：
  - 温度：瓶子下面是 "Sample A"，然后按场景原来的行序，每个字段先画量名一行（如 "Mass of each particle:"），再画一行 [数字框][单位]。
  - 磁力：原来的磁铁和距离标尺保留，去掉标尺上的文字；每一对下面加一行 [数字框][单位]。
  - 数字框的宽度按该字段最宽的字串在 L 字号下的宽度留出（质量 "00"、速度 "0,000"、距离 "00.00"）。位置只由场景的版式参数决定，不读数值，也不看答案。
  - 标签、量名和单位都在框外，用原字号，S 和 L 完全相同。
  - S 用场景原来的字号。但共同排版的画布比原图高，166 张温度图的 letterbox 缩放比例因此略小，最低为原比例的 94.03%，所以 S 在 256 输入上的字略小于原图（评审 EXP37 NOTE-01，不重画）；L 用让 256 输入上数字墨迹约 16 px 的字号（按每张画布实际的 letterbox 缩放比例单独算），逗号和小数点跟着字串一起放大。
- **全量检查**（8,600 张图 = 4,300 族 × 两视图，共 25,800 个数字；`data/exp37/render_summary.json`、`pictures.json`）：
  - 每对 S / L 图在数字框外逐像素相同：0 处违例；
  - 每个数字的墨迹都在自己的框内（与"不画数字"的同一张图相减）：0 处违例；
  - 框内在不画数字时是纯白，没有压住标签、单位或其他行：0 / 25,800；框与框之间没有重叠：0；
  - 墨迹高度在实际 256 输入上测量（不含逗号和小数点；把 letterbox 后的图与不画数字的图相减，差 ≥ 64 灰阶的行数）：
    - L：15 px 700 个、16 px 22,643 个、17 px 2,457 个，全部在 16 ± 1 之内；
    - S：2–9 px，大多是 4–6 px。
- **预览**：`runs/exp37-preview/pairs.png`，16 对 S | L 的 256 实际输入，各对的数字和框见 `pairs.json`。按规则挑选，不看任何模型分数，覆盖：
  - 温度：A 在左 / 在右、速度行在上、短措辞、最长速度串、孪生视图、最小画布、最大原字号；
  - 磁力：mm 小数、Pair 1 在右、cm 小数、大小不同、最矮画布、最窄画布、最小原字号、孪生视图。

## 读出（运行前写下，不改；`scripts/exp37/report.py`，复用 exp36 的统计）

- 固定在 1,000 步末点。每个模型评四份：
  - 600 张 tune 画成 S、画成 L、原图三种（只评完整数值条件，`readout.py --full-numbers-only`）；
  - 自己训练版本的 200 张 fit 切片。
  - 都是真图加同一张固定换图，逐数记录里带模型、输入版本和图片集哈希。
  - 不再重复随机遮罩的专项诊断；训练中的 val 只作运行记录。
- **主比较**：L 模型看 L 图，对比 S 模型看 S 图，同一批族按族配对。沿用 exp36 的四条投入门槛：
  1. 整数宏平均差 ≥ +0.10，且下界 > 0；
  2. 异值两对象宏平均差 ≥ +0.10，且下界 > 0；
  3. L 的质量、速度整数准确率各 ≥ 0.20；
  4. L 在"目标值确实变了、换图恰是孪生"的数字上，真图 − 换图的下界 > 0。

  通过只说明"用大字训练、看大字能救回这个任务"，不代表产品输入已经修好。
- **只报告**：2 × 2 交叉矩阵（S / L 模型 × S / L 图），用来区分训练适应和测试字号；两个模型在原图上的结果；fit 切片；与 exp36-B 的比较只作历史参考。
- **保护**：两臂各评 7 个面板，对 v0.3 用原规则，与数字终点分开。
- **结果怎么用**（评论家决定，不自动启动任何训练）：
  - 只有大字成功 → 支持"可见性 / 尺度"这一解释，下一项是尺度覆盖和原尺寸迁移的配方；
  - 大字也失败 → 不判架构永远不行，下一轮转区域对应或可优化性，不原样加步数。

**读法**（只限这次的设置；按评审 EXP37-RESULT-01 / 02 收窄）：
- 同一共同版式下，只把数字放大到 256 上约 16 px，并且训练和测试都用大字，完整数字补全就明显上升，按标签对应也变得可测：两对象同时对约 14%，孪生两视图都对约 18%。在"目标字段值改变的本族孪生图"上，真图比换图好 +0.118（158 / 109 对 414）。
- 这支持"数字字形的可读性"是限制之一。但这一对照并不严格只改了印字像素：real_layout 的孪生图还可能改变粒子半径或磁铁间隙，所以不能排除几何等线索的贡献。
- 绑定仍然不可靠：L / L 中同图两对象值相等的项对 0.806，值不同的项只对 0.336，两对象同时对只有 0.144。总体 0.589 主要来自相等项，不能当作已解决找对象和比较。
- 交叉矩阵（L 看 S 0.168，S 看 L 0.202）说明：这次的单尺度训练没有直接迁移到另一种字号或原版式。这不证明混合尺度训练一定失败，也不证明高分辨率是唯一路线。
- 两个模型在原图上都很低（0.089 / 0.113）。原图失败同时包含字高和排版域两方面的变化，产品的真实输入没有修好。
- 按预写分支，下一项是 exp38：在原生未重绘的图上做 256 / 512 输入对照（评论家 EXP38-PREP-01）。两臂都不是发布候选。
