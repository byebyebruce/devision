# exp40 方案：从 exp37-L 起点做 256 决策训练，原图与大字图配对（O / M 两臂；CPU 准备完成，未运行，等评论家的模型许可）

日期：2026-10-18。依据：评论家 EXP39-RESULT-01 / 02、EXP40-PREP-01、EXP40-READOUT-01、V04-TIME-04。

## 问题

从一个已有可测大字数值能力的 256 端点出发：在决策阶段让同一语义的原图和大字图同时受监督，能不能把这个能力迁回原图？旧决策回放能不能修复保护面板的代价？

- exp37 的 L/L 整数 0.589、异值两对象 0.144，只是有限的正证据，不说明绑定已经解决。
- 这次和以前做过的都不同：exp38-C / exp39 是原图纯 MLM；exp32 B 的起点 A2 还没学好完整数字；也不重做 v0.3 那种直接小字读数训练。
- 不是把原 512 B 改个名字绕过 `invest_in_512=false`。原 v04b 的配方和 chain 不运行，历史上的失败保持原样。

## 起点与训练设置（两臂相同，各自独立）

- **起点**：两臂都从 `runs/exp37-l/stage1` 初始化，256 输入、64 个视觉 token。
  - 权重 sha256 `f9fc93c2…`，config `3a10bacd…`；chain 启动时核对，并写进每臂的 `START.json`。
- **配置**：`configs/exp40-{m,o}.yaml`，两份只差 `name` 和 `data`。dry-run 通过。
- **训练设置**：与 B 的已审设置相同。
  - RLCD + gold CE；lr_new 2e-5（投影层）、lr_head 1e-5（决策头中不属于编码器的参数）、lr_lora 5e-5（ModernBERT 的 LoRA，r 16 / α 32）；
  - 视觉塔顶 4 层以 5e-6 解冻；ModernBERT 原权重不解冻（unfreeze_top 0）；
  - warmup 100、seed 1、micro_batch 8、eval_batch 8，epochs 1。
  - 不加纯 MLM 阶段，不引入新 RL 算法，不改线上图像入口，不重绘评测原图。
- **唯一的设置改动：`eval_every` 由 1600 改为 1650**。这只影响训练中的监测，不影响更新本身；两臂相同。改动的理由见下面的"预算"。
  - 训练中的验证轮次：第 0 步、第 1,650 步、末点（3,298）、合并 LoRA 后各一轮，共 4 轮（与 exp32 B 的轮数相同）。
  - 1600 时在第 3,200 步还会多一轮，它和第 3,298 步的末点验证只隔 98 步，几乎重复。
- **温度**：起点 config 里带的是 v0.3 的温度。训练末点在 r13b val 上重新拟合（按题型 + 按选项数分桶），写入终点 config，替换起点的温度。
  - 筛查一律在冻结后的终点上、用拟合后的温度评；报告核对每个文件的 `run.checkpoint` 和 `temperature: fitted`。

| 块 | 题数 | 两臂之间 |

| 合计 | 26,384 | 23,744 行 |

- **选族**：从 B 的 600 个温度训练族和 600 个磁力训练族中，各取 300 个整族。
  - 用 `random.Random(40)` 抽取，不参考任何模型输出。
  - 每族保留两个数值视图，以及全部原题、选项和 gold。
- **两次曝光**：
  - O 臂：两次都用原图。
  - M 臂：第一次用原图，第二次用 exp37 的 L 画法画同一场景（image_id `exp40-L:<族>:<视图>`）。
  - 相对 B，这样做使独立族数减半、每族曝光加倍；数据量并没有增加。两臂之间则完全一致。
- **配对单元**：每道 real_layout 题拆成一题一行，规范 qid：mass / speed / distance，ScienceQA 式的问题为 cmp；group 为族。题面、选项和 gold 不变。
  - 读数单元（同字段的 A/B 或 Pair 1/2 × 两视图 × 两次曝光）各 8 题；比较单元（两视图 × 两次曝光）各 4 题。
- **L 图**：
  - 1,200 张中，796 张直接用 exp37 已画的。
  - 其余 404 张（202 族）由 exp37 的 renderer 从同一训练场景（`real_layout.families()`）重画，放在 `data/exp40/images/L/`。
  - 抽查 4 族 8 张：重画结果与 exp37 已有的 L 图逐像素相同。
  - 1,200 张全部核对：图上每个数字的（字段、对象、数值）与该行读数题的 gold 一致。
  - 这一步不改数字，也不借 gold 决定任何图像变换。
- **域差异**：L 图和原图同时在字号和版式上不同（exp37 的共享版式：数字框、标签行、磁铁距离条上去掉了文字）。所以本实验检验的是"原图与 L 域配对训练"，不能称为单独字号的因果效应。
- **身份与隔离**：
  - 所选族都是 train 划分。
  - 确认集、真实 ScienceQA 图、exp31 题都不进训练；canonical 和图片隔离沿用 real_layout 与 B 的划分。
- **文件**：

  | 文件 | sha256 |
  |---|---|
  | `train_O.jsonl` | `2931a3d5…` |
  | `train_M.jsonl` | `1afe9d2d…` |
  | `rl_tune_L.jsonl`（real_layout tune 决策题换上 exp37 的 L tune 图；只报告） | `12d1f676…` |
  | 来源 `data/v04b/train_mix.jsonl` | `fd53d394…` |

- **预览**：`runs/exp40-preview/sheet.png` 与 `notes.json`。
  - 按固定规则选 8 族：温度、磁力各取 exp37 已有的前 2 族和重画的前 2 族，按 id 排序。
  - 每族两视图的原图和 L 图并排，都是 256 letterbox 后的样子。人工看过，数字与 gold 一致。

## 真实批计划（`scripts/exp40/plan_check.py` → `data/exp40/PLAN.json`）

- **核对路径**：走真实的 `read_decision_jsonl` → `rlcd._items`（exp37-L 自己的 tokenizer 和 config）→ `random.seed(1)` → `plan_batches(8)`。
- **两臂结果相同**：
  - 26,384 个 item，没有丢题，也没有去重；
  - 3,298 次更新，全部是满 8 题的批；
  - 15,466 个单元，最大 8 题，没有一个被拆开；
  - real_layout 单元：mass / speed / distance 各 300 个 8 题单元，cmp 600 个 4 题单元。
- **两臂之间**：item 的 token ids、markers、target、qid、group、sample_id 全部相同，只有 4,800 个 item 的图片不同；批计划完全相同。
- 训练时实际的随机状态还取决于模型构建，更新次数以运行日志为准。

## 运行与预算（`scripts/exp40/chain.sh`；运行前写定）

- **顺序**：先 M 后 O，串行，每臂固定一轮。
  - 每臂：训练（受 watch 监控）→ 冻结权重和 config → 必需筛查 14 集。
  - 两臂都做完后，再跑只报告的集合：rl_tune_L、exp31、语义 tune。
  - 最后出报告。
  - 一臂失败或被停，不影响另一臂。不重试，不自动接完整评测。
- **启动前检查**：
  - 没有其他模型进程；
  - exp37-L 的权重和 config sha 正确；
  - 两臂数据的 sha 等于 MANIFEST 记录的值；
  - PLAN.json 显示两臂 item 和批计划相同；
  - `runs/exp40-{m,o}` 原本不存在。
- **截止**：min(启动 + 330 分钟, 2026-10-18 10:00:00)，最后 120 秒留给报告。各步用 `run_capped`，到点 TERM，15 秒后 KILL。
- **watch**（`scripts/exp40/watch.py`）：复用 B 的 watch，只换阈值。B 的 `decide` / `main` 加了 `slow` 参数，默认 6，B 的行为不变。
  - 首窗（第 100 步）> 3 秒 / 更新，或任意两个相邻的纯训练窗口 > 3 秒 → 停止。exp32 B 在 256 下实测为 1.39–1.46 秒；第 1,700 窗口含验证，不算。
  - 任一窗口 MPS 驱动内存 > 16 GB 且可用内存 < 2 GB → 停止。
  - 停滞上限：首窗前 30 分钟；1,600 和 3,200 窗口之后 40 分钟；其余 10 分钟。
- **预算依据**：exp32 B 实测。3,001 步、4 轮验证，训练 112 分钟；每步 1.43 秒；含验证的窗口推算一轮验证约 10.6 分钟；必需筛查各集用时见 `runs/exp32.out`。

| 部分（每臂） | 估计 |
|---|---|
| 加载 + 3,298 步 × 1.43 秒 | 约 80 分钟 |
| 4 轮验证（val + 10 个监测集，比 exp32 多 exp31 和语义 tune，每轮约 12 分钟）+ 拟合温度、保存 | 约 50 分钟 |
| 冻结 + 必需筛查 14 集（exp32 同集合约 14 分钟，加 syn_erased；每集记录 hash） | 约 16 分钟 |
| 每臂小计 | 约 146 分钟 |
| 两臂 + 只报告集（每臂约 4 分钟）+ 报告 | 约 302 分钟 |

- 保持 B 原来的 eval_every 1600（5 轮验证）时，估计约 326 分钟，在 330 分钟里几乎没有余量。所以把 eval_every 改成 1650，在方案里写明，没有删对照、减步或漏保护。
- 余量约 28 分钟，仍然偏紧。到截止时，O 的必需项可能仍未完成，报告会写 incomplete，不会因此给 M 或 O 通过。
- M 的首窗出来后，用实测的初始验证耗时和训练吞吐重算两臂的总时长；预计装不下就立即回报，不擅自改步数、门槛或冻结层。

## 终点读出（`scripts/exp40/report.py`；运行前写定）

- **身份**：
  - 每臂 `START.json` 要写明 exp37-L 的 sha、本臂自己的数据文件和 sha；
  - 阶段的 `run.json` 要在本臂的数据上、从 exp37-L 训练；
  - 否则报告拒绝（"wrong arm"）。没有 START 记为 incomplete。
  - 每个筛查文件都要绑定本臂冻结的权重 / config，核对未变（`scripts/v04b/freeze.py`）。
- **每臂的五条筛查**，沿用 `scripts/v04b/report.build`，不改：
  - 真实 SQA 温度 / 磁力按 68 : 114 迁移，准确率 ≥ +10 个点且下界 > 0，看图收益变化的下界 > 0；
  - 7 个保护面板没有预写代价；
  - dev16 读数和比较各自通过；
  - 擦除控制有效。
  - 任何一项没完成就是 incomplete，不给通过。只有完整通过时，才写顶层 `model_sha256`（`runs/exp40-{m,o}-screen.json`）。
- **主科学比较**（两臂的 rl_tune 都完成时才算）：
  - 主指标：原图 rl_tune 决策题上，M − O 的"异值两对象同时对"宏平均（质量 / 速度 / 距离等权）。
    - 按 canonical case 聚类做配对 bootstrap：共享 canonical case 的族连成一个簇，300 族共 165 簇；seed 0，重抽 2,000 次。
  - 同时报告每臂的：
    - 各字段读数准确率及宏平均；
    - 金标改变时孪生两视图同时对；
    - 异值时两对象预测相同的比例。
  - 只有 M − O 的下界 > 0 才称为"桥接"。单侧提升、区间跨 0 的都不算。
- **只报告**：rl_tune_L（大字能力是否保留，不用来选候选）、exp31、语义 tune。
- **候选**（预写）：
  - M 五条全过 → 优先 M；
  - M 不过而 O 全过 → 可以选 O，但不称大字桥接有效；
  - 两臂都不过 → 都不是候选，不续训，不临时降门槛。
  - 通过只表示进入原定的 29 集全评、最终确认和发布验证，不等于已经发布。
- **不在本实验内**：
  - 不要求 MLM 的整数补全和三选项准确率数值相等，两种任务分开看。
  - rl_confirm 只作已有监测。75 属性和 80 ChartQA 只在最终候选锁定后打开一次。
  - 单种子、开发集上反复决策的局限继续披露。

## CPU 验证

- `scripts/exp40/test_exp40.py`，5 项：
  1. 两臂数据如实映射 B 的行：其他块原样保留；real_layout 每题的题面、选项、gold 和 state_text 等于 B 的源行；M 第二次曝光用 L 图，O 两次都用原图；两臂除图片外逐行相同。
  2. L 图上的数字与 gold 不符时拒绝。
  3. 报告拒绝错臂（START 写的是另一臂的数据，或 run.json 在另一臂的数据上训练），没启动或缺筛查时记为 incomplete，且不写 model_sha256。
  4. 只有配对下界 > 0 才判为桥接；两臂题目不同时拒绝。
  5. 256 的 watch 阈值。
- `scripts/v04b` 的已有测试照常通过（watch 加参数后行为不变）。
- **chain 流程演练**：在临时目录里用假的 `uv` 走完整个 chain，不跑模型，exp37-L 与 data 是指向真实文件的链接。
  - 启动检查通过；
  - 两臂各 18 项按顺序 completed，FROZEN.json 记下 17 个集合；
  - 报告通过身份检查后，因为假的明细没有 v0.3 的对照记录而退出。这是预期的。
- 冒烟：用 exp32 B 和 v0.3 的已有 rl_tune 明细跑一遍 compare，结果是 both −0.012 [−0.030, +0.006]，与 exp32 的记录方向一致。这只是代码冒烟，不是 exp40 的结果。
