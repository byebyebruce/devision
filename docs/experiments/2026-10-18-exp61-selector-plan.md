# EXP61 方案：用训练来源的版式覆盖修复自动选择器（EXP61-PREP-01；CPU 准备，未运行）

日期：2026-10-18。执行 EXP60 预写的「先补选择器监督」分支：同样冻结的读取通路，只换框，速度就从 0 / 24 升到 21 / 24（[+0.75, +1.00]）。这一轮只训练选择器；candidate_eligible 恒为 false。只在评审另发 EXP61-RUN-01 后运行。

## 冻结与可训练部分

- **冻结**：EXP57 端点 962503fb / 09a5b447（视觉塔与 EXP50-T 逐位相同、词嵌入、决策）；EXP51-T 字符头 0b548142；EXP58 bundle 70bd5aa8 的读取规则（region、严格解码、千位格式）。
- **只训练选择器**：从 EXP53 登记的端点（runs/exp53/selector.pt 8f10f1fd）出发，配方与 EXP53 相同：
  - L1(cx, cy, w, h) + (1 − GIoU)，AdamW lr 1e-3 / wd 0.01，batch 64，seed 0，100 步预热后 cosine；
  - 2,000 次更新，取末步，CPU 上训练；
  - 唯一改变：起点是 EXP53 的端点，而不是随机初始化（`train_from`，其余与 `selector.train` 逐行相同）。
- **输入**不变：全图的 256 个 patch 及几何，加题目文字的词嵌入。框、字段标签、答案、题号都不是输入。

## 固定数据（`scripts/exp61/build.py` → `data/exp61/`，只在 CPU 上生成）

- **来源**：real_layout 生成器自己的图（`scripts/data/real_layout.py`，经 exp43 的 scenes 只读重放）。不用任何 ScienceQA 或 dev 图；不用 EXP59 / EXP60 那 24 张图的像素、框或数值。
- **训练变体 train_V**：
  - 生成器 train split 的 100 个温度族 + 100 个磁力族，按稳定哈希 `sha256("exp61-v1:" + family)` 选取；
  - 排除 data/exp49/questions.jsonl 的全部 440 个族（fit_O / fit_L / rl_tune / rl_tune_L）；
  - 每族两个视图，共 400 张图、1,200 个框（质量 / 速度 / 距离各 400）。
- **回放**：fit_O + fit_L，即 EXP53 的 1,152 个框；patch 直接用 EXP53 登记的 global.npz（a0172943）。
- **新版式开发切片 tune_V**（现在冻结，从不训练）：生成器 tune split 的全部 300 个族（即 rl_tune 的族），两个视图，共 600 张图、1,800 个框。同一族的两个视图在同一 split。
- **变换规则**：只裁掉空白行，从不裁到墨迹（逐图检查），参数由 `random.Random(sha256(seed + 图片 id))` 决定。
  - 上边：去掉 t 行，t ∈ 0 .. min(30, 第一行墨迹)；
  - 下边：裁到最后一行墨迹下方 m 行，m ∈ 0 .. 6；
  - 框：exp45 的 `original_box`（EXP45 / 51 语义：温度是该样本半幅的行带；磁力是该组的宽标签带），平移 −t 后裁到新画布。绘制的值必须在框内，另一对象的值不能碰到框（与 exp45 的检查相同）。
  - 目标值是绘制的数值，不带千位逗号（与 exp49 相同）。
- **身份**：
  - questions.jsonl c37e35eb245277c07d52da89b1aa0e8bcdeb68effe5e402a70bc56f5c3aa66f3；
  - 图片摘要 7efa5591a484b4390d96117a6769da75707f0e8b1bf0cdbd1a787b0c4ce162c3；
  - MANIFEST 02195a21e2bf10d1153ee056d6b628b2e100e887a09bdc8573349a653b2c08b0；
  - audit ef1edb961f3cc5d031630413b0ad7b796fe09cf2f3aa6e3bf141bf90beaab7b7；
  - 生成是确定的：重建后两个主 SHA 不变。
- **预览**：runs/exp61_preview/train_V.png（55cd1f01…）、tune_V.png（aef6f55f…），各 12 张图带框。目视：温度框是行带，不少落在画布底边；磁力框是宽标签带。

## 读数验收（主看自动读数，不看 IoU）

- **统计口径**（EXP53 的口径，逐题 = 解码有效且等于目标值）：all、各字段、同图同字段两个对象都对、值改变的孪生都对、真值 − 供体（值改变的题：读成自己的目标的比例减去读成孪生目标的比例），区间按族自助法。
- **预写门槛**：
  - **新版式**（tune_V，新选择器）：all ≥ 0.80，每字段 ≥ 0.60，两对象 ≥ 0.50，孪生 ≥ 0.50，真值 − 供体 ≥ 0.20 且下界 > 0；同时新 − 旧（按族配对）下界 > 0；
  - **旧版式保留**（rl_tune 原图，新选择器 vs EXP56 登记的旧读数）：all 和每个字段的下降都 ≤ 0.03。旧基线复算为 all 0.817、质量 0.913、速度 0.818、距离 0.718，与 EXP53 auto 的 1,470 / 1,800 一致；
  - **oracle 对照**（tune_V，固定框经 exp60 的镜像读取）：all ≥ 0.80 且每字段 ≥ 0.60。不满足就记为「新版式上区域读取未解决」，不归咎于选择器；
  - **EXP60 的 24 张**（只作事后开发诊断）：新的自动速度 ≥ 18 / 24，且相对旧自动（EXP60 auto）改善的下界 > 0。同时报告质量 / 距离，以及全部比较题的转移（24 个 Reading.decide 请求）。这一项不授予发布资格。
  - **fit 有效性**：新旧选择器在 fit_O / fit_L / train_V / tune_V 上的平均 IoU，以及变体上「框是否装下绘制的值」，单独列出。
- **分支**（按此顺序）：
  - oracle 不过：新版式上区域读取未解决，不是选择器的问题；
  - 旧版式退化超过 0.03：这个选择器不能用；
  - 新版式不过：这个配方没有修好选择器；
  - EXP60 的 24 张不满足：生成版式上修好了，真实 24 张没有，覆盖缺口仍在；
  - 全过：这个配方（回放 + 版式变体，不单独归功于某一种增强）修好了选择器。下一步要另行许可：用新 bundle 做 EXP58 B1 口径的实时验证；仍不是候选。
- **边界**：真实迁移仍要沿用 EXP58 B1 的同题 / 错图全口径和原门槛；不用人工框或金标属性补成绩。
