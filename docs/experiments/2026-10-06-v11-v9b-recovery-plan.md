# 从 v9b 继续训练：计数恢复与旧能力保护计划

日期：2026-10-06（Asia/Shanghai）  
作者：Codex  
依据代码：`3b1d7e2`；实验起点：`runs/v9b-lr-replay/stage2`  
状态：**建议方案，尚未实施，也未经过独立评审。** 本文件不表示代码、配置、数据或新评测已经生成。暂按“恢复计数、保住左右与 ScienceQA”设计，主线预算约 4–6 小时；优先级或预算由负责人后续回答修订。本轮只制定计划，不启动训练。

**建议先完成一个预算受限的恢复实验。** 保留当前架构，从 v9b 新建优化器继续阶段 2：约一万道不同题各训练一遍，计数 3,000 道、非计数回放 4,500 道、原有左右题约 2,488 道。投影层、决策头和 LoRA 的学习率减半，使用新计数监测集筛选，只有通过才做最终评测。ScienceQA 的目标是保护已有能力，突破示意图读数不列为本轮承诺。

## 1. 已知事实与本轮假设

事实依据为 [训练日志](../training-log.md)、[历史实验记录](2026-09-30-rlcd-plateau.md)、`runs/v10-count/stage2/train_report.json` 及其 `eval/compare/`。

- v10 从 v9b 继续训练，计数 1,244 道重复两遍，dev 净增加 11 道正确题；测试计数仍为 103/136，其中 6 道由错变对、6 道由对变错。不能把它解释为完全没有学习，也没有证据证明计数已恢复。
- v10 左右位置原图与镜像同时答对率从 53.4% 升至 67.5%；ScienceQA 从 74.2% 降至 73.1%，需看图的自然科学切片从 47.4% 降至 42.7%。
- v10 非计数回放只有 1,244 道，ScienceQA 184 道；两遍分别为 2,488 和 368 题次。v9b 非计数回放两遍为 4,438 题次，ScienceQA 为 656 题次。
- v10 校准前 dev NLL 从 0.747 升至 0.988，choice 拟合温度从 v9b 的 2.40 升至 3.51。这支持控制继续微调的强度，但不能单凭温度认定是哪项训练参数造成过拟合。
- 当前通用训练池计数 7,787 道、7,208 张图；答案 0–10，0–4 占多数，8–10 比较少。更换抽样不能凭空获得大量高数量或复杂条件计数能力。

**待验证假设**：在接近 v10 的更新次数内，增加唯一题覆盖、恢复非计数回放题次，并减小更新幅度，能否改善计数泛化且少损伤旧能力。本实验同时改变构成、重复方式和学习率，检验的是整套恢复配方，不做单因素因果归因。不保证有效。

## 2. 起点与模型范围

| 项目 | 约定 |

架构不变是本轮控制变量的选择，不是 CPU 的硬性限制。仓库已允许考虑更高分辨率或更多视觉 token；这类试验另立方案，需验证权重迁移、位置编码及 CPU 延迟。本轮失败不能推出必须换架构。

## 3. 先建立能验证计数泛化的留出数据

这一步在训练前完成。不能先训练、再找一批模型表现好的题验证。

### 3.1 新计数集合

利用本地 VQAv2 Val 问题和标注包，沿用现有转换规则：`how many`、答案 0–10、至少 7/10 标注者一致、2–5 个选项、相邻数字干扰项、固定种子。官方提供 train / validation 标注及 `question_id`、`image_id` 等字段；这里构建的是**项目自建 choice 评测**，不是官方开放式 VQA 分数。[官方格式说明](https://visualqa.org/download.html)

建议由执行者新增 `scripts/data/v11_count_eval.py`，复用 `v2_vqa_choice.py` 的转换与校验纯函数，避免调用会搬移历史目录的 `v2_build.main`。

| 集合 | 目标数量 | 用途 |
|---|---:|---|
| `data/v11/dev_count_transfer.jsonl` | 300 题 / 300 张图 | 判断旧 dev 的提升是否迁移到 COCO val 图片；可用于筛选 |
| `data/v11/test_count_fresh.jsonl` | 600 题 / 600 张图 | 封存至末步 checkpoint 通过筛选后，只评一次 |
| `data/v11/dev_count_existing.jsonl` | 580 题 / 487 张图 | 从 `data/v2/dev_vqa_choice.jsonl` 提取计数；补充监测，含原 dev_mix 的计数题，不当成独立证据相加 |

构建流程必须满足：

1. 排除 v9b 初始化链的全部训练图片，覆盖 caption 对齐和阶段 2；并排除项目现有 dev、calibration、test、bench 及已用于诊断/选配方的图片。不能仅检查新的训练混合。COCO / VG 别名归一化，照片以既有 dHash ≤ 2 规则补充近重复过滤；存下实际检查清单和缺失项。
2. 每图最多选一题。使用 `seed=20261006`，在不看模型预测的前提下按图片分组、兼顾答案范围与选项数，分配 300 / 600 两组。不要强行把 8–10 等稀缺答案复制到满额，也不按模型对错挑题。
3. 场景、文件缺失或标签异常在封存前处理。抽查约 30 道新题，覆盖 0、1–2、3–4、5–10 和不同选项数，检查实际 256 输入可辨认性；不要求逐道人工重标全量。
4. 输出 `EVAL_MANIFEST.json`：完整题号、原始来源、图片身份、数量、答案/选项分布、过滤计数、哈希、seed 和检查范围。保存固定错配图映射，各 checkpoint 使用相同映射。
5. 把 `v11` 加入 `scripts/data/v5_build.py::held_files` 的目录枚举，验证 `v9_mix.py` 实际读到了新留出文件，再构建训练集。当前代码只枚举到 v10，不能假定自动包含 v11。
6. 若隔离后不能足额构建 300 + 600 张图，或历史训练图片清单不全，**先停在数据准备阶段**，报告实际可用量及缺口，修改本计划后再训练；不得悄悄复用旧测试图或把训练池切一块称为 v9b 未见测试。

600 题是比旧 136 题更大的证据集，不保证一定得到足够窄的区间。独立性仅相对于已审计的项目数据使用史，不声称 SigLIP2 等外部预训练链从未见过这些图片。

### 3.2 其余集合的角色

- `data/v5/dev_mix.jsonl`：继续作为训练 val 与温度拟合集；用于监测和选择的事实明确披露，其拟合后校准指标不当作独立泛化证据。
- `data/v6/dev_lr_pairs.jsonl`：左右能力保护。
- `data/v10/dev_sqa_diagram.jsonl`：258 道示意图题，保护自然科学读图表现；这已经是 monitoring，不能重新叫盲测。
- 旧 `test_*` 和 `bench_*`：冻结的历史回归基准，多轮选方案已经参考过，不能声称完全未参与研发决策。
- 新计数 test 不参与配比、学习率、选 checkpoint 或温度拟合。训练前只核验数据和哈希，不生成模型成绩；只对新 dev 补 v9b 基线。

## 4. 训练数据：约一万道题，各训练一遍

优先复用已有混合器，提议参数为 `--replay 7500 --count-share 0.4 --seed 0 --pairs-file data/v9/r_pairs.jsonl`。`0.4` 是回放中的计数比例，不是整个训练集的比例。

| 部分 | 唯一题数 | 本轮题次 | 目的 |
|---|---:|---:|---|
| 计数 | 3,000 | 3,000 | 从现有清洗池抽更多不同题，避免只重复 v10 的 1,244 道 |
| 左右原题 | 预计 2,488 | 预计 2,488 | 保留已经学到的能力；原图/镜像整对保留 |
| 其他能力回放 | 4,500 | 4,500 | 恢复其他任务的监督量，特别是 ScienceQA |
| 合计 | **预计 9,988** | **预计 9,988** | **一遍，预计 1,249 步** |

非计数 4,500 按 `v9_mix.py` 现有非计数配额同比例、最大余数取整：

| 类别 | 题数 | 类别 | 题数 |
|---|---:|---|---:|
| VSR | 761 | ScienceQA | 665 |
| Visual7W | 475 | 物体存在 | 380 |
| A-OKVQA | 349 | GQA | 317 |
| 颜色 | 285 | 上下相对位置 | 285 |
| VQAv2 是非 | 254 | AI2D | 222 |
| TQA | 222 | 尺寸 | 158 |
| 上下位置 | 127 | 合计 | **4,500** |

ScienceQA 的 665 道一遍，题次接近 v9b 的 328 × 2 = 656，明显多于 v10 的 184 × 2 = 368；这只是监督预算保护，不能保证能力必然不掉。整个方案约 30% 计数、25% 左右、45% 其他能力。

数据准备约定：

- 使用已有正确题面、选项、gold，不给旧题人为编造新答案，不复制 136 道测试题的问法来针对性造训练题。
- 计数池和回放池先完成 held 图片及近重复过滤，再抽样。记录最终答案 0–10、选项数、问题模板、唯一图片数；本轮沿用池的既有配平，不额外做高数量过采样，避免同时改变过多因素。
- 新留出图片可能使左右列表再减少。令最终左右题数为 L，实际总题数 `N=L+7500`，步数 `S=ceil(N/8)`，warmup 为 `ceil(0.1*S)`；按结果写入配置，不能硬编码旧数量后仍声称 1,249 步。
- 任何回放类别不足配额，构建失败并报告，不用重复题静默补足。最终 `MIX.json` 保存实际配额、哈希、隔离清单、近重复结果、seed 和实际步数。
- 所有样本保持一题一个训练 item，ID 唯一。长提示沿用现有 `shorten_hints`，不另写一套图像预处理或序列拼接。

供执行者在上述隔离实现完成后使用的构建命令（本次未执行）：

```sh
uv run python scripts/data/v9_mix.py --root data \
  --out data/v11/recovery_mix --pairs-file data/v9/r_pairs.jsonl \
  --replay 7500 --count-share 0.4 --seed 0
```

## 5. 训练参数与 checkpoint

| 参数 | 设定 | 理由 |
|---|---|---|
| epochs | 1 | 扩大不同题的覆盖，减少同轮重复 |
| micro_batch | 8 | 与现有稳定配置一致 |
| lr_new / lr_head | `2.5e-5` / `2.5e-5` | v10 的一半，作为待验证的保守微调选择 |
| lr_lora | `5e-5` | v10 的一半 |
| warmup | 预计 125 | 总步数约 10%，按最终 S 算 |
| LoRA | r=16、alpha=32，沿用现有 target modules | 不增加新的结构变量 |
| unfreeze_top | 0 | 不解冻文本原始层或视觉塔 |
| RLCD | group_size=4；sigma 0.4 → 0.1 | 沿用现有目标及退火 |
| device / amp | `mps` / 显式 `off` | 此轮维持 FP32；之前 BF16 对照并未有效区分精度 |
| seed | 0 | 记录，MPS 不承诺逐位复现 |
| log_every | 50 | 查看训练 NLL、梯度和耗时 |
| eval_every | 0 | 保留 step 0 与 epoch 末评估，减少重复扫 dev |
| save_every | 500 | 只用于崩溃恢复，不当成可直接加载的最佳模型快照 |

训练时 `val=dev_mix`，不额外把多个重叠 dev 集合都挂进周期性 `--eval`。末步保存后再统一评计数、左右和示意图监测集。当前实现末尾会再次算 val logits 并拟合温度，这项成本计入预算。

建议创建 `configs/v11-v9b-recovery.yaml`，其核心配置如下；这是文档模板，不是已存在的配置文件，步数变化时先修订 warmup：

```yaml
name: v11-v9b-recovery
device: mps
common:
  log_every: 50
stages:
  - name: stage2
    kind: train
    init: runs/v9b-lr-replay/stage2
    data: data/v11/recovery_mix/train.jsonl
    val: data/v5/dev_mix.jsonl
    params:
      epochs: 1
      micro_batch: 8
      lr_new: 2.5e-5
      lr_head: 2.5e-5
      lr_lora: 5.0e-5
      warmup: 125
      lora_r: 16
      lora_alpha: 32
      unfreeze_top: 0
      group_size: 4
      sigma_start: 0.4
      sigma_end: 0.1
      amp: "off"
      seed: 0
      eval_every: 0
      save_every: 500
```

不写训练后立即执行全量测试的 `evaluate`。另设只评测配置指向该末步 checkpoint。新运行不得误用已有目录中的 `resume.pt`；正常意外中断可在同配置、同数据下恢复，但不能边续跑边改 epoch、学习率或数据。

训练中出现非有限 loss/梯度、读图失败、OOM 或持续异常耗时，执行者停止并排查；这不是一次“模型能力失败”。由于本轮只约 1,249 步，不新增自动早停或中间 checkpoint 导出机制。训练 NLL、未校准 dev NLL 与温度变化均报告，不单凭温度变大就判失败。

## 6. 筛选：一次训练，只评监测集

训练前对 v9b 补齐新 dev 的逐题基线和固定错配图对照；已有集合复用与文件哈希对应的结果。末步模型的筛选配置分别评 `dev_mix`、`dev_lr_pairs`、580 题计数 dev、新 300 题计数 dev、258 题示意图 dev。控制组优先只在计数和示意图集合运行，避免把大 dev_mix 的所有对照重复跑多遍。

所有差值均为候选 − v9b，单位为百分点；报告按 canonical 图片分组的配对 95% 区间。计数统计要给出旧错新对、旧对新错和净变化。门槛中的点估计是预算决策规则，不宣称统计显著。

| 条件 | 进入全量评测的要求 |
|---|---|
| 新计数 dev 有迁移 | 300 题准确率点估计提高至少 2 个点（净多对至少 6 题）；真图−错配图收益的变化点估计 ≥ 0 |
| 既有计数不倒退 | 580 题计数 dev 差值 ≥ 0；288 题旧切片单独报告，不当作第二份独立证据 |
| 左右保住 | dev 位置题同时对率差值 ≥ −3；相对位置选择/是非报告，但小样本不新增显著性硬门槛 |
| ScienceQA 保住 | 新示意图 dev 总体差值 ≥ −2；真图−错配图收益变化 ≥ −2；dev_mix 的 ScienceQA 差值 ≥ −2 |
| 其他能力 | 固定 dev_mix 去掉 400 道左右题、288 道计数题后的 4,490 题，准确率差值 ≥ −0.5 |
| 来源警戒 | 上述旧能力切片没有来源同时满足“差值 ≤ −3 且区间上界 < 0” |

**全部满足才进入最终评测。任一不满足就结束本轮，保留 v9b 和运行记录。** 不把没有显著变化写成等效，不把筛选未通过写成该架构学不会计数。更低学习率、第二个 seed、改构成或再训一遍均不自动启动；若要继续，先根据本次哪道门槛失败另定最小实验。

这些门槛比 v10 多了跨图片来源的计数监测与示意图保护，但仍不保证最终测试通过。阈值是本轮事先约定的工程取舍，不是已有实验证明的最优值。

## 7. 最终评测与采用规则

筛选通过后，锁定**同一个末步 checkpoint 及温度**，不重训、不换 seed、不再拟合测试集。使用单独 `configs/v11-v9b-recovery-eval.yaml`，复制 v10 全量评测集合并指向新的 checkpoint，显式 `device: mps`、`calibration_fit: dev_mix`，在 `history` 中列出实际使用过的监测集；新 test 保持 heldout。新旧题号、gold、错配图映射和选项控制一致，配对前检查全量匹配，不能只保留双方共有的部分题而不报警。

### 7.1 新计数是主要有效性证据

对新 600 题 test 评 v8、v9b、候选的真图、错配图和选项倒序结果；这些模型成绩在候选锁定后一起生成。按图片配对重采样 2,000 次、seed 0，预设规则为：

- 相对 v9b：准确率提高至少 **2 个点**，且差值区间下界 > 0。
- 相对 v8：准确率差值区间下界 > **−2 个点**，用于支持“恢复到此前水平附近”的结论。
- 看图收益相对 v9b 的变化区间下界 > 0，支持提升确实涉及视觉信息；若准确率过线而这一项不确定，只能报告准确率恢复，不能宣布视觉计数能力恢复。

新 test 的 n 和分布必须在训练前锁定；也分别报告答案 0、1–2、3–4、5–10 与选项数，稀少子类只描述。旧 136 题继续报告 v8/v9b/候选、净增题数和区间，但**改为历史回归参考，不再用这 136 题单独决定本轮成功**。这是本计划在训练前明确的口径调整，不能等结果不理想才改规则。达到新集合门槛也不得把旧 136 题未补回隐去。

### 7.2 其他能力与概率质量

| 检查 | 预设要求 |
|---|---|
| 位置与相对位置选择 | 原图/镜像同时对率分别与 v9b 配对，差值区间下界 > −5；是非题单独报告，不声称本轮解决 |
| 所有旧 test 和四个 bench_lv | 与 v9b 配对，准确率差值区间下界 > −2；bench_pope 同样报告 |
| ScienceQA 自然科学读图 323 题 | 单独报告准确率与看图收益差值；若任一出现“下降至少 2 个点且区间上界 < 0”，视为专项保护失败，不能用其他题型上涨抵消 |
| 概率质量 | 校准后新计数 test、旧 test_vqa_choice、bench_lv_scienceqa 的 NLL 相对 v9b 均不增加超过 0.02；ECE、Brier、温度和倒序敏感性一起报告，不以低 ECE 单独背书 |
| 外部参考 | 生成 `lv_report.py` 报告；沿用已有本地 Laya Vision 201M 对照，不因本轮更换外部 baseline |

区间未跨过保护线是“证据不足”，不等于已证明退化；但默认不自动替换当前模型。所有主要条件满足时，建议负责人采用；任一主要条件不满足，保留 v9b，说明是否存在可单独利用的能力收益。负责人若明确选择接受某项代价，应记录为取舍，而不是改写通过条件。

对于“与 v8 的非劣效”以及“看图收益”的小幅变化，即使 600 题仍可能证据不足。本轮不追加测试题直到显著，也不把同图多问当作独立样本扩大 n。

## 9. 本轮之后的分支

- **计数恢复、旧能力保住**：保留候选，按负责人决定采用；再单独立项 ScienceQA 读数。
- **新旧计数 dev 都不升，其他能力稳定**：这份配方没有足够计数收益，下一轮先核对训练题覆盖/可辨认性，再决定是否增加复杂计数数据源；不默认延长 epoch。
- **旧 dev 升而新 dev 不升**：优先定位图片来源、问题模板或答案分布差异，不能用旧 dev 再选一个更好看的 checkpoint。
- **计数升而 ScienceQA/左右掉**：明确是能力取舍尚未解决，下一次只针对失败的保护项设计有限对照，不临时动用 test 调配比。
