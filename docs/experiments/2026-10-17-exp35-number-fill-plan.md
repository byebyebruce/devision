# exp35 方案：A2 能不能按图补出被问的数值——只读短诊断（评论家 EXP35-RUN-01 放行，已运行一次，结果见文末）

日期：2026-10-17。依据：评论家 EXP32-MID-01 / 02、EXP35-PREP-01。exp32 B 第 1600 步的明细显示：
- 同一张图上两个对象的数值不同时，两道读数题几乎总是给同一个答案（质量 133 / 138、速度 182 / 191、距离 83 / 85）；
- 孪生图的 gold 变了，两张图都答对的几乎没有（0 / 138、2 / 191、0 / 85）；
- 温度题 41 题里 40 次选 sample B。

A2 末点的 MLM 总分是真图 0.923、换图 0.897。但被遮的 token 大多是说明文字的固定模板，这个总分说明不了数值本身补得出补不出。本诊断把这一层拆开，用来在 exp32 终点仍失败时选下一个训练分支。它不是训练，不随 exp32 结束自动启动。

## 要回答的问题

**在 exp32 的 A2 末点（`runs/exp32-align/stage1`，sha256 `8476145e…e297`），被遮住的数值能不能按图补出来，并且对上 Sample A / B、Pair 1 / 2？**

## 输入（只读）

- checkpoint：`runs/exp32-align/stage1`，即合并 LoRA 后保存的权重。run.sh 启动前核对 sha256。
- MLM 头：ModernBERT-large 的头，从本地 Hugging Face 缓存读取，`HF_HUB_OFFLINE=1`，不下载。
- 数据：`data/real_layout/captions_tune.jsonl` 的 600 张图（已参与开发，没有新的用途）。不读 rl_confirm、75 题属性和 80 题 ChartQA。
- 不更新参数，不拟合温度。

## 两个条件（`scripts/exp35/mlm_numbers.py`）

1. **复现原评估并拆分 token。**
   - 完全按 `align._evaluate` 的做法：600 张图按文件顺序，batch 16，max_caption_tokens 44，mask_prob 0.5，每个模式各用 Random(1)，换图是批内轮转一位。
   - 总分必须复现 `align_report.json` 末点的真图 0.9233559 / 换图 0.8965990。原评估是在 LoRA 未合并时做的，这里用合并后的权重，所以容差定为绝对差 ≤ 0.002，并照实报告差值。超出容差时，只报告、不解读分项。
   - 同一次前向里，把每个被遮 token 归为两类，各自报告 n、准确率、NLL 和真图 − 换图：
     - "被问的数值"，再按质量 / 速度 / 距离拆分；
     - "其余文字"。
   - 两类的 n 加权后必须还原总分（`recombines`）。
2. **完整数值遮罩。**
   - 每条说明文字里，所有数值跨度（两个对象的质量 / 速度 / 距离）的全部 token 都遮住，其他一律不遮。标签、量名和单位保留，两个对象同时遮，不能从另一边抄数。
   - 真图和同一张换图（同一种批内轮转）用完全相同的文本和 mask。
   - 报告：
     - token 准确率；
     - 整个数字的所有 token 都对的比例，按字段；
     - 同图两对象数值不同时，两边都对的比例和分母；
     - 孪生两视图里数值变了的那一项，两视图都对的比例和分母。
   - 一个数字占几个 token 本身就可能泄露数值，所以要看真图 − 换图的差，而不是准确率本身。
   - 这个条件和原来随机遮罩的门槛分开报告，不替换 exp24 门槛。

**数值跨度的规则**：取 "mass of each particle M u"、"average particle speed V m/s"、"X <单位> apart" 里的数字（含逗号、小数点）。不含 "Pair 1 / 2" 的编号，也不含单位。token 的字符 offset 与跨度重叠，就算这个数字的一部分。

**换图的构成**（EXP35-R1-02）：captions_tune 里一个族的 v0 和 v1 相邻，批内轮转一位后，600 次换图的构成是：
- 换成同族孪生图 300 次，其中数值改变 205 次、数值不变 95 次（例如只交换了磁铁大小）；
- 换成其他族 300 次，其中同题型 168 次、温度 / 磁力题型也不同 132 次。

原换图不变，以保证原评估能复现。所以总体的真图 − 换图差，是"这种固定换图下看图带来的总收益"，混合了数值、对象属性、背景 / 版式和题型的变化，不能直接称为数值随图变化。数值是否按标签绑定，要结合完整数值准确率、异值时两边同时正确、孪生两视图同时正确这些读出来判断。数值 token 的两个条件另按换图的四种构成分项报告（同一次前向，不增加模型调用，也不是新门槛）。

**来源记录**（EXP35-R1-01）：第一次前向之前写出 `runs/exp35-number-fill/START.json`，记录：
- 实际读取的 MLM 头：缓存文件路径、快照 revision `45bb4654…`、文件 sha256 `44510fec…`，以及三个张量 head.dense.weight、head.norm.weight、decoder.bias 的 dtype、shape 和 sha256；decoder 与被评 checkpoint 的输入 embedding 绑定，checkpoint 的 sha256 另记；
- A2 权重和数据的 sha256；
- 600 条的原顺序，以及每条的换图 id 和换图类别。

## 结果怎么用（不是已确认的根因，评论家据此选下一步）

- **A2 的数值补全或绑定也弱**（完整数值遮罩下，真图 − 换图的差小，两对象 / 孪生同时对的比例低）：优先修"数值—标签"的监督，不靠 MLM 总分 0.92 继续堆 B 的题。例如"只在真实版式说明文字上加强数值跨度的监督"的单变量改稿，保留 COCO 回放，另写方案。
- **A2 能按图补对完整数值，但 B 仍两问同答**：重点查 B 阶段的表示保持和"问题 → 数值"的读出，也要分清是不是 B 的更新造成的；不能仅凭 A2 好就认定决策头是唯一原因。
- exp33 只在仅剩保护代价时用；exp34 只在字段读数确实成功、语义仍未过时用，不因距离总分 0.69 误触发。

## 结果（2026-10-17 16:26:48–16:29:27，约 157 秒，退出码 0；`runs/exp35.out`、`runs/exp35-number-fill/{START,report}.json`）

**身份**：
- A2 sha256 `8476145e…e297`（run.sh 核对通过）；
- MLM 头为缓存快照 `45bb4654…`，文件 `44510fec…`。START.json 在 16:26:51 写出，早于第一次前向；
- 数据：captions_tune `1b90cfad…`，600 条，换图构成 205 / 95 / 168 / 132。

**1. 复现原评估**：真图 0.9233559、换图 0.8965990，与 align_report 末点逐位相同（容差 0.002 内，实际误差为 0）。真图和换图两种模式下，两类 token 加权都还原了总分（recombines 都为 True）。

- 按换图构成分：换成数值变了的孪生图时差 +0.004，数值没变的孪生图 +0.005，别族同题型 +0.024，别族别题型 +0.030。
- 异值时两对象同时正确：真图和换图都是 0（距离 0 / 85、质量 0 / 138、速度 0 / 191）。
- 孪生两视图里数值变了的那一项两视图同时正确：真图和换图也都是 0（0 / 85、0 / 138、0 / 191）。

**读法**（按方案预写的用法，只用于选下一步，不是已确认的根因）：
- MLM 总分 0.92 几乎全部来自模板文字（0.996）。被问的数值只有 0.61，而且和换图几乎一样。
- 换成"只改了数值的孪生图"时，真图对数值 token 没有任何帮助（−0.001）；能看出的一点差异只出现在换成别族、别题型的图时，说明模型用到的是版式 / 题型 / 背景这类粗信息，而不是数字本身。
- 把数字全部遮住时，整个数字补对的只有 2–7%，两对象或孪生同时正确的是 0。
- 结论：A2 末点没有学会按图补出数值，更没有对上标签。按预写的分支，这属于"A2 的数值补全 / 绑定也弱"，应先修数值与标签的监督或可读性，不再继续往 B 里堆题。
- 这个结果不能区分三种可能：MLM 监督太弱（被遮的大多是模板 token）、数字在 256 输入里太小（温度图约 5–11 px，磁力图约 4–9 px）、投影层容量不够。哪一个是主因，需要下一项设计来区分，由评论家决定。
